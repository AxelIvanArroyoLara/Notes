## Introducción

El análisis de las funciones recursivas es un proceso que requiere del hallazgo de un umbral superior asintótico en el tiempo de ejecución.

Muchos algoritmos se valen de la recursividad, y analizar el tiempo de ejecución tiene una **relación de recurrencia** que expresa este valor temporal para una entrada de tamaño $n$ en términos del tiempo de ejecución para entradas más pequeñas; por ejemplo, en un algoritmo *Merge Sort*, el arreglo se divide en dos mitades, ordenando cada una recursivamente para después fusionar los resultados obtenidos. Esto lleva a la relación de recurrencia $T(n)=2T \frac{n}{2} + cn$, en donde el término $cn$ representa el tiempo requerido para unir ambas mitades:

```
#include <stdio.h>

void fun(int n) {
    if (n <= 1)
        return;
    fun(n / 2);
    fun(n / 2);
    for (int i = 0; i < n; i++) {
        printf("GFG ");
    }
}
```

En este caso entonces, la complejidad de la función se escribe como $T(n)=2T(\frac{n}{2})+O(n)$. Para hallar la complejidad final, se debe resolver entonces la recurrencia, que puede hacerse de tres maneras:

- **Método de sustitución:** Se intuye por la forma de la solución y luego se prueba matemáticamente.
- **Método de árbol de recurrencia:** Representa la recurrencia como un árbol en el que se suman los costos de ejecución de cada nivel.
- **Teorema maestro:** Este teorema otorga una forma directa de dividir y hallar el tiempo de recurrencias en la forma especificada con anterioridad.
