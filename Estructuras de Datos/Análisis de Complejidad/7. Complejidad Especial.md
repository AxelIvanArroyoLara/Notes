
El **espacio auxiliar** se define como el espacio extra o temporal que del que dispondrá un algoritmo. Por otra parte, la **complejidad especial** es el espacio total tomado por un algoritmo respecto al tamaño de sus entradas. Este incluye al espacio auxiliar y al espacio tomado por las entradas.

Por ejemplo, dado el caso de que se requiera comparar dos algoritmos de ordenamiento con base en su espacio utilizado, entonces el espacio auxiliar sería un mejor criterio que la complejidad. *Merge Sort* utiliza $O(n)$ espacio auxiliar, mientras que *Insertion* y *Heap Sort* utilizan tan solo $O(1)$; sin embargo, la complejidad espacial de ambos es de $O(n)$.

La complejidad espacial se considera un concepto paralelo a la complejidad temporal (descrita a detalle en módulos previos): si se desea crear un arreglo de tamaño $n$, esto requerirá un espacio $O(n)$. Por otro lado, si se genera un arreglo bidimensional $n*n$, se toma O($n^2$) espacio. 

Las llamadas recursivas también influyen. 

#### Ejemplo:

```
int add (int n){  
    if (n <= 0){  
        return 0;  
    }  
    return n + add (n-1);  
}  
  
Here each call add a level to the stack :  
  
1.  add(4)  
2.    -> add(3)  
3.      -> add(2)  
4.        -> add(1)  
5.          -> add(0)  
  
Each of these calls is added to call stack and takes up actual memory.  
So it takes O(n) space.
```

Aquí se observan un número $n$ de llamadas, pero eso no implica un tamaño con la misma complejidad.
