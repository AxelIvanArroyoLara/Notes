## Introducción

La **notación Big-O** es una manera de expresar el umbral superior de un algoritmo en términos de tiempo o complejidad. De manera particular:

- Describen comportamiento asintótico para una función, mas no su valor exacto.
- Puede utilizarse para comparar la eficiencia de dos algoritmos o estructuras de datos diferentes.
- Brinda un límite superior respecto al tiempo tomado por un algoritmo de acuerdo con el tamaño de su entrada. Por lo general, se asume el peor caso.

---

## Definición Big-O

Dadas dos funciones $f(n)$ y $g(n)$, puede decirse que $f(n)$ es $O(g(n))$ si la primera función no crece tan rápido que $c*g(n)$ para todos los $n>=n_0$, en donde $c$ y $n_0$ son valores constantes.

### Hallar complejidad:

Se toman los pasos revisados en el módulo anterior:

- Ignorar los ordenes menores y solo considerar el mayor.
- Ignorar la constante asociada al término de mayor orden.

#### Ejemplo:

1. $f(n) = 3n^2 + 2n + 1000Log(n) + 5000$

- Se toma $3n^2$
- Ignorando la constante: $n^2$

Por lo tanto, el valor Big-O de la expresión es $O(n^2)$

## Propiedades de la Notación Big-O

### Reflexividad:

Para cada función $f(n)$, $f(n)=O(f(n))$

Por ejemplo:

$f(n)=n^2$, entonces $f(n)=O(n^2)$

### Transitividad:

Si $f(n)=O(g(n))$ y $g(n)=O(h(n))$, entonces $f(n)=O(h(n))$

Por ejemplo:

Si $f(n) = n^2$, $g(n) = n^3$, y $h(n) = n^4$, entonces $f(n) = O(g(n))$ y $g(n) = O(h(n))$.  
Por lo tanto, por transividad, $f(n) = O(h(n))$.

Es decir, se pasa la complejidad mayor a la función base.

### Factor constante:

Para cualquier constante $c>0$ y funciones $f(n)$ y $g(n)$, si $f(n) = O(g(n))$, entonces $cf(n)=O(g(n))$.

Por ejemplo: 

Si $f(n) = n$, $g(n) = n^2$. Entonces $f(n) = O(g(n))$. Por lo tanto, $2f(n) = O(g(n))$.

### Regla de la suma:

If $f(n) = O(g(n))$ and $h(n) = O(k(n))$, then $f(n) + h(n) = O(max( g(n), k(n) )$ When combining complexities, only the largest term dominates.

Por ejemplo:

$f(n) = n^2$, $h(n) = n^3$. Entonces, $f(n) + h(n) = O(max(n^2 + n^3) = O (n^3)$

### Regla del producto:

Si $f(n)=O(g(n))$ y $h(n)=O(k(n))$, entonces $f(n)*h(n)=O(g(n)*k(n))$

Por ejemplo:

$f(n)=n$, $g(n)=n^2$, $h(n)=n^3$, $k(n)=n^4$, entonces, $f(n)=O(g(n))$ y $h(n)=O(k(n))$. Por lo tanto, $f(n)*h(n)=O(g(n)*k(n))=O(n^6)$.

### Composition Rule

If f(n) = O(g(n)), then f(h(n)) = O(g(h(n))).

Por ejemplo:

 If $f(n)=n^2$, $g(n)=n^3$ and $h(n)=log$, then by composition rule $f(h(n))=O(g(h(n)))$. Therefore, $(log(n))^2=O((log(n))^3)(log(n))^2=O((log(n))^3)$.

## Notaciones Comunes

### Complejidad lineal (Big $O(n)$):

La **complejidad lineal** indica que el tiempo de ejecución de un algoritmo crece linealmente con el tamaño de las entradas. Por ejemplo, un algoritmo de búsqueda lineal:

```
bool findElement(int arr[], int n, int key)
{
    for (int i = 0; i < n; i++) {
        if (arr[i] == key) {
            return true;
        }
    }
    return false;
}
```

### Complejidad logarítmica (Big $O(log(n))$)

Esta complejidad indica que el tiempo del algoritmo es directamente proporcional al tamaño de la entrada del algoritmo. Por ejemplo, una búsqueda binaria:

```
int binarySearch(int arr[], int l, int r, int x)
{
    if (r >= l) {
        int mid = l + (r - l) / 2;
        if (arr[mid] == x)
            return mid;
        if (arr[mid] > x)
            return binarySearch(arr, l, mid - 1, x);
        return binarySearch(arr, mid + 1, r, x);
    }
    return -1;
}
```

### Complejidad cuadrática (Big $O(n^2)$):

Esta complejidad indica que el tiempo es proporcional al cuadrado del tamaño de la entrada. Esto se ve en *bubble sort*:

```
void bubbleSort(int arr[], int n)
{
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(&arr[j], &arr[j + 1]);
            }
        }
    }
}
```

### Complejidad cúbica (Big $O(n^3)$):

Esta complejidad indica que el tiempo es proporcional al cubo del tamaño de la entrada. Esto se ve en *matrix multiplication*:

```
void multiply(int mat1[][N], int mat2[][N], int res[][N])
{
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            res[i][j] = 0;
            for (int k = 0; k < N; k++)
                res[i][j] += mat1[i][k] * mat2[k][j];
        }
    }
}
```

### Complejidad polinomial (Big $O(n^k)$):

Esta complejidad refiere a aquellas que puedan expresarse mediante una función polinomial para una función de tamaño $n$. 

Estos algoritmos generalmente se consideran eficientes debido a que crecen proporcionalmente a sus entradas. Algunos ejemplos comunes de algoritmos con esta complejidad se encuentran las tres descritas previamente.

### Complejidad exponencial (Big $O(2^n)$):

La complejidad exponencial significa que el tiempo se duplica con cada adición al conjunto de entradas. Por ejemplo, al general subsets de un subset:

```
void generateSubsets(int arr[], int n)
{
    for (int i = 0; i < (1 << n); i++) {
        for (int j = 0; j < n; j++) {
            if (i & (1 << j)) {
                cout << arr[j] << " ";
            }
        }
        cout << endl;
    }
}
```

### Complejidad factorial (Big $O(n!)$):

Esta es la peor complejidad, y se da cuando un algoritmo crece factorialmente respecto al tamaño de la entrada. Esta se ve regularmente en algoritmos que generan todas las permutaciones para todos los datos:

```
void permute(int* a, int l, int r)
{
    if (l == r) {
        for (int i = 0; i <= r; i++) {
            cout << a[i] << " ";
        }
        cout << endl;
    }
    else {
        for (int i = l; i <= r; i++) {
            swap(a[l], a[i]);
            permute(a, l + 1, r);
            swap(a[l], a[i]); // backtrack
        }
    }
}
```
