## Introducción
El análisis de los ciclos es un proceso que consiste en encontrar el número de operaciones ejecutadas en función de la entrada dada. A continuación se describen los pasos generales para efectuar este procedimiento:

- Determinar el número de iteraciones del ciclo.
- Determinar el número de operaciones realizadas en cada paso del ciclo.
- Expresar el número total de operaciones realizadas por el ciclo respecto al tamaño de la entrada.
- Determinar el orden de crecimiento de la expresión para el número de operaciones realizadas por el loop.
---
## Niveles de Complejidad

### Complejidad constante O(1):

$O(1)$ se refiere a que la complejidad se mantiene constante; es decir, el tiempo de ejecución es por completo independiente del tamaño de la entrada. Un ciclo que solo se ejecuta una cantidad determinada de veces también se considera como $O(1)$; por ejemplo:

```
for (int i = 1; i <= 10; i++) {
    // some O(1) expressions
}
```

### Complejidad lineal $O(n)$:

Esta complejidad se da en los casos donde las variables del ciclo son incrementadas o decrementadas de manera constante; por ejemplo, efectuar una búsqueda en un arreglo desordenado o iterar una estructura y ejecutar una cantidad de operaciones constante para cada elemento:

```
// Here c is a positive integer constant
for (int i = 1; i <= n; i += c) {
    // some O(1) expressions
}

for (int i = n; i > 0; i -= c) {
    // some O(1) expressions
}
```

## Complejidad cuadrática $O(n^c)$:

Esta complejidad se ve definida en los casos en los que el desempeño del algoritmo es directamente proporcional al cuadrado de la entrada; por ejemplo, en los ciclos anidados, $c$ es igual a la cantidad de veces que más se repete la instrucción más interna.

```
for (int i = 1; i <= n; i += c) {
    for (int j = 1; j <= n; j += c) {
        // some O(1) expressions
    }
}

for (int i = n; i > 0; i -= c) {
    for (int j = i + 1; j <= n; j += c) {
        // some O(1) expressions
    }
}
```

## Complejidad logarítmica $O(Log (n))$:

La complejidad de un ciclo se considera $O(Log(n))$ en caso de que las variables del mismo se dividan o multipliquen por un valor constante:

```
for (int i = 1; i <= n; i *= c) {
    // some O(1) expressions
}
for (int i = n; i > 0; i /= c) {
    // some O(1) expressions
}
```

```
// Recursive function
void recurse(int n)
{
    if (n <= 0)
        return;
    else {
        // some O(1) expressions
    }
    recurse(n/c);
  // Here c is positive integer constant greater than 1
}
```

## Complejidad logarítmica doble $O(Log (Log(n))$:

Esta complejidad viene dada por los casos en los que las variables de un ciclo son reducidas o incrementadas exponencialmente por un valor constante:

```
// Here c is a constant greater than1
for (int i = 2; i <= n; i = pow(i, c)) {
    // some O(1) expressions
}

// Here fun is sqrt or cuberoot or any
// other constant root
for (int i = n; i > 1; i = fun(i)) {
    // some O(1) expressions
}
```

## Combinación de Complejidades

Al haber loops consecutivos, la complejidad de tiempo se calcula en función de la suma de todas las complejidades de los ciclos individuales; por ejemplo:

```
for (int i = 1; i <= m; i += c) {
    // some O(1) expressions
}
for (int i = 1; i <= n; i += c) {
    // some O(1) expressions
}
```

Aquí, la complejidad total vendría dada por la expresión $O(m)+O(n)$, que es $O(m+n)$. Dado el caso de que $m == n$, entonces la complejidad pasa a ser $O(2n)$, que es $O(n)$.

Ahora bien, para calcular la complejidad incluyendo condicionales, al estar utilizando la notación *Big O*, debemos considerar siempre el peor caso posible; es decir, asumir que la estructura selectiva llevará al número máximo de iteraciones posibles. 

Cuando el código es demasiado complejo para considerar todos los casos, se utiliza un umbral bajo la premisa de ignorar todas las estructuras de control complejas.
