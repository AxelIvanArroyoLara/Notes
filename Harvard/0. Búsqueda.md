
## Introducción

La metodología de búsqueda se enfoca en el uso de agentes que, dado un estado inicial y un objetivo, sean capaces de llegar del primero al último. En este caso, una aplicación de este tipo recibe como entrada la localización actual y el destino y, basándose en un algoritmo de búsqueda, retorna un camino sugerido.

Ahora bien, aquí se concentran algunas de las definiciones más importantes para este campo:

### Agente:

Es una entidad que percibe su ambiente y actúa sobre él. En un sistema de navegación, el agente sería la representación de un vehículo que necesita decidir qué acciones tomar para llegar a su destino.
### Estado:

Es una configuración del agente en su entorno; por ejemplo, dado un puzzle de 15 piezas, un estado es una manera en la que todos los números se acomodan en el tablero. 

- **Estado inicial:** El estado desde el que el algoritmo comienza. En una app de navegación, sería la posición local.

### Acciones: 

Son decisiones que pueden ser tomadas en un estado; más precisamente, estas pueden definirse como una función. Tras recibir el estado `s` como input, la función `Actions(s)` retorna como salida el set de acciones que pueden ser ejecutadas desde `s`. Por ejemplo, en el puzzle, las acciones de un estado dado son las formas en las cuales los cuadrados pueden ser deslizados en la configuración actual. 
### Modelo de transición:

El modelo de transición puede ser definido como una función: tras recibir el estado `s` y una acción `a` como entrada, `Results(s, a)` regresa el estado resultante de ejecutar la acción sobre el estado. Por ejemplo, dada una cierta configuración del puzzle (estado `s`), mover un cuadro en cualquier dirección (acción `a`), llevará a una nueva configuración / estado.
### Espacio de estados:

Refiere al set de todos los estados alcanzables desde el inicial partiendo de cualquier secuencia de acciones; por ejemplo, en un puzzle 15, el espacio de estados es consiste en todas las $\frac{16!}{2}$ configuraciones en el tablero que pueden alcanzarse desde el estado inicial. El espacio de estados puede visualizarse como el grafo dirigido con estados, representados como nodos, y acciones, representado como flechas entre los nodos.

### Prueba de objetivo:

Es la condición que determina si un estado dado es un estado objetivo. Por ejemplo, en el navegador, la prueba determinaría si la locación actual del agente es el destino. Si es, el problema ya está resuelto; si no, se continúa buscando.

### Coste:

El costo numérico asociado al camino dado; por ejemplo, la app no solo lleva al destino, sino que trata de hacerlo mientras minimiza los costes, encontrando la forma más rápida de llegar al estado objetivo.

## Resolver Problemas de Búsqueda

### Solución:

La secuencia de acciones que llevan desde el estado inicial hacia el estado objetivo. De entre estas, se puede tener una *solución óptima*, que es la mejor en cuestión de costes. 

### Estructura:

En problemas de búsqueda, los datos son comúnmente guardados dentro del *nodo*; una estructura de datos que contiene la siguiente información:

- Un estado.
- El nodo padre desde el que el nodo actual fue generado.
- La acción aplicada al padre para llegar al nodo actual.
- El costo del camino desde el estado inicial del nodo.

Los nodos contienen información que los vuelven sumamente útiles para los propósitos de los algoritmos de búsqueda: contienen un estado, que puede ser revisado usando la prueba de objetivo para ver si este es el final. Si lo es, entonces el coste del camino puede ser comparado al de los otros nodos, lo que permite seleccionar la opción óptima. Una vez que el nodo es elegido, gracias a su capacidad para guardar al nodo padre, es posible rastrear cada paso desde el estado inicial, siendo la secuencia de acciones, la solución.

Sin embargo, los nodos son simplemente una estructura de datos; no buscan, sino que retienen información. Para realmente efectuar una búsqueda, se utiliza la **frontera**: un mecanismo que gestiona a los nodos. Esta comienza conteniendo el estado inicial y un set vacío de elementos explorados, y entonces repite las acciones siguientes hasta que una solución es alcanzada.

Repetir:

1. Si la frontera está vacía:
	- *Stop*. No hay solución al problema.
2. Remover un nodo de la frontera. Este es el nodo que se considerará. 
3. Si el nodo contiene al estado objetivo:
	- Retornar la solución. *Stop*.
- De lo contrario:
	- Expandir el nodo (hallar todos os nuevos nodos que se pueden alcanzar desde el actual) y añadir los nodos resultantes a la frontera.
	- Añadir el nodo actual al set de explorados.

### Depth-First Search:

El nodo a eliminar en la frontera es una decisión con implicaciones en la calidad de la solución y lo rápido que se logra. Hay múltiples maneras para responder la cuestión de qué nodos deberían ser consideradas primero, los que pueden ser representados por estructuras *stack*. 

Los algoritmos de tipo *depth first* parten de un enfoque en donde deben agotar todas las direcciones posibles antes de intentar con otra. En estos casos, la frontera se maneja en forma de *stack*, lo que resulta en un algoritmo que va tan profundo como le sea posible en una sola dirección, dejando las demás para después.

En el mejor de los casos, esta es la estructura más rápida; contrariamente, en el peor de los casos el algoritmo explorará cada camino posible antes de siquiera hallar la solución, tomando el mayor tiempo posible, siendo además probable que el camino encontrado no sea el más óptimo.

##### Ejemplo:

```
  # Define the function that removes a node from the frontier and returns it.
    def remove(self):
    	  # Terminate the search if the frontier is empty, because this means that there is no solution.
        if self.empty():
            raise Exception("empty frontier")
        else:
        	  # Save the last item in the list (which is the newest node added)
            node = self.frontier[-1]
            # Save all the items on the list besides the last node (i.e. removing the last node)
            self.frontier = self.frontier[:-1]
            return node
```

### Breadth-First Search:

Es la configuración opuesta a la *depth-first search*, buscando seguir múltiples direcciones al mismo tiempo, tomando un solo paso en cada dirección posible antes de tomar el segundo en cada una. En este caso, la frontera se gestiona a través de una *queue*, en donde el primero que entra, es el primero que sale: los nodos entran en fila y se consideran de acuerdo con el que haya sido añadido primero (el primero que llega es el primero que se sirve). 

Este algoritmo garantiza hallar siempre la solución óptima, aunque será el más largo de ejecutar; este algoritmo siempre tomará más de el tiempo mínimo.

##### Ejemplo:

```
    # Define the function that removes a node from the frontier and returns it.
    def remove(self):
    	  # Terminate the search if the frontier is empty, because this means that there is no solution.
        if self.empty():
            raise Exception("empty frontier")
        else:
            # Save the oldest item on the list (which was the first one to be added)
            node = self.frontier[0]
            # Save all the items on the list besides the first one (i.e. removing the first node)
            self.frontier = self.frontier[1:]
            return node
```
