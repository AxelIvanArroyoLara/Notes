## Introducción

Esta tercera parte de la introducción a los sistemas distribuidos cambia el enfoque respecto al hardware y al sistema operativo estudiados previamente. El interés se desplaza hacia los **sistemas distribuidos de información**, es decir, sistemas en los que una aplicación, sus datos y los mecanismos para acceder a ellos pueden encontrarse repartidos entre distintos componentes y máquinas. Este tema se ubica después del estudio de sistemas multiprocesadores y multicomputadoras y antes de abordar las aplicaciones distribuidas.

La idea central consiste en partir de un **sistema de información tradicional**, identificar cuáles son sus componentes y después observar qué ocurre cuando esos componentes dejan de encontrarse concentrados en un solo lugar. A partir de esa distribución aparecen nuevos problemas que un sistema convencional no necesita resolver con la misma intensidad: cómo localizar recursos, cómo comunicarse, cómo mantener una visión coherente del estado global, cómo recuperarse de fallas y cómo proteger la información.

---

## Sistema de información

Un **sistema de información**, abreviado SI, puede entenderse a partir de varias capas funcionales, separando claramente la **interfaz de usuario**, la **aplicación** y la **administración de datos**. Esta última se divide a su vez en mecanismos de acceso y almacenamiento, mientras que en la parte inferior se encuentran los datos propiamente dichos.

La estructura presentada puede representarse de la siguiente manera:

```text
Usuario
   │
   ▼
┌─────────────────────┐
│ Interfaz de usuario │
└─────────────────────┘
   │
   ▼
┌─────────────────────┐
│     Aplicación      │
└─────────────────────┘
   │
   ▼
┌─────────────────────┐
│ Acceso a los datos  │
├─────────────────────┤
│ Almacenamiento      │
└─────────────────────┘
   │
   ▼
┌─────────────────────┐
│        Datos        │
└─────────────────────┘
```

La división no representa componentes aislados, sino distintas responsabilidades dentro del mismo sistema.

### Interfaz de usuario

La **interfaz de usuario** constituye la parte mediante la cual una persona interactúa con el sistema. Recibe acciones del usuario y presenta resultados.

Por sí sola, la interfaz normalmente no contiene toda la lógica necesaria para decidir qué hacer con la información. Su función principal es permitir la interacción entre la persona y las demás capas del sistema.

### Aplicación y lógica aplicativa

La diapositiva agrupa la aplicación dentro de la **lógica aplicativa**.

La lógica aplicativa representa las reglas y operaciones que determinan el comportamiento del sistema. Es la parte que transforma una acción del usuario en una operación concreta.

Por ejemplo, conceptualmente:

```text
Usuario solicita una operación
          │
          ▼
Interfaz de usuario
          │
          ▼
Lógica aplicativa
          │
          ▼
Acceso a los datos
```

La aplicación no representa únicamente aquello que se muestra en pantalla. Representa también la lógica encargada de determinar **qué operación debe realizarse**.

### Administración de datos

La diapositiva agrupa dos elementos dentro de la administración de datos:

- acceso;
    
- almacenamiento.
    

El **acceso** representa los mecanismos utilizados para consultar o modificar la información, mientras que el **almacenamiento** corresponde a la manera en que esa información permanece guardada.

Finalmente se encuentran los **datos**, que constituyen la información sobre la cual trabaja el sistema.

Por tanto, un sistema de información completo puede verse como una secuencia:

```text
Interacción
    ↓
Lógica
    ↓
Acceso
    ↓
Almacenamiento
    ↓
Datos
```

## Distribución de los sistemas de información

Una vez identificadas las partes de un sistema de información, aparece la siguiente pregunta: **¿qué ocurre cuando esas partes se distribuyen?**

La diapositiva de la página 4 muestra precisamente esta transformación. Los componentes que antes aparecían como bloques únicos comienzan a dividirse: existen varias interfaces, varias aplicaciones, varios mecanismos de acceso y almacenamiento y conjuntos de datos que pueden encontrarse distribuidos.

La idea puede representarse de forma simplificada:

```text
Sistema centralizado

Interfaz
   ↓
Aplicación
   ↓
Acceso
   ↓
Almacenamiento
   ↓
Datos
```

frente a:

```text
Sistema distribuido

Interfaz A     Interfaz B     Interfaz C
    │              │              │
    ▼              ▼              ▼
Aplicación A   Aplicación B   Aplicación C
      \            │            /
       \           │           /
        ───── Administración ─────
             distribuida
                 │
        ┌────────┴────────┐
        ▼                 ▼
     Datos A           Datos B
```

La distribución puede afectar diferentes niveles. No necesariamente significa únicamente que haya bases de datos distintas. También pueden encontrarse distribuidas las interfaces, la lógica de aplicación o las funciones de acceso y almacenamiento.

---

## Distribuir no significa solamente copiar el sistema

La figura de la página 4 es importante porque muestra que un sistema distribuido no tiene que consistir en varias copias idénticas del sistema completo. Los distintos componentes pueden dividirse y repartirse de maneras diferentes.

Por ejemplo, puede existir una situación conceptual en la que:

```text
Máquina A
├── interfaz
└── parte de la aplicación

Máquina B
├── otra parte de la aplicación
└── acceso a datos

Máquina C
├── almacenamiento
└── datos
```

En este caso, una sola operación puede requerir la participación de varias máquinas.

El sistema deja de poder asumir que todo se encuentra disponible dentro de una misma computadora. Como consecuencia, la **comunicación** pasa a convertirse en una parte fundamental del funcionamiento.

---

## Requerimientos mínimos de un sistema distribuido

Las últimas tres diapositivas desarrollan los llamados **requerimientos mínimos**. En ellas aparece un entorno formado por componentes muy diferentes: estaciones de trabajo, dispositivos móviles o nómadas, fuentes de información, sistemas manejadores de bases de datos, recursos activos y distintos dispositivos conectados mediante una infraestructura de comunicación.

El dibujo no debe interpretarse como una arquitectura específica que deba memorizarse. Su función es mostrar un entorno distribuido donde existen muchos recursos heterogéneos que deben colaborar.

En el centro aparece repetidamente:

```text
COMUNICACIÓN
```

Esto señala que la infraestructura de comunicación es aquello que permite conectar todos los componentes distribuidos.

Sin comunicación, los elementos podrían existir, pero no formarían realmente un sistema distribuido cooperativo.

---

## Comunicación

La **comunicación** es uno de los requerimientos más básicos porque los recursos ya no se encuentran necesariamente dentro de la misma máquina.

En un sistema centralizado, una aplicación puede acceder directamente a recursos locales. Cuando estos se encuentran distribuidos, la información debe viajar entre diferentes componentes.

El esquema general pasa a ser:

```text
Componente A
     │
     │ comunicación
     ▼
   Red
     │
     ▼
Componente B
```

En las diapositivas de requerimientos mínimos, la comunicación ocupa visualmente el centro del sistema y conecta estaciones de trabajo, dispositivos móviles, fuentes, DBMS y otros recursos.

Esto explica por qué la comunicación no constituye un complemento opcional. Es el mecanismo que permite que las distintas partes funcionen conjuntamente.

---

## Nombrado y designación

El primer requerimiento adicional mostrado en la página 5 es **Nombrado y Designación**.

Cuando existen múltiples recursos distribuidos, no basta con que estén conectados. También es necesario que el sistema tenga alguna forma de **identificarlos y determinar a qué recurso se hace referencia**.

Conceptualmente, aparece un problema muy sencillo:

```text
"Se necesita el recurso X"
          │
          ▼
¿Cuál recurso es X?
          │
          ▼
¿Dónde está X?
          │
          ▼
¿Cómo se accede a X?
```

El **nombrado** proporciona una forma de identificar recursos.

La **designación** relaciona esa identificación con el recurso que debe utilizarse dentro del entorno distribuido.

### Por qué aparece este problema

En una sola computadora, muchos recursos se encuentran dentro de un entorno bien delimitado. En un sistema distribuido pueden existir múltiples máquinas, dispositivos, bases de datos y servicios.

Por ejemplo, si existen varios recursos similares:

```text
DBMS A
DBMS B
DBMS C
```

el sistema necesita distinguirlos.

No basta con afirmar que se utilizará “la base de datos”. Debe existir un mecanismo que permita determinar **qué componente concreto corresponde al recurso solicitado**.

---

## Recursos móviles y heterogéneos

La figura de la página 5 también incluye explícitamente una entidad denominada **nómada**, una estación de trabajo, diferentes fuentes y un DBMS.

Esto refuerza una característica importante del escenario mostrado: los recursos distribuidos no necesariamente tienen la misma naturaleza.

Puede haber:

```text
Computadoras fijas
Dispositivos móviles
Bases de datos
Fuentes de información
Recursos activos
Servidores
```

Todos deben coexistir dentro del mismo entorno de comunicación.

La distribución, por tanto, no sólo introduce separación física. También introduce **heterogeneidad**, porque los participantes del sistema pueden tener funciones y características distintas.

---

## Estado global

La página 6 introduce otro requerimiento: **Estado global y recuperación**. Además, incorpora explícitamente una dimensión de **tiempo** mediante una flecha horizontal sobre el sistema.

La idea de estado global aparece porque cada participante del sistema posee solamente información parcial sobre lo que está ocurriendo.

Puede imaginarse un sistema con tres nodos:

```text
Nodo A        Nodo B        Nodo C
Estado A      Estado B      Estado C
```

Cada uno conoce su propio estado local.

Sin embargo, el sistema completo posee un estado formado por la combinación de todos ellos:

```text
Estado global
=
Estado A
+
Estado B
+
Estado C
+
interacciones entre ellos
```

La dificultad consiste en que estos estados pueden estar cambiando mientras los nodos se comunican.

---

## El tiempo y la distribución

La aparición explícita de **Tiempo** en la página 6 resulta significativa.

En un sistema distribuido, los acontecimientos ocurren en distintos componentes y la información no necesariamente llega de forma instantánea a todos ellos.

Conceptualmente:

```text
Tiempo ───────────────────────────────→

Nodo A:   evento A1 ───────── evento A2
                    \
                     \ mensaje
                      \
Nodo B:   ─────────── evento B1 ───────
```

Mientras el mensaje viaja, el sistema continúa evolucionando.

Esto hace que conocer el estado global resulte más difícil que simplemente consultar una variable única.

En un sistema centralizado puede existir un punto único desde el cual observar gran parte del estado. En un sistema distribuido, ese estado está repartido y evoluciona a lo largo del tiempo.

---

## Recuperación

La página 6 relaciona directamente el **estado global** con la **recuperación**.

La relación entre ambos conceptos es natural: si ocurre un problema, el sistema necesita determinar cuál era su situación y cómo regresar a un estado válido.

Puede representarse así:

```text
Sistema funcionando
       ↓
Estado válido
       ↓
Ocurre un problema
       ↓
Recuperación
       ↓
Retorno a un estado válido
```

En un sistema distribuido, esta recuperación se vuelve más complicada porque diferentes partes pueden encontrarse en estados distintos.

Un componente podría haber completado una operación mientras otro todavía no la ha procesado.

Por tanto, recuperar el sistema requiere considerar **el estado de múltiples participantes**, no únicamente el de una máquina individual.

---

## La relación entre estado global, tiempo y recuperación

Los tres elementos mostrados en la página 6 se encuentran relacionados:

```text
Distribución
     ↓
Cada nodo tiene estado propio
     ↓
Los estados cambian con el tiempo
     ↓
Se necesita construir una visión global
     ↓
Esa visión permite coordinar recuperación
```

El problema principal no es simplemente saber qué contiene cada computadora, sino entender **qué estaba ocurriendo en el sistema completo en determinado momento**.

---

## Tolerancia a fallas

La página 7 incorpora explícitamente la **tolerancia a fallas** como otro requerimiento mínimo. Además, el diagrama representa fallas mediante rayos que afectan diferentes componentes del entorno.

La presencia de varias máquinas implica que existen también más lugares donde puede producirse una falla.

Puede fallar:

```text
un nodo
una conexión
una fuente
un almacenamiento
un dispositivo
algún componente intermedio
```

La diapositiva no desarrolla mecanismos específicos para resolver cada situación, pero establece la necesidad de que el sistema contemple la existencia de fallos.

### Fallar parcialmente

Una característica importante mostrada por el propio dibujo es que una falla puede afectar **una parte** del sistema mientras otros componentes permanecen operativos.

Conceptualmente:

```text
Nodo A   ✓
Nodo B   ✗
Nodo C   ✓
Nodo D   ✓
```

El sistema ya no puede asumir simplemente:

```text
todo funciona
```

o:

```text
todo está caído
```

Puede existir un escenario intermedio donde algunas partes continúan disponibles y otras no.

Esta situación hace necesaria la tolerancia a fallas.

---

## Relación entre tolerancia a fallas y recuperación

La recuperación estudiada en la diapositiva anterior y la tolerancia a fallas presentada en la siguiente forman parte del mismo problema general.

La **tolerancia a fallas** se relaciona con la capacidad del sistema para enfrentarse a la presencia de fallos.

La **recuperación** se relaciona con la necesidad de restablecer un estado correcto cuando dichos fallos afectan al sistema.

El flujo conceptual es:

```text
Falla
  ↓
Detección del problema
  ↓
El sistema intenta continuar o reaccionar
  ↓
Recuperación
  ↓
Estado válido
```

Las diapositivas no especifican todavía los algoritmos empleados para realizar estas tareas, por lo que esta introducción debe entenderse como la identificación del problema, no como una explicación de mecanismos concretos.

---

## Seguridad

La página 7 añade **Seguridad** junto con tolerancia a fallas.

Cuando los componentes del sistema se comunican mediante una infraestructura distribuida, la información deja de permanecer exclusivamente dentro de una única máquina.

Esto implica que existen múltiples participantes y canales de comunicación que deben ser considerados desde el punto de vista de seguridad.

La relación básica puede representarse así:

```text
Nodo A
   │
   │ información
   ▼
Red de comunicación
   │
   ▼
Nodo B
```

El sistema debe permitir que los componentes correctos se comuniquen y utilicen los recursos correspondientes sin que la distribución elimine las garantías necesarias sobre la información y los servicios.

La diapositiva no detalla todavía mecanismos específicos de seguridad. Únicamente la establece como uno de los requerimientos fundamentales que surgen al construir un entorno distribuido.

---

## Relación entre los requerimientos mínimos

Los requerimientos presentados en las tres diapositivas no deben aprenderse como conceptos aislados. Todos aparecen como consecuencia de haber distribuido los componentes del sistema de información.

La relación puede reconstruirse de la siguiente forma:

```text
Sistema de información
        ↓
Se distribuyen sus componentes
        ↓
Existen múltiples recursos y máquinas
        │
        ├── deben comunicarse
        │
        ├── deben poder identificarse
        │
        ├── tienen estados locales
        │
        ├── evolucionan con el tiempo
        │
        ├── pueden fallar de manera independiente
        │
        └── deben proteger recursos e información
        ↓
Requerimientos de un sistema distribuido
```

De esta manera, la secuencia de las diapositivas sigue una lógica clara.

Primero aparece la **comunicación**, porque sin ella los participantes no podrían cooperar.

Después aparece el **nombrado y designación**, porque una vez conectados resulta necesario identificar los recursos disponibles.

Posteriormente aparece el problema del **estado global y la recuperación**, porque los componentes evolucionan independientemente a lo largo del tiempo.

Finalmente aparecen la **tolerancia a fallas y la seguridad**, porque un sistema formado por múltiples componentes debe ser capaz de considerar fallas parciales y proteger sus recursos.

## Del sistema de información centralizado al distribuido

Toda esta parte de la introducción puede entenderse mediante una transformación progresiva.

### Sistema de información convencional

```text
Interfaz
    ↓
Aplicación
    ↓
Acceso
    ↓
Almacenamiento
    ↓
Datos
```

Todos los componentes se presentan inicialmente como una única estructura funcional.

### Sistema de información distribuido

Los mismos elementos pueden comenzar a dividirse entre diferentes participantes:

```text
        Usuarios
       /   |   \
      ▼    ▼    ▼
 Interfaces distribuidas
       \   |   /
      Aplicaciones
       distribuidas
           │
     Comunicación
       /       \
      ▼         ▼
 Acceso A    Acceso B
    │           │
    ▼           ▼
 Datos A     Datos B
```

La funcionalidad básica sigue existiendo, pero ahora debe añadirse una infraestructura que permita coordinarla.

### Nuevos problemas

Como resultado aparecen:

```text
Distribución
    ↓
Comunicación
    ↓
Nombrado y designación
    ↓
Estado global + tiempo
    ↓
Recuperación
    ↓
Tolerancia a fallas
    ↓
Seguridad
```

Esta secuencia resume el argumento completo de la clase.

## Qué cambia realmente al distribuir un sistema

La diferencia principal entre un sistema de información convencional y uno distribuido no consiste únicamente en utilizar más computadoras.

El cambio fundamental es que **las distintas funciones dejan de encontrarse necesariamente dentro del mismo espacio físico y lógico**.

En el sistema original, una operación podía recorrer:

```text
Interfaz
→ Aplicación
→ Datos
```

dentro de una infraestructura relativamente integrada.

Después de la distribución puede ocurrir:

```text
Interfaz
   │
   ▼
Máquina A
   │
   │ comunicación
   ▼
Máquina B
   │
   ▼
Servicio de acceso
   │
   │ comunicación
   ▼
Máquina C
   │
   ▼
Datos
```

La operación sigue siendo conceptualmente la misma, pero ahora depende de múltiples componentes que deben localizarse, comunicarse, coordinarse y mantenerse disponibles.

Por eso la distribución introduce complejidad adicional incluso cuando la función visible para el usuario parece sencilla.

# Ideas fundamentales de la clase

Un sistema de información puede analizarse separando su interfaz de usuario, su lógica aplicativa y la administración de datos. Esta última comprende los mecanismos de acceso, almacenamiento y los datos propiamente dichos.

Cuando un sistema de información se distribuye, estos componentes pueden dejar de encontrarse concentrados en una sola máquina. La interfaz, las aplicaciones, el acceso, el almacenamiento y los datos pueden repartirse entre diferentes participantes.

La comunicación constituye la base que permite convertir varios recursos independientes en un sistema capaz de colaborar. Sin ella, la distribución produciría únicamente componentes aislados.

Una vez que existen múltiples recursos conectados aparece la necesidad de nombrarlos y designarlos, ya que el sistema debe saber qué recurso se desea utilizar y cómo identificarlo dentro del entorno distribuido.

La distribución también provoca que el estado del sistema se encuentre repartido. Cada participante posee un estado local y todos evolucionan a lo largo del tiempo, por lo que construir una visión del estado global resulta necesario para coordinar correctamente el funcionamiento y la recuperación.

Finalmente, los componentes de un sistema distribuido pueden fallar de manera independiente. Por ello aparecen como requerimientos fundamentales la tolerancia a fallas, la recuperación y la seguridad. La introducción no desarrolla todavía los mecanismos concretos para resolver estos problemas, sino que establece por qué surgen necesariamente cuando un sistema de información pasa de una arquitectura centralizada a una distribuida.
