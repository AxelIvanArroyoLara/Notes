## Introducción

Cuando se desea mostrar en displays de 7 segmentos el resultado de una operación binaria, no basta con conectar directamente los bits de la salida al display. Un número binario y un conjunto de dígitos decimales representan la información de forma diferente.

El problema planteado consiste en tomar un registro binario de **9 bits**, cuyo rango es de $0$ a $511$, y mostrar su valor decimal utilizando **tres displays de 7 segmentos**:

```
Display 2     Display 1     Display 0
Centenas      Decenas       Unidades
```

Por ejemplo, si la entrada binaria representa:

\[ 345 \]

los displays deben mostrar:

```
3   4   5
```

Para conseguirlo, el diseño se divide en dos etapas:

```
Binario de 9 bits
       │
       ▼
Conversión binario → BCD
       │
       ├── centenas
       ├── decenas
       └── unidades
       │
       ▼
BCD → 7 segmentos
       │
       ▼
3 displays
```

Esta separación permite reutilizar un mismo módulo BCD-a-7-segmentos para cada uno de los tres dígitos. El documento propone exactamente esta arquitectura por etapas para convertir un valor entre $0$ y $511$ en centenas, decenas y unidades antes de enviarlo a los displays. BCD_a_decimal-1

---

## Representación BCD

### Qué se necesita obtener:

Después de convertir el número binario, el sistema produce tres valores:

- `hund`: centenas, entre $0$ y $5$;
- `tens`: decenas, entre $0$ y $9$;
- `ones`: unidades, entre $0$ y $9$.

Cada uno utiliza 4 bits porque un dígito decimal entre $0$ y $9$ puede representarse mediante BCD.

Por ejemplo, para:

\[ 345 \]

se obtiene:

```
hund = 3
tens = 4
ones = 5
```

En binario:

```
hund = 0011
tens = 0100
ones = 0101
```

Estos valores ya pueden entregarse individualmente a un decodificador BCD a 7 segmentos.

### Por qué no puede utilizarse directamente el binario:

Un valor como:

```
9'b101011001
```

es un número binario completo, no tres dígitos decimales independientes.

Un display de 7 segmentos no necesita conocer el valor binario completo, sino qué dígito decimal debe mostrar.

Por ello se requiere una transformación intermedia:

```
binario
   ↓
dígitos decimales en BCD
   ↓
segmentos del display
```

Esta es la función del convertidor binario a BCD. BCD_a_decimal-1

## Primer método: división por constantes

### Idea general:

El primer método utiliza operaciones aritméticas simples para separar centenas, decenas y unidades.

Si la entrada `bin` está limitada al rango:

\[ 0\le bin\le511 \]

entonces puede descomponerse mediante divisiones por $100$ y $10$.

El proceso es:

```
bin
 │
 ├── /100 ──────────────► centenas
 │
 └── quitar centenas
         │
         ▼
        r100
         │
         ├── /10 ───────► decenas
         │
         └── quitar decenas
                  │
                  ▼
                unidades
```

---

## Obtención de las centenas

### División entre 100:

Las centenas se calculan mediante:

\[ hund=\left\lfloor\frac{bin}{100}\right\rfloor \]

Como la entrada máxima es:

\[ 511 \]

el valor máximo de centenas es:

\[ \left\lfloor\frac{511}{100}\right\rfloor=5 \]

Por tanto:

\[ 0\le hund\le5 \]

En Verilog:

```
assign hund = bin / 9'd100;
```

Por ejemplo:

\[ bin=345 \]

entonces:

\[ hund=\left\lfloor\frac{345}{100}\right\rfloor=3 \]

La división entera elimina la parte fraccionaria.

---

## Residuo después de extraer centenas

### Eliminación de la contribución de centenas:

Después de conocer las centenas, debe eliminarse esa parte del número.

Se calcula:

\[ r100=bin-hund\cdot100 \]

Para:

\[ bin=345 \]

y:

\[ hund=3 \]

se obtiene:

\[ r100=345-(3)(100) \]\[ r100=45 \]

Por tanto, `r100` contiene únicamente la parte correspondiente a decenas y unidades.

El rango de `r100` queda entre:

\[ 0 \]

y:

\[ 99 \]

En Verilog:

```
assign r100 = bin - hund * 9'd100;
```

---

## Obtención de las decenas

### División entre 10:

Una vez eliminadas las centenas, las decenas se calculan como:

\[ tens=\left\lfloor\frac{r100}{10}\right\rfloor \]

Dado que:

\[ 0\le r100\le99 \]

entonces:

\[ 0\le tens\le9 \]

Para:

\[ r100=45 \]

se obtiene:

\[ tens=\left\lfloor\frac{45}{10}\right\rfloor=4 \]

En Verilog:

```
assign tens = r100 / 9'd10;
```

---

## Obtención de las unidades

### Eliminación de las decenas:

Después de obtener las decenas, se elimina su contribución:

\[ ones=r100-tens\cdot10 \]

Para:

\[ r100=45 \]

y:

\[ tens=4 \]

se obtiene:

\[ ones=45-(4)(10) \]\[ ones=5 \]

En Verilog:

```
assign ones = r100 - tens * 9'd10;
```

El proceso completo para $345$ queda:

```
345 / 100 = 3
      ↓
centenas = 3

345 - 300 = 45
      ↓
r100 = 45

45 / 10 = 4
      ↓
decenas = 4

45 - 40 = 5
      ↓
unidades = 5
```

---

## Implementación combinacional con `assign`

### Módulo:

La implementación presentada es completamente combinacional:

```
module bin9_to_bcd3_struct (
    input  wire [8:0] bin,
    output wire [3:0] hund,
    output wire [3:0] tens,
    output wire [3:0] ones
);

    wire [8:0] r100;

    assign hund = bin / 9'd100;

    assign r100 = bin - hund * 9'd100;

    assign tens = r100 / 9'd10;

    assign ones = r100 - tens * 9'd10;

endmodule
```

Cada `assign` describe una relación combinacional continua.

No existe un reloj ni registros dentro del módulo.

Por tanto:

```
cambia bin
   ↓
se recalculan centenas
   ↓
se recalcula r100
   ↓
se recalculan decenas
   ↓
se recalculan unidades
```

El documento señala que, en FPGA, las divisiones por constantes suelen ser optimizadas por las herramientas de síntesis y que, cuando `/` está permitido en el proyecto, esta versión resulta compacta y legible. BCD_a_decimal-1

## Significado del ancho `9'd100`

### Literal de Verilog:

La expresión:

```
9'd100
```

puede interpretarse como:

```
9  → ancho del literal
'd → base decimal
100 → valor
```

Así, el número decimal $100$ se representa utilizando 9 bits dentro de la expresión.

El mismo patrón aparece con:

```
9'd10
```

que representa el valor decimal $10$ con un ancho explícito de 9 bits.

Mantener controlados los anchos evita que las operaciones se interpreten con tamaños inesperados.

## Segundo método: comparadores y restas

### Objetivo:

El segundo método realiza la misma conversión sin utilizar:

```
/
%
```

En su lugar se utilizan:

- comparadores `>=`;
- multiplexores mediante `? :`;
- restas.

El procedimiento consiste en identificar en qué rango se encuentra la entrada y, a partir de ese rango, determinar el dígito correspondiente.

El documento propone este método especialmente para casos donde el uso de división esté prohibido. BCD_a_decimal-1

---

## Centenas mediante comparación por rangos

### Comparadores:

Para conocer cuántas centenas existen, se comprueba si el valor es mayor o igual a ciertos múltiplos de 100.

Por ejemplo:

```
wire ge500 = (bin >= 9'd500);
wire ge400 = (bin >= 9'd400);
wire ge300 = (bin >= 9'd300);
wire ge200 = (bin >= 9'd200);
wire ge100 = (bin >= 9'd100);
```

Cada señal responde a una pregunta.

Por ejemplo:

```
ge500 = 1
```

significa:

\[ bin\ge500 \]

Mientras que:

```
ge300 = 1
```

significa:

\[ bin\ge300 \]

### Selección de centenas:

Después se utiliza una cadena de operadores ternarios:

```
assign hund =
    ge500 ? 4'd5 :
    ge400 ? 4'd4 :
    ge300 ? 4'd3 :
    ge200 ? 4'd2 :
    ge100 ? 4'd1 :
            4'd0;
```

El orden es importante porque primero se comprueban los valores más grandes.

Por ejemplo, si:

\[ bin=345 \]

entonces:

```
345 >= 500 → falso
345 >= 400 → falso
345 >= 300 → verdadero
```

Por tanto:

```
hund = 3
```

---

## Operador ternario como multiplexor

### Sintaxis:

El operador:

```
condicion ? A : B
```

significa:

```
si condición = 1
    salida = A
si condición = 0
    salida = B
```

En términos de hardware puede interpretarse como un multiplexor 2:1.

```
           A ─────┐
                  │
condición ─────► MUX ───► salida
                  │
           B ─────┘
```

Una cadena como:

```
ge500 ? 5 :
ge400 ? 4 :
ge300 ? 3 :
...
```

representa una estructura de selección basada en prioridades.

El documento señala explícitamente que el patrón `cond ? A : B` se convierte en un multiplexor, mientras que `>=` produce comparadores. BCD_a_decimal-1

---

## Residuo de las centenas

### Cálculo:

Después de obtener `hund`, se calcula:

\[ r100=bin-hund\cdot100 \]

En Verilog:

```
wire [8:0] r100 = bin - (hund * 9'd100);
```

Aunque aparece una multiplicación, el segundo operando corresponde a una constante y `hund` únicamente puede tomar valores entre $0$ y $5$.

El resultado sigue estando limitado a:

\[ 0\le r100\le99 \]

---

## Decenas mediante comparación por rangos

### Comparadores:

Una vez obtenido `r100`, se realizan comparaciones con múltiplos de $10$:

```
wire ge90 = (r100 >= 9'd90);
wire ge80 = (r100 >= 9'd80);
wire ge70 = (r100 >= 9'd70);
wire ge60 = (r100 >= 9'd60);
wire ge50 = (r100 >= 9'd50);
wire ge40 = (r100 >= 9'd40);
wire ge30 = (r100 >= 9'd30);
wire ge20 = (r100 >= 9'd20);
wire ge10 = (r100 >= 9'd10);
```

Posteriormente:

```
assign tens =
    ge90 ? 4'd9 :
    ge80 ? 4'd8 :
    ge70 ? 4'd7 :
    ge60 ? 4'd6 :
    ge50 ? 4'd5 :
    ge40 ? 4'd4 :
    ge30 ? 4'd3 :
    ge20 ? 4'd2 :
    ge10 ? 4'd1 :
           4'd0;
```

Para:

\[ r100=45 \]

se obtiene:

```
45 >= 90 → 0
45 >= 80 → 0
...
45 >= 50 → 0
45 >= 40 → 1
```

por lo que:

```
tens = 4
```

---

## Unidades mediante resta

### Cálculo final:

Las unidades se obtienen eliminando las decenas:

\[ ones=r100-tens\cdot10 \]

En Verilog:

```
assign ones = r100 - (tens * 9'd10);
```

El documento señala que esta expresión es equivalente a calcular el residuo entre $10$, pero sin utilizar el operador `%`. BCD_a_decimal-1

---

## Ejemplo completo del método por comparación

### Entrada $345$:

Para centenas:

```
345 >= 500 → no
345 >= 400 → no
345 >= 300 → sí
```

Entonces:

\[ hund=3 \]

Después:

\[ r100=345-(3)(100)=45 \]

Para decenas:

```
45 >= 90 → no
45 >= 80 → no
...
45 >= 40 → sí
```

Entonces:

\[ tens=4 \]

Finalmente:

\[ ones=45-(4)(10)=5 \]

El resultado BCD es:

```
hund = 0011
tens = 0100
ones = 0101
```

Es decir:

```
3 4 5
```

## Comparación entre los dos métodos

### División por constantes:

El primer método expresa directamente las operaciones matemáticas:

```
/100
- centenas × 100
/10
- decenas × 10
```

Tiene una descripción corta y clara.

### Comparadores y restas:

El segundo método expresa de forma más explícita el hardware:

```
comparar con 500, 400, 300...
        ↓
seleccionar centenas
        ↓
restar centenas
        ↓
comparar con 90, 80, 70...
        ↓
seleccionar decenas
        ↓
restar decenas
```

La diferencia puede resumirse así:

|Método|Operaciones principales|Característica|
|---|---|---|
|División por constantes|`/`, multiplicación, resta|Más compacto|
|Comparadores y restas|`>=`, `? :`, resta|Evita `/` y `%`|

Ambos generan finalmente los mismos tres dígitos BCD.

## Interpretación del hardware sintetizado

### Comparaciones:

Una expresión como:

```
bin >= 9'd300
```

representa un comparador.

Conceptualmente:

```
bin ──────┐
          ├── comparador >= ──► 0 o 1
300 ──────┘
```

### Operador ternario:

Una expresión:

```
cond ? A : B
```

representa un multiplexor.

### Resta:

Una operación:

```
A - B
```

puede implementarse mediante suma utilizando complemento a dos.

El documento resume precisamente esta traducción: comparaciones `>=` se convierten en comparadores, el operador ternario en multiplexores y las restas en sumadores que utilizan complemento a dos. BCD_a_decimal-1

## Conexión con los displays de 7 segmentos

### Arquitectura completa:

Después de producir los tres dígitos BCD, cada uno se conecta a una instancia del decodificador BCD a 7 segmentos.

La arquitectura general es:

```
                  ┌──────────► BCD→7seg ──► seg2
                  │             centenas
                  │
bin[8:0] ─► Binario→BCD
                  │
                  ├──────────► BCD→7seg ──► seg1
                  │             decenas
                  │
                  └──────────► BCD→7seg ──► seg0
                                unidades
```

Se utiliza un solo convertidor binario-a-BCD, pero tres instancias del mismo módulo BCD-a-7-segmentos.

---

## Reutilización de módulos

### Instancias:

Si ya existe un módulo:

```
bcd_to_7seg
```

puede reutilizarse tres veces:

```
bcd_to_7seg s0 (
    .digit(o),
    .seg(seg0)
);

bcd_to_7seg s1 (
    .digit(t),
    .seg(seg1)
);

bcd_to_7seg s2 (
    .digit(h),
    .seg(seg2)
);
```

Cada instancia contiene la misma lógica funcional, pero recibe un dígito distinto.

Así:

```
s0 → unidades
s1 → decenas
s2 → centenas
```

Este patrón muestra una ventaja importante del diseño modular en Verilog: una función puede describirse una vez y posteriormente reutilizarse mediante múltiples instancias.

## Módulo superior

### Estructura:

El documento propone un módulo que conecta todo:

```
module mult9_to_3x7seg (
    input  wire [8:0] mult_out,
    output wire [6:0] seg0,
    output wire [6:0] seg1,
    output wire [6:0] seg2
);

    wire [3:0] h, t, o;

    bin9_to_bcd3_cmp_sub u0 (
        .bin(mult_out),
        .hund(h),
        .tens(t),
        .ones(o)
    );

    bcd_to_7seg s0 (
        .digit(o),
        .seg(seg0)
    );

    bcd_to_7seg s1 (
        .digit(t),
        .seg(seg1)
    );

    bcd_to_7seg s2 (
        .digit(h),
        .seg(seg2)
    );

endmodule
```

La estructura puede verse como una jerarquía:

```
mult9_to_3x7seg
│
├── u0: binario → BCD
│
├── s0: BCD → 7 segmentos
│        unidades
│
├── s1: BCD → 7 segmentos
│        decenas
│
└── s2: BCD → 7 segmentos
         centenas
```

El documento conecta explícitamente uno de los dos convertidores binario-a-BCD con tres instancias reutilizadas del decodificador BCD-a-7-segmentos. BCD_a_decimal-1

## Displays dedicados y displays multiplexados

### Displays dedicados:

Si cada display posee su propio bus:

```
seg0[6:0]
seg1[6:0]
seg2[6:0]
```

entonces cada decodificador puede controlar permanentemente su display.

La arquitectura es:

```
BCD unidades ──► decoder ──► seg0
BCD decenas  ──► decoder ──► seg1
BCD centenas ─► decoder ──► seg2
```

No hace falta ningún mecanismo adicional de selección temporal.

### Displays multiplexados:

Si los tres displays comparten las mismas líneas de segmentos, no pueden recibir simultáneamente tres patrones independientes a través del mismo bus.

En ese caso se necesita hardware adicional:

```
contador / temporizador
        │
        ▼
selección de display
        │
        ▼
MUX de segmentos
        │
        ▼
líneas compartidas
```

El sistema debe seleccionar repetidamente qué display se encuentra activo y qué patrón de segmentos se coloca en el bus compartido.

El documento señala específicamente que, para displays multiplexados, se necesita un controlador adicional formado por temporizador o contador, selección de display y multiplexor de segmentos. BCD_a_decimal-1

---

## Ánodo común y cátodo común

### Importancia:

El mismo patrón lógico no funciona necesariamente para todos los displays.

El módulo:

```
bcd_to_7seg
```

debe corresponder al tipo físico de display utilizado.

### Cátodo común:

Normalmente los segmentos son activos en `1`.

Conceptualmente:

```
1 → segmento encendido
0 → segmento apagado
```

### Ánodo común:

Normalmente ocurre lo contrario:

```
0 → segmento encendido
1 → segmento apagado
```

Por tanto, en un display de ánodo común suele requerirse invertir el patrón de segmentos.

El documento advierte explícitamente que el decodificador debe adaptarse al tipo de display y que la polaridad de activación cambia entre ánodo y cátodo común. BCD_a_decimal-1

## Separación de responsabilidades

### Convertidor binario a BCD:

Su trabajo termina cuando produce:

```
hund
tens
ones
```

No necesita saber cómo funciona físicamente el display.

### Decodificador BCD a 7 segmentos:

Recibe únicamente un valor entre $0$ y $9$:

```
digit
```

y produce:

```
seg[6:0]
```

No necesita saber de dónde provino el número.

### Driver de multiplexado:

Si los displays comparten líneas, este módulo se encarga de seleccionar temporalmente:

- qué display se activa;
- qué patrón se muestra.

Esta separación produce una arquitectura modular:

```
Conversión numérica
       │
       ▼
Codificación visual
       │
       ▼
Control físico del display
```

Cada módulo realiza una función concreta.

# Ideas fundamentales de la clase

Un número binario de 9 bits no puede conectarse directamente a tres displays esperando que aparezcan centenas, decenas y unidades. Primero debe convertirse a una representación decimal separada en tres dígitos BCD.

La arquitectura recomendada divide el problema en dos etapas. La primera convierte el valor binario en centenas, decenas y unidades. La segunda reutiliza un decodificador BCD-a-7-segmentos para convertir cada dígito en el patrón visual correspondiente.

La separación decimal puede realizarse mediante división por constantes. Las centenas se obtienen dividiendo entre $100$, posteriormente se elimina su contribución, las decenas se obtienen dividiendo el residuo entre $10$ y finalmente las unidades se obtienen mediante una resta.

También puede realizarse la conversión sin utilizar `/` ni `%`. En ese caso se utilizan comparadores, multiplexores y restas. Los comparadores determinan en qué rango está el valor, mientras que una cadena de operadores ternarios selecciona el dígito correspondiente.

El operador `cond ? A : B` describe una selección combinacional que se implementa como un multiplexor. Del mismo modo, las expresiones `>=` se implementan mediante comparadores y las restas pueden realizarse mediante sumadores utilizando complemento a dos.

La reutilización de módulos permite emplear un solo diseño `bcd_to_7seg` tres veces: una instancia para unidades, otra para decenas y otra para centenas. Esto permite mantener separada la conversión numérica de la lógica de visualización.

Finalmente, la conexión física depende del tipo de hardware disponible. Si cada display posee sus propias líneas de segmentos, pueden controlarse directamente. Si los displays comparten las mismas líneas, se necesita multiplexado mediante un temporizador o contador, selección de display y un multiplexor de segmentos. Además, la lógica del decodificador debe respetar si el display es de ánodo común o cátodo común.
