## Introducción

Los sistemas digitales implementados en FPGA no solo deben producir un resultado correcto; también deben considerar **cuántos recursos utilizan, cuántos ciclos requieren, qué precisión ofrecen y cómo se comunican con el resto del sistema**. Esta idea es especialmente importante al implementar operaciones como multiplicación y división, ya que una misma operación matemática puede convertirse en arquitecturas de hardware muy diferentes.

El desarrollo de multiplicadores y divisores parte de operaciones binarias básicas como desplazamientos, sumas, restas y comparaciones. A partir de ellas pueden construirse arquitecturas completamente combinacionales, capaces de entregar un resultado con poca latencia pero utilizando más recursos, o arquitecturas iterativas, que reutilizan el mismo hardware durante varios ciclos para reducir el área ocupada. El objetivo general es interpretar multiplicación y división binarias, entender productos parciales, residuos y desplazamientos, y relacionar estas operaciones con una implementación sintetizable en Verilog. multiplicadores_divisores_captu…

## Desplazamientos binarios

### Desplazamiento a la izquierda:

Un desplazamiento hacia la izquierda mueve todos los bits de un número una determinada cantidad de posiciones y, para números enteros sin signo, equivale a multiplicar por una potencia de dos.

Si $x$ se desplaza $k$ posiciones:

\[ x << k = x2^k \]

Por ejemplo:

\[ 0011_2 = 3 \]

al desplazarse una posición hacia la izquierda:

\[ 0011 << 1 = 0110_2 = 6 \]

Por tanto:

\[ 3 \cdot 2 = 6 \]

Esta operación es especialmente útil en hardware porque un desplazamiento puede realizarse de manera mucho más directa que una multiplicación general.

### Desplazamiento a la derecha:

Un desplazamiento hacia la derecha equivale aproximadamente a dividir entre una potencia de dos:

\[ x >> k \approx \left\lfloor \frac{x}{2^k}\right\rfloor \]

En una representación entera, los bits que salen por la derecha se pierden del resultado almacenado. Sin embargo, estos bits pueden contener información importante relacionada con el **residuo o la parte fraccionaria**.

Por ejemplo:

\[ 0111_2 = 7 \]

y:

\[ 0111 >> 1 = 0011_2 = 3 \]

Matemáticamente:

\[ \frac{7}{2}=3 \]

con residuo:

\[ 1 \]

Por esta razón, en operaciones de división no siempre puede ignorarse el bit descartado.

## Anchura de los resultados

### Importancia del número de bits:

Uno de los errores más comunes en hardware digital consiste en realizar correctamente una operación, pero almacenar el resultado en un registro demasiado pequeño.

El ancho forma parte del diseño funcional del circuito.

Para una suma entre dos números de $N$ bits puede requerirse:

\[ N+1 \]

bits.

Por ejemplo:

\[ 1111_2 + 1111_2 = 11110_2 \]

Dos números de 4 bits producen un resultado de 5 bits.

### Anchura en multiplicación:

La regla práctica presentada para una multiplicación es:

\[ [N\text{ bits}] \times [N\text{ bits}] \rightarrow [2N\text{ bits}] \]

Esto ocurre porque el valor máximo sin signo de $N$ bits es:

\[ 2^N-1 \]

y el producto máximo es:

\[ (2^N-1)^2 \]

que puede requerir hasta $2N$ bits.

Por ejemplo, para dos operandos de 4 bits:

\[ 15 \times 15 = 225 \]

y:

\[ 225_{10}=11100001_2 \]

que utiliza 8 bits.

### Anchura en división:

En división deben considerarse dos resultados diferentes:

- cociente;
- residuo.

Si el dividendo y divisor son de $N$ bits, normalmente se reserva hasta $N$ bits para el cociente y suficiente espacio para el residuo.

La idea fundamental es que **perder un bit no constituye únicamente un problema visual: puede cambiar completamente el valor numérico obtenido**. ## Representación de números con signo

### Complemento a dos:

La representación más utilizada para números enteros negativos en sistemas digitales es el **complemento a dos**.

Para un número de $N$ bits, el rango representable es:

\[ -2^{N-1}\le x\le 2^{N-1}-1 \]

Por ejemplo, con 8 bits:

\[ -128\le x\le127 \]

El complemento a dos de un número puede obtenerse invirtiendo todos sus bits y sumando uno:

\[ C2(x)=\overline{x}+1 \]

Por ejemplo:

```
00101101
   ↓ invertir
11010010
   ↓ +1
11010011
```

### Complemento a uno:

El **complemento a uno** consiste únicamente en invertir los bits:

\[ C1(x)=\overline{x} \]

La diferencia fundamental es que el complemento a uno puede representar dos ceros, mientras que el complemento a dos tiene un único cero.

Por esta razón, la mayoría de procesadores y FPGA emplean complemento a dos para representar enteros negativos.

## Suma y resta utilizando el mismo hardware

### Restar mediante complemento a dos:

Una resta:

\[ A-B \]

puede transformarse en:

\[ A-B=A+(\overline{B}+1) \]

Esto permite utilizar **el mismo sumador tanto para sumar como para restar**.

La arquitectura utiliza una señal de control, por ejemplo `SUB`.

```
                 SUB
                  │
B ──────────────► XOR ─────► B'
                              │
A ────────────────────────────┼──► SUMADOR ───► Y
                              │
                        Cin = SUB
```

Cuando:

\[ SUB=0 \]

se obtiene:

\[ B'=B \]

y:

\[ Cin=0 \]

por lo que:

\[ Y=A+B \]

Cuando:

\[ SUB=1 \]

se obtiene:

\[ B'=\overline{B} \]

y:

\[ Cin=1 \]

por lo tanto:

\[ Y=A+\overline{B}+1=A-B \]

El uso de XOR permite invertir condicionalmente todos los bits de $B$. Esta estructura evita construir un sumador y un restador independientes.

## Diseño parametrizable en Verilog

### Parámetros:

Un módulo puede definirse de forma que su tamaño sea modificable al momento de elaborar el diseño.

Por ejemplo:

```
module addsub #(parameter N = 8) (
    input  wire [N-1:0] A, B,
    input  wire SUB,
    output wire [N-1:0] Y,
    output wire COUT
);
```

El parámetro:

```
parameter N = 8
```

establece un valor predeterminado de 8 bits, pero puede modificarse cuando se instancia el módulo.

Por ejemplo:

```
addsub #(.N(16)) u_addsub (...);
```

crea una versión de 16 bits.

### Significado de `#`:

El símbolo `#` se relaciona aquí con la lista de parámetros de un módulo.

El parámetro **no es una variable que cambie mientras el circuito está funcionando**.

Se determina durante la elaboración del diseño.

Conceptualmente:

```
Parámetro
    │
    ├── define tamaño o estructura
    │
    └── se fija antes de operar el hardware
```

## Multiplicación binaria

### Productos parciales:

La multiplicación binaria puede interpretarse como una suma de **productos parciales desplazados**.

Si:

\[ B=\sum_{i=0}^{N-1}b_i2^i \]

entonces:

\[ AB=\sum_{i=0}^{N-1}b_i(A<<i) \]

Cada bit $b_i$ del multiplicador decide si debe agregarse o no una copia desplazada de $A$.

Si:

\[ b_i=0 \]

el producto parcial correspondiente es cero.

Si:

\[ b_i=1 \]

el producto parcial es:

\[ A<<i \]

Por tanto, una multiplicación binaria puede reducirse a:

```
examinar bit
    │
    ▼
¿vale 1?
 ├── no ──► no sumar
 │
 └── sí ──► sumar A desplazado
```

Esta es la idea central detrás del multiplicador **shift-add**.

---

## Ejemplo de multiplicación binaria

### Multiplicación de 11 por 6:

Se consideran:

\[ A=1011_2=11 \]

y:

\[ B=0110_2=6 \]

El multiplicador $B$ contiene los bits:

```
0 1 1 0
```

Por tanto, los productos parciales relevantes corresponden a las posiciones donde aparece un `1`.

El primer bit vale cero:

\[ 1011\times0=0000000 \]

El siguiente bit vale uno y está en la posición 1:

\[ 1011<<1=0010110 \]

El siguiente también vale uno y se encuentra en la posición 2:

\[ 1011<<2=0101100 \]

Al sumar:

\[ 0010110+0101100=1000010_2 \]

y:

\[ 1000010_2=66 \]

Por tanto:

\[ 11\times6=66 \]

La multiplicación binaria puede resumirse como **examinar, desplazar y sumar repetidamente**.

## Arquitecturas de multiplicación

### Multiplicador combinacional:

Una arquitectura combinacional genera el producto mediante hardware que realiza toda la función sin reutilizar secuencialmente el mismo recurso.

Puede describirse simplemente mediante:

```
assign P = A * B;
```

Si los operandos poseen $N$ bits:

```
input  wire [N-1:0] A, B;
output wire [2*N-1:0] P;
```

El ancho de $P$ permite conservar todos los bits significativos del resultado.

El operador `*` expresa **la intención del diseño**. Posteriormente, la herramienta de síntesis decide cómo implementar físicamente la operación, por ejemplo utilizando LUT o bloques DSP.

### Multiplicador shift-add:

El multiplicador **shift-add** reutiliza un mismo sumador durante varios ciclos.

Su latencia típica es del orden de:

\[ N \]

ciclos para operandos de $N$ bits.

Su principal ventaja es utilizar menos hardware.

### Multiplicador con DSP y pipeline:

Una FPGA puede disponer de bloques DSP especializados capaces de realizar multiplicaciones eficientemente.

También pueden introducirse registros intermedios formando un **pipeline**.

Esto aumenta el número de ciclos entre entrada y salida, pero permite procesar nuevas entradas con mayor frecuencia.

Las arquitecturas se comparan de forma general como:

|Arquitectura|Latencia|Área|Uso típico|
|---|---|---|---|
|Combinacional|Baja|Alta|Máxima velocidad|
|Shift-add|$N$ ciclos|Baja|Ahorro de recursos|
|DSP/pipeline|Varios ciclos|Bloques DSP|Procesamiento intensivo|

La elección depende de los recursos disponibles y del rendimiento requerido.

## Multiplicador secuencial shift-add

### Funcionamiento general:

El algoritmo utiliza normalmente:

- un registro para $A$;
- un registro para $B$;
- un acumulador;
- un sumador;
- un contador;
- lógica de control.

El procedimiento básico es:

1. cargar $A$ y $B$;
2. inicializar el acumulador en cero;
3. observar el bit menos significativo de $B$;
4. si ese bit vale `1`, sumar $A$ al acumulador;
5. desplazar $A$ hacia la izquierda;
6. desplazar $B$ hacia la derecha;
7. repetir durante $N$ ciclos.

El esquema conceptual es:

```
A_reg ── <<1 ──►
                \
                 ► SUMADOR ──► ACUMULADOR
                /
B_reg[0] ──────┘

B_reg ── >>1

          ▲
          │
     FSM + contador
```

La presentación separa claramente dos responsabilidades:

```
Datapath → realiza operaciones sobre los datos
FSM      → decide cuándo debe realizarse cada operación
```

Esta separación es fundamental en el diseño digital. multiplicadores_divisores_captu…

### Importancia de $B_0$:

El bit menos significativo del multiplicador determina si el multiplicando debe agregarse al acumulador durante esa iteración.

Es decir:

\[ B_0=1 \Rightarrow \text{sumar} \]\[ B_0=0 \Rightarrow \text{no sumar} \]

Posteriormente $B$ se desplaza a la derecha para que el siguiente bit ocupe la posición $B_0$.

## Señales `start` y `done`

### Operaciones iterativas:

Una operación que tarda varios ciclos necesita un protocolo para indicar:

- cuándo comenzar;
- cuándo está ocupada;
- cuándo el resultado es válido.

Una estructura típica utiliza estados:

```
           start
IDLE ─────────────► RUN
                    │
                    │ count < N
                    └───────┐
                            │
                    count = N
                            ▼
                           DONE
                            │
                         nuevo
                         start
                            │
                            ▼
                           IDLE
```

### Estado `IDLE`:

El módulo espera una nueva operación.

### Estado `RUN`:

Se realizan las iteraciones requeridas.

### Estado `DONE`:

La salida ya es válida.

La señal `start` captura las entradas y `done` indica que el resultado puede utilizarse. Durante la ejecución no debe aceptarse una nueva operación si el hardware todavía está ocupado. multiplicadores_divisores_captu…

## Verificación mediante testbench

### Función del testbench:

Un **testbench** aplica estímulos al módulo y comprueba sus resultados.

Por ejemplo:

```
initial begin
    A = 4'd3;
    B = 4'd5;
    #10;

    A = 4'd15;
    B = 4'd15;
    #10;

    $display("A=%d B=%d P=%d", A, B, P);
    $finish;
end
```

Los casos de prueba deberían incluir:

- cero;
- uno;
- valores máximos;
- potencias de dos;
- combinaciones aleatorias;
- valores que prueben límites de ancho.

Es importante distinguir entre **simulación** y **síntesis**.

La simulación comprueba principalmente el comportamiento lógico descrito.

La síntesis determina el hardware generado y permite analizar recursos, temporización y restricciones.

## Multiplicación con signo

### Extensión de signo:

Cuando un número con signo debe ampliarse a una cantidad mayor de bits, no deben agregarse ceros indiscriminadamente.

Debe copiarse el bit de signo.

Por ejemplo:

\[ 1011_2=-5 \]

en 4 bits.

Al extenderlo a 8 bits:

\[ 11111011_2=-5 \]

Los bits agregados son unos porque el bit de signo original era `1`.

Si el número fuera positivo, se agregarían ceros.

### Uso de `signed`:

En Verilog, los operandos que representan números con signo deben declararse explícitamente como `signed`.

Por ejemplo:

```
input  wire signed [N-1:0] A;
input  wire signed [N-1:0] B;
output wire signed [2*N-1:0] P;
```

Esto es importante porque una misma secuencia de bits puede interpretarse de maneras distintas según sea `signed` o `unsigned`.

## División binaria

### Cociente y residuo:

La división entera se describe mediante:

\[ D=qd+r \]

donde:

- $D$ es el dividendo;
- $d$ es el divisor;
- $q$ es el cociente;
- $r$ es el residuo.

Para números positivos:

\[ 0\le r<d \]

Por ejemplo:

\[ 25/5=5 \]

con:

\[ r=0 \]

Mientras que:

\[ 26/5=5 \]

con:

\[ r=1 \]

porque:

\[ 26=(5)(5)+1 \]

Por ello, un divisor digital suele producir **dos resultados**:

```
        ┌──────────┐
D ─────►│          │────► q
d ─────►│ DIVISOR  │
        │          │────► r
        └──────────┘
```

## División restauradora

### Idea general:

La **división restauradora** se basa en una secuencia repetitiva de:

```
desplazar
    ↓
restar
    ↓
examinar signo
    ↓
decidir bit del cociente
```

En cada iteración:

1. se desplaza el residuo parcial;
2. se incorpora el siguiente bit del dividendo;
3. se resta tentativamente el divisor;
4. se comprueba si el resultado es negativo.

Si el resultado es negativo, significa que el divisor era demasiado grande para el residuo parcial actual.

Por tanto:

\[ q_i=0 \]

y el residuo anterior debe **restaurarse**.

Si el resultado no es negativo:

\[ q_i=1 \]

y la resta se conserva.

El flujo puede representarse como:

```
Desplazar
    │
    ▼
Restar d
    │
    ▼
 ¿R < 0?
  /    \
sí      no
│        │
▼        ▼
restaurar q_i = 1
q_i = 0
```

De ahí proviene el nombre **restauradora**. multiplicadores_divisores_captu…

## Ejemplo conceptual de división

### División de 25 entre 5:

El procedimiento va incorporando uno por uno los bits del dividendo y construyendo progresivamente el cociente.

El resultado final mostrado es:

\[ q=00101_2=5 \]

y:

\[ r=00000_2=0 \]

Por tanto:

\[ 25=5(5)+0 \]

La idea importante no es únicamente memorizar el ejemplo, sino entender que cada nuevo bit del cociente depende de comparar el residuo parcial con el divisor.

## Datapath de un divisor iterativo

### Ruta de datos:

Un divisor iterativo necesita almacenar y modificar varios valores:

- dividendo $D$;
- divisor $d$;
- residuo $R$;
- cociente $q$.

También requiere:

- comparador;
- restador;
- registros;
- contador.

Conceptualmente:

```
D, d, start
     │
     ▼
Registros D, d, R, q
     │
     ▼
Comparador + restador
     │
     ▼
q, r, done
```

Una FSM controla el flujo:

```
             resultado de comparación
                       │
                       ▼
                  FSM + contador
                       │
                       ▼
                    control
                       │
                       ▼
                 registros
```

Esta separación entre **datapath** y **control** vuelve a aparecer porque la división también reutiliza hardware durante múltiples ciclos.

## División larga, restauradora y no restauradora

### División larga:

Se parece al algoritmo aprendido para división decimal.

La operación consiste esencialmente en:

- comparar;
- decidir;
- restar;
- continuar.

Es conceptualmente clara, aunque poco paralela.

### División restauradora:

Cuando la resta produce un valor negativo, el residuo previo se recupera.

Su principal ventaja es que resulta relativamente sencilla de comprender y controlar.

### División no restauradora:

La versión no restauradora evita recuperar inmediatamente el residuo en cada paso negativo.

Esto puede reducir determinadas operaciones, aunque requiere una lógica de control diferente.

La selección entre métodos depende de:

- latencia permitida;
- recursos disponibles;
- necesidad de cociente;
- necesidad de residuo.

Matemáticamente:

\[ \frac{D}{0} \]

no está definido.

Un circuito digital debe decidir explícitamente qué hacer cuando:

\[ d=0 \]

No conviene simplemente ejecutar el algoritmo y aceptar cualquier valor producido.

```
             división
```

## Dividir mediante el recíproco

### Transformación de la división:

Una división puede escribirse como:

\[ \frac{D}{d}=D\left(\frac{1}{d}\right) \]

Esto permite sustituir el divisor por:

1. un cálculo o aproximación del recíproco;
2. una multiplicación.

Puede ser conveniente cuando la multiplicación es mucho más eficiente que una división general.

### LUT de recíprocos:

Puede almacenarse una aproximación de:

\[ \frac{1}{d} \]

en una LUT.

Esto ofrece rapidez a cambio de memoria.

### Newton-Raphson:

También puede calcularse el recíproco mediante una aproximación iterativa.

Este método requiere varias operaciones, pero puede converger rápidamente.

### Divisor constante:

Si $d$ es constante, muchas optimizaciones pueden realizarse durante la síntesis.

Por ejemplo:

\[ \frac{x}{8}=x>>3 \]

porque:

\[ 8=2^3 \]

En otros casos, la división constante puede transformarse en combinaciones de multiplicaciones, desplazamientos y sumas.

## Punto fijo

### Representación Qm.n:

El punto fijo permite representar fracciones utilizando enteros cuya escala se encuentra implícita.

En un formato con $n$ bits fraccionarios:

\[ x=X_{\text{entero}}2^{-n} \]

Esto significa que el hardware almacena un entero, pero se interpreta como si existiera un punto binario en una posición conocida.

### Multiplicación en punto fijo:

Si dos números tienen $n$ bits fraccionarios:

\[ A=a2^{-n} \]\[ B=b2^{-n} \]

entonces:

\[ AB=(ab)2^{-2n} \]

Por lo tanto, el producto contiene **$2n$ bits fraccionarios**.

Para regresar a la escala original debe desplazarse:

\[ P_{\text{reescalado}}=P>>n \]

En Verilog puede aparecer como:

```
wire signed [2*W-1:0] prod = a * b;
assign y = prod >>> FRAC;
```

El operador `>>>` realiza un desplazamiento aritmético a la derecha, preservando adecuadamente el signo.

### Decisiones adicionales:

Un diseño de punto fijo también debe decidir:

- redondeo;
- truncamiento;
- saturación;
- bits de guarda;
- overflow.

Por ello, definir el formato numérico es parte integral de la arquitectura.

## Punto flotante IEEE 754

### Formato de precisión simple:

IEEE 754 de precisión simple utiliza 32 bits distribuidos en:

```
┌───┬──────────┬─────────────────────────┐
│ S │    E     │            F            │
└───┴──────────┴─────────────────────────┘
 1      8                  23
```

donde:

- $S$ = signo;
- $E$ = exponente;
- $F$ = fracción.

Para números normalizados:

\[ x=(-1)^S(1.F)_2 2^{E-127} \]

El valor 127 es el **bias** del exponente.

---

## Ejemplo IEEE 754

### Representación de $+5.75$:

Primero se convierte a binario:

\[ 5.75_{10}=101.11_2 \]

Se normaliza:

\[ 101.11_2=1.0111_2\times2^2 \]

El signo es positivo:

\[ S=0 \]

El exponente real es:

\[ 2 \]

y el exponente almacenado es:

\[ E=2+127=129 \]

En binario:

\[ 129=10000001_2 \]

La fracción corresponde a los bits posteriores al `1` implícito:

\[ F=0111000\ldots \]

hasta completar 23 bits.

## Operaciones de punto flotante

### Suma y resta:

Una suma o resta en punto flotante requiere varias etapas:

1. alinear los exponentes;
2. ajustar las mantisas;
3. sumar o restar;
4. normalizar;
5. ajustar el exponente;
6. redondear;
7. comprobar casos especiales.

Esta complejidad explica por qué una suma flotante es considerablemente más costosa que una suma entera convencional.

### Multiplicación:

En una multiplicación de punto flotante:

- los signos se combinan mediante XOR;
- los exponentes se suman;
- las mantisas se multiplican.

Conceptualmente:

\[ S_R=S_A\oplus S_B \]\[ E_R=E_A+E_B \]

y:

\[ M_R=M_A M_B \]

Posteriormente debe normalizarse y ajustarse el bias correspondiente.

### División:

En división:

- los signos también utilizan XOR;
- los exponentes se restan;
- las mantisas se dividen.

Conceptualmente:

## Selección de arquitectura

### Resultado inmediato:

Si se requiere una respuesta con poca latencia, puede utilizarse:

- operador `*`;
- multiplicador combinacional;
- bloque DSP.

### Ahorro de recursos:

Cuando el área es limitada, resultan apropiadas arquitecturas iterativas como:

- shift-add;
- división iterativa.

El mismo recurso se reutiliza durante varios ciclos.

### Alto throughput:

Si deben procesarse muchos datos continuamente, puede utilizarse un **pipeline**.

Aunque la primera respuesta tarde varios ciclos, posteriormente pueden obtenerse nuevos resultados con una alta frecuencia.

### Divisor constante:

Si el divisor es conocido durante síntesis pueden considerarse:

- desplazamientos;
- sumas;
- multiplicación por recíproco.

### Precisión controlada:

Para muchas aplicaciones embebidas puede emplearse **punto fijo**, permitiendo elegir explícitamente cuántos bits se dedican a precisión y rango.

### Gran rango dinámico:

Cuando se necesita representar valores extremadamente grandes y pequeños, puede utilizarse:

- punto flotante;
- IP especializada.

La selección de arquitectura siempre representa un compromiso entre:

\[ \text{área} \leftrightarrow \text{latencia} \leftrightarrow \text{throughput} \leftrightarrow \text{precisión} \]

## Registros de desplazamiento

### SIPO:

Un registro **SIPO —Serial-In Parallel-Out—** recibe los bits uno por uno y construye una palabra paralela.

```
din ──► SIPO ──► word
        serie
          ↓
       paralelo
```

Después de recibir $N$ bits, la palabra completa puede entregarse simultáneamente.

### PISO:

Un registro **PISO —Parallel-In Serial-Out—** realiza el proceso inverso.

```
word ──► PISO ──► dout
       paralelo
          ↓
         serie
```

Las señales típicas de estos módulos incluyen:

- `clk`;
- `rst`;
- `enable`;
- `valid`;
- `done`.

Estos registros aplican directamente el concepto de desplazamiento estudiado previamente.

## FSM para recepción SIPO

### Estados:

Un controlador SIPO puede utilizar tres estados:

```
          start
IDLE ─────────────► SHIFT
                    │
                    │ k < N-1
                    └───────┐
                            │
                    k = N-1
                            ▼
                           DONE
                            │
                           ack
                            │
                            ▼
                           IDLE
```

En `SHIFT` se desplaza el registro y aumenta el contador.

Cuando se recibe el último bit, el sistema entra a `DONE`.

En `DONE`, la palabra se considera válida hasta que el receptor confirma su recepción mediante una señal como `ack`.

Esta estructura evita perder información por no coordinar correctamente productor y consumidor.

## FIFO

### Concepto:

Una **FIFO —First-In First-Out—** es una estructura donde el primer dato escrito es el primero que se lee.

Puede imaginarse como una cola:

```
Entrada
  ↓
[1][2][3][4]
           ↓
         Salida
```

La FIFO permite desacoplar dos módulos que trabajan a ritmos diferentes.

Por ejemplo, un productor puede generar temporalmente datos más rápido de lo que el consumidor puede procesarlos. La FIFO almacena esos datos mientras esperan.

### Estructura interna:

Una FIFO puede contener:

- memoria RAM;
- puntero de escritura;
- puntero de lectura;
- señal `full`;
- señal `empty`.

Conceptualmente:

```
din, wr_en
    │
    ▼
┌────────────────────────┐
│          FIFO          │
│                        │
│ RAM                    │
│ puntero escritura      │
│ puntero lectura        │
└────────────────────────┘
    │             │
    ▼             ▼
  dout       full / empty
```

La presentación define precisamente a la FIFO como una cola que desacopla módulos que trabajan a diferentes ritmos. multiplicadores_divisores_captu…

### FIFO síncrona:

Una FIFO síncrona utiliza el mismo reloj para lectura y escritura.

Puede parametrizarse mediante:

```
parameter W = 8;
parameter DEPTH = 16;
```

donde:

- `W` representa el ancho de cada dato;
- `DEPTH` representa la cantidad de elementos almacenables.

El ancho necesario para los punteros puede calcularse mediante:

```
localparam AW = $clog2(DEPTH);
```

Las señales `full` y `empty` permiten evitar escribir cuando la memoria está llena o leer cuando no existe ningún dato disponible.

## Decodificador BCD a 7 segmentos

### BCD:

Un dígito **BCD —Binary-Coded Decimal—** utiliza 4 bits para representar un decimal entre 0 y 9.

Por ejemplo:

```
Decimal    BCD
   0       0000
   1       0001
   2       0010
   ...
   9       1001
```

Las combinaciones:

```
1010 a 1111
```

corresponden a valores de 10 a 15 y no representan dígitos BCD válidos.

Por tanto, el hardware debe definir qué hacer con esos casos.

### Display de 7 segmentos:

Un display utiliza siete segmentos:

```
       a
     ─────
  f │     │ b
    │  g  │
     ─────
  e │     │ c
    │     │
     ─────
       d
```

Cada dígito requiere una combinación diferente de segmentos.

### Cátodo común:

En un display de cátodo común:

\[ 1=\text{segmento encendido} \]

Para mostrar `0` deben activarse:

```
a,b,c,d,e,f
```

y desactivarse:

```
g
```

Por tanto:

```
seg = 7'b1111110;
```

asumiendo el orden:

```
{a,b,c,d,e,f,g}
```

### Ánodo común:

En un display de ánodo común, la lógica se invierte:

\[ 0=\text{segmento encendido} \]

Por ello, antes de escribir el decodificador siempre debe conocerse el tipo de display utilizado.

### Implementación mediante `case`:

Un decodificador puede expresarse con un bloque combinacional:

```
always @(*) begin
    case (bcd)
        4'd0: seg = 7'b1111110;
        4'd1: seg = 7'b0110000;
        4'd2: seg = 7'b1101101;
        4'd3: seg = 7'b1111001;
        4'd4: seg = 7'b0110011;
        4'd5: seg = 7'b1011011;
        4'd6: seg = 7'b1011111;
        4'd7: seg = 7'b1110000;
        4'd8: seg = 7'b1111111;
        4'd9: seg = 7'b1111011;
        default: seg = 7'b0000001;
    endcase
end
```

El caso `default` define explícitamente el comportamiento para entradas BCD inválidas.

# Ideas fundamentales de la clase

La multiplicación binaria puede entenderse como la suma de productos parciales desplazados. Cada bit del multiplicador decide si una copia desplazada del multiplicando debe sumarse. Esta relación permite construir desde multiplicadores combinacionales hasta arquitecturas iterativas shift-add.

La división se fundamenta en comparar, restar, decidir y repetir. En la división restauradora, una resta negativa provoca que el residuo anterior se restaure y que el bit correspondiente del cociente sea cero; una resta válida se conserva y produce un uno en el cociente.

Una operación aritmética no puede diseñarse correctamente sin considerar el ancho de los datos. Una multiplicación de dos operandos de $N$ bits puede requerir $2N$ bits, mientras que suma, división y operaciones con signo requieren analizar explícitamente overflow, residuo y extensión de signo.

Las arquitecturas combinacionales utilizan más recursos para obtener resultados rápidamente, mientras que las arquitecturas iterativas reutilizan recursos durante varios ciclos. Esta relación entre área y latencia constituye una decisión de diseño y no simplemente una consecuencia del código escrito.

Los parámetros de Verilog permiten crear hardware reutilizable para diferentes anchos de palabra. Un parámetro se establece durante la elaboración del circuito y no debe confundirse con una señal que cambia durante la ejecución.

El punto fijo proporciona una forma eficiente de trabajar con fracciones cuando la escala puede determinarse previamente. La multiplicación modifica esa escala, por lo que el producto debe reescalarse mediante desplazamientos. El punto flotante proporciona mayor rango dinámico, pero requiere manejar mantisa, exponente, normalización, redondeo y casos especiales.

Las operaciones iterativas necesitan un protocolo de control. Señales como `start`, `done`, `valid`, `full` y `empty` permiten coordinar módulos que no producen o consumen información instantáneamente.

Finalmente, registros de desplazamiento, FIFO, decodificadores, multiplicadores y divisores pueden verse bajo la misma perspectiva: todos están formados por recursos elementales de hardware conectados mediante una arquitectura específica. Comprender qué ocurre con cada bit, en cada registro y en cada ciclo permite pasar de una expresión matemática o un fragmento de Verilog a una comprensión real del circuito que será sintetizado.
