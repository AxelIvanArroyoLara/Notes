## Introducción

En Verilog, un ciclo `for` no debe interpretarse automáticamente como un ciclo de programación tradicional. En software, un `for` suele significar que una misma instrucción se ejecuta repetidamente a lo largo del tiempo; en cambio, en una descripción de hardware el sintetizador puede **expandir el ciclo y crear estructuras físicas repetidas**.

Esta diferencia es fundamental para comprender cómo se sintetizan diseños en FPGA o ASIC. Un ciclo `for` con cuatro iteraciones no significa necesariamente que el circuito tardará cuatro ciclos de reloj. Puede significar que se crearán cuatro grupos de compuertas trabajando en paralelo dentro de una misma red combinacional. El material parte justamente de esta distinción entre repetición de software y replicación de hardware, y después la aplica al diseño de multiplicadores de 5 bits. Ciclos_FOR_Multiplicadores_Veri…

El tema también conecta varios conceptos importantes de diseño digital:

- ciclos `for` procedurales;
- `for generate`;
- síntesis combinacional y secuencial;
- restricciones de portabilidad hacia ASIC;
- multiplicación mediante LUT o ROM;
- multiplicación mediante corrimientos y productos parciales;
- tratamiento de números con signo;
- verificación exhaustiva.

La idea central es que **Verilog describe hardware**, no una secuencia de instrucciones ejecutadas por un procesador.

## Significado del ciclo `for` en hardware

### Diferencia con un ciclo de software:

En software, un ciclo como:

```
for (i = 0; i < 4; i++) {
    operacion();
}
```

normalmente significa:

```
Tiempo
  ↓

operación 0
   ↓
operación 1
   ↓
operación 2
   ↓
operación 3
```

Existe una reutilización temporal de los mismos recursos del procesador.

En Verilog sintetizable, un `for` puede interpretarse de manera completamente distinta.

Supóngase que se describe:

```
for (i = 0; i < 4; i = i + 1) begin
    // operación combinacional
end
```

El sintetizador puede **desenrollar** el ciclo y construir hardware equivalente para las cuatro iteraciones:

```
for de 4 iteraciones
        │
        ▼
┌─────────────┐
│ Hardware 0  │
└──────┬──────┘
       │
┌──────▼──────┐
│ Hardware 1  │
└──────┬──────┘
       │
┌──────▼──────┐
│ Hardware 2  │
└──────┬──────┘
       │
┌──────▼──────┐
│ Hardware 3  │
└─────────────┘
```

Esto no implica cuatro flancos de reloj.

La cantidad de ciclos de reloj depende de cómo esté descrita la arquitectura, no del hecho de que aparezca un `for`.

## Estructura básica del `for` procedural

### Sintaxis:

Un `for` procedural puede aparecer dentro de bloques como `always`.

Por ejemplo:

```
integer i;

always @(*) begin
    for (i = 0; i < N; i = i + 1) begin
        // operación combinacional
    end
end
```

La variable `i` se utiliza durante la elaboración o síntesis para identificar cada iteración de la descripción.

Para que el sintetizador pueda expandir correctamente el ciclo, el número de iteraciones debe poder determinarse estáticamente.

Esto significa que, en términos generales:

- el valor inicial debe ser conocido;
- el límite debe ser constante o depender de un parámetro conocido;
- el incremento debe permitir conocer cuándo termina el ciclo;
- la cantidad total de iteraciones debe ser finita.

La razón es sencilla: el sintetizador necesita saber **cuánto hardware debe construir**.

## Un `for` no ahorra hardware automáticamente

### Desenrollado del ciclo:

Un error común consiste en pensar que escribir un ciclo hace que el hardware reutilice un único recurso.

Esto no ocurre automáticamente.

Si cada iteración representa una operación diferente sobre diferentes bits o señales, el sintetizador puede generar una copia física de esa lógica para cada iteración.

Así:

```
for (i = 0; i < 8; i = i + 1)
    y[i] = ~x[i];
```

puede transformarse conceptualmente en:

```
x[0] ─► NOT ─► y[0]
x[1] ─► NOT ─► y[1]
x[2] ─► NOT ─► y[2]
...
x[7] ─► NOT ─► y[7]
```

Es decir, ocho inversores físicos.

El `for` facilita la descripción y evita escribir ocho líneas casi idénticas, pero **no significa que exista un único inversor reutilizado ocho veces**.

## Ejemplo de paridad

### Cálculo mediante XOR:

La paridad de un vector puede obtenerse aplicando XOR entre todos sus bits.

Una implementación con ciclo es:

```
module paridad_for (
    input wire [7:0] x,
    output reg paridad
);

integer i;

always @(*) begin
    paridad = 1'b0;

    for (i = 0; i < 8; i = i + 1)
        paridad = paridad ^ x[i];
end

endmodule
```

Conceptualmente se realiza:

\[ P=x_0\oplus x_1\oplus x_2\oplus \cdots \oplus x_7 \]

El sintetizador puede generar una red de compuertas XOR.

```
x[0] ──┐
       XOR ──┐
x[1] ──┘     │
             XOR ──┐
x[2] ────────┘     │
                   XOR ── ... ─► paridad
```

El material muestra justamente que el ciclo se expande en una red combinacional; la comodidad del `for` está en la descripción, no en una reducción automática del número de compuertas. Ciclos_FOR_Multiplicadores_Veri…

### Operador de reducción:

La misma intención puede expresarse mediante:

```
assign paridad = ^x;
```

El operador `^` aplicado a todo el vector realiza una reducción XOR.

Por tanto:

```
^x
```

equivale funcionalmente a:

```
x[0] ^ x[1] ^ x[2] ^ ... ^ x[7]
```

El objetivo en ambos casos es describir la misma función lógica.

## Asignaciones completas en lógica combinacional

### Problema de los latches:

Dentro de un bloque combinacional, todas las salidas deben recibir un valor para **todos los caminos posibles de ejecución**.

Por ejemplo:

```
always @(*) begin
    for (i = 0; i < 8; i = i + 1)
        if (habilitar)
            y[i] = x[i];
end
```

presenta un problema.

Cuando:

```
habilitar = 1
```

cada `y[i]` recibe `x[i]`.

Pero cuando:

```
habilitar = 0
```

no existe ninguna asignación.

Entonces la descripción implica que `y[i]` debe conservar su valor anterior.

Conservar un valor anterior requiere memoria.

Por ello, el sintetizador puede inferir un **latch**.

### Forma completa:

Una descripción combinacional adecuada sería:

```
always @(*) begin
    for (i = 0; i < 8; i = i + 1)
        if (habilitar)
            y[i] = x[i];
        else
            y[i] = 1'b0;
end
```

Ahora cada salida recibe un valor tanto si `habilitar` vale `1` como si vale `0`.

Conceptualmente:

```
habilitar = 1 → y[i] = x[i]

habilitar = 0 → y[i] = 0
```

No es necesario conservar un estado previo y, por tanto, la lógica puede permanecer puramente combinacional.

## `for` en circuitos secuenciales

### Uso dentro de `always @(posedge clk)`:

Un ciclo también puede aparecer dentro de un bloque secuencial.

Por ejemplo:

```
always @(posedge clk) begin
    if (reset)
        q <= 8'b0;
    else
        for (i = 0; i < 8; i = i + 1)
            q[i] <= d[i];
end
```

Es importante no interpretar esto como:

```
ciclo 1 → copiar d[0]
ciclo 2 → copiar d[1]
ciclo 3 → copiar d[2]
...
```

No ocurre así.

Todas las asignaciones se producen asociadas al mismo flanco de reloj.

El resultado corresponde aproximadamente a ocho flip-flops:

```
d[0] ─► FF ─► q[0]
d[1] ─► FF ─► q[1]
d[2] ─► FF ─► q[2]
...
d[7] ─► FF ─► q[7]
          ▲
          │
         clk
```

El `for` describe repetidamente la estructura de los ocho registros.

## Asignaciones bloqueantes y no bloqueantes

### Asignación bloqueante `=`:

La recomendación presentada para lógica combinacional es utilizar asignaciones bloqueantes:

```
=
```

Por ejemplo:

```
always @(*) begin
    y = a & b;
end
```

### Asignación no bloqueante `<=`:

Para lógica secuencial se recomienda utilizar:

```
<=
```

Por ejemplo:

```
always @(posedge clk) begin
    q <= d;
end
```

Esto ayuda a representar correctamente el comportamiento simultáneo de registros activados por un mismo reloj.

Una regla práctica es:

```
Combinacional → =

Secuencial    → <=
```

La recomendación forma parte de las reglas de síntesis destacadas en el material, junto con la necesidad de asignar todas las salidas y mantener separados los bloques combinacionales y secuenciales. Ciclos_FOR_Multiplicadores_Veri…

## `for generate`

### Concepto:

Un `for generate` no ejecuta sentencias procedurales.

Su función es **replicar estructuras del diseño durante la elaboración**.

Por ejemplo:

```
genvar k;

generate
    for (k = 0; k < 8; k = k + 1) begin : GEN_INV
        not U_INV (y[k], a[k]);
    end
endgenerate
```

Esto crea ocho instancias de una compuerta `not`.

Conceptualmente:

```
k = 0 → instancia NOT 0
k = 1 → instancia NOT 1
k = 2 → instancia NOT 2
...
k = 7 → instancia NOT 7
```

### `genvar`:

En este tipo de ciclo se utiliza:

```
genvar
```

en lugar de una variable procedural `integer`.

`genvar` existe para controlar la generación estructural del diseño.

---

## `for` procedural frente a `for generate`

### Diferencia principal:

Ambas construcciones producen repetición en la descripción, pero trabajan en contextos distintos.

|Característica|`for` procedural|`for generate`|
|---|---|---|
|Ubicación|Dentro de `always`, tareas o funciones|Fuera de bloques procedurales|
|Variable típica|`integer`|`genvar`|
|Uso|Repetir operaciones sobre señales|Replicar instancias o conexiones|
|Momento|Síntesis|Elaboración|
|Resultado|Lógica combinacional o secuencial|Estructura jerárquica repetida|

Puede pensarse así:

```
for procedural
      ↓
"repetir esta operación sobre varias señales"

for generate
      ↓
"crear varias copias de esta estructura"
```

La distinción entre ambos tipos es una de las ideas centrales del contenido. Ciclos_FOR_Multiplicadores_Veri…

## Recomendaciones para ciclos sintetizables

### Límites estáticos:

Los límites deben ser constantes o depender de parámetros conocidos durante la síntesis.

Por ejemplo:

```
parameter N = 8;

for (i = 0; i < N; i = i + 1)
```

es adecuado porque `N` queda determinado durante la elaboración del diseño.

En cambio, un ciclo cuyo número de iteraciones dependa de un dato que solo se conocerá mientras el circuito está funcionando puede resultar problemático para una expansión puramente combinacional.

### Cantidad finita de iteraciones:

El sintetizador debe poder establecer cuántas copias de lógica requiere.

Por eso una condición sin límite estático puede impedir la síntesis o producir resultados no portables.

### Profundidad lógica:

Incluso cuando el ciclo es sintetizable, debe analizarse el hardware generado.

Por ejemplo, si cada iteración depende de la anterior:

```
etapa 0 → etapa 1 → etapa 2 → ... → etapa N
```

la profundidad combinacional puede crecer considerablemente.

Esto incrementa el retardo de propagación.

Por tanto:

```
más iteraciones
      ↓
posible mayor cantidad de lógica
      ↓
posible ruta crítica más larga
      ↓
menor frecuencia máxima
```

## Construcciones problemáticas para ASIC

### Retardos `#`:

Una construcción como:

```
#10;
```

representa tiempo de simulación.

No describe directamente un elemento físico de retardo portable para síntesis ASIC.

Por ello se utiliza principalmente en bancos de pruebas.

### `initial`:

Un bloque:

```
initial begin
    ...
end
```

puede utilizarse en simulación y algunas herramientas FPGA permiten aprovecharlo para inicializar memorias.

Sin embargo, el material advierte que no constituye una forma portable de inicialización física para ASIC.

### `forever`:

Un ciclo:

```
forever begin
    ...
end
```

no posee por sí mismo un límite estático de expansión.

Por ello puede no representar una estructura sintetizable adecuada.

### `while` dependiente de datos:

Si el número de iteraciones depende del valor de una señal:

```
while (x != 0)
```

el sintetizador podría no saber cuántas iteraciones debe crear.

### `repeat(variable)`:

Una repetición cuyo límite cambia dinámicamente presenta el mismo problema: la cantidad de hardware necesaria puede ser desconocida durante síntesis.

### $display y $monitor:

Construcciones como:

```
$display(...)
$monitor(...)
```

son de simulación.

No representan hardware físico que deba sintetizarse.

### Acceso a archivos:

El acceso a archivos se utiliza normalmente en bancos de pruebas o flujos específicos, no como una descripción portable de lógica ASIC convencional.

El material resume estas limitaciones señalando que retardos, `initial`, ciclos sin límites estáticos, llamadas de impresión y acceso a archivos deben distinguirse cuidadosamente de las construcciones sintetizables. Ciclos_FOR_Multiplicadores_Veri…

## Diferencias prácticas entre FPGA y ASIC

### FPGA:

Una FPGA posee recursos ya fabricados, como:

- LUT físicas;
- bloques RAM;
- DSP;
- flip-flops;
- interconexiones programables.

Por ello, ciertas descripciones pueden mapearse directamente a recursos existentes.

### ASIC:

En un ASIC, el sintetizador utiliza una **biblioteca de celdas estándar** o macros disponibles en una tecnología específica.

Por ejemplo, una LUT conceptual descrita mediante Verilog no implica necesariamente que exista una LUT física idéntica en el ASIC.

Una tabla escrita mediante `case` puede terminar convertida en:

- compuertas;
- decodificadores;
- multiplexores.

Una ROM física solo puede utilizarse si existe una macro correspondiente dentro de la tecnología.

Por ello:

```
Verilog
   ↓
describe función lógica

Biblioteca tecnológica
+
restricciones
   ↓
determinan implementación física
```

Esta separación es fundamental: el mismo RTL puede producir estructuras físicas diferentes dependiendo de la tecnología objetivo.

## Multiplicación con signo de 5 bits

### Rango de los operandos:

Para números con signo de 5 bits en complemento a dos:

\[ -2^{4}\le x\le2^{4}-1 \]

por tanto:

\[ -16\le A,B\le15 \]

### Casos extremos:

Uno de los productos más grandes es:

\[ (-16)(-16)=256 \]

También aparece:

\[ (-16)(15)=-240 \]

Esto permite analizar cuántos bits se necesitan para almacenar el producto.

### Ancho del resultado:

Una salida signed de 9 bits posee el rango:

\[ -256\le x\le255 \]

Por tanto, aunque puede representar $-256$, **no puede representar $+256$**.

Debido a que:

\[ (-16)(-16)=+256 \]

se necesitan 10 bits.

Con 10 bits signed:

\[ -512\le P\le511 \]

por lo que todos los productos posibles de dos entradas signed de 5 bits quedan representados.

Así:

```
A → 5 bits signed
B → 5 bits signed
P → 10 bits signed
```

El material enfatiza precisamente este caso porque una salida de 9 bits parecería suficiente a primera vista, pero falla para el producto positivo $256$. Ciclos_FOR_Multiplicadores_Veri…

## Multiplicador mediante LUT o ROM

### Idea general:

En lugar de calcular físicamente:

\[ P=A\times B \]

pueden almacenarse previamente **todos los productos posibles**.

Como cada entrada tiene 5 bits, existen:

\[ 2^5=32 \]

patrones posibles para $A$ y otros:

\[ 2^5=32 \]

para $B$.

Por tanto:

\[ 32\times32=1024 \]

combinaciones.

### Construcción de la dirección:

Los dos operandos se concatenan:

\[ \text{dirección}=\{A[4:0],B[4:0]\} \]

La dirección tiene:

\[ 5+5=10 \]

bits.

Por tanto existen:

\[ 2^{10}=1024 \]

direcciones.

Cada dirección contiene un producto de 10 bits.

El almacenamiento total es:

\[ 1024\times10=10240 \]

bits.

La arquitectura puede representarse como:

```
A[4:0] ─┐
        ├──► {A,B} ─► dirección de 10 bits ─► ROM ─► P[9:0]
B[4:0] ─┘                                 1024 × 10
```

## Concatenación en Verilog

### Uso de `{ }`:

Las llaves permiten concatenar campos.

Por ejemplo:

```
{a, b}
```

une ambos vectores.

Si cada uno tiene 5 bits:

```
a = a4 a3 a2 a1 a0
b = b4 b3 b2 b1 b0
```

entonces:

```
{a,b}
=
a4 a3 a2 a1 a0 b4 b3 b2 b1 b0
```

Es decir, una palabra de 10 bits.

### Ejemplo con signo:

Para:

\[ A=-1 \]

en 5 bits:

```
11111
```

y:

\[ B=2 \]

representado como:

```
00010
```

la dirección es:

```
1111100010
```

La concatenación conserva los patrones de complemento a dos de los operandos.

## Declaración del multiplicador LUT

### Puertos:

El módulo utiliza:

```
module multiplicador_lut_5bits (
    input wire signed [4:0] a,
    input wire signed [4:0] b,
    output wire signed [9:0] resultado
);
```

Cada elemento tiene un significado específico.

`input` indica un puerto de entrada.

`output` indica un puerto de salida.

`wire` describe una señal conducida continuamente y que no almacena estado.

`signed` indica que el vector debe interpretarse en complemento a dos.

`[4:0]` indica un bus de 5 bits.

`[9:0]` indica un bus de 10 bits.

### Declaración de la tabla:

Puede utilizarse:

```
reg signed [9:0] lut [0:1023];
```

Esto representa una memoria con:

- 1024 posiciones;
- 10 bits por posición.

Conceptualmente:

```
lut[0]     → 10 bits
lut[1]     → 10 bits
...
lut[1023]  → 10 bits
```

## Inicialización de la LUT

### Recorrido de combinaciones:

Para llenar todos los productos pueden utilizarse dos ciclos anidados:

```
for (i = 0; i < 32; i = i + 1) begin
    for (j = 0; j < 32; j = j + 1) begin
        ...
    end
end
```

Esto recorre:

\[ 32\times32=1024 \]

combinaciones.

### Interpretación de los valores signed:

Para un patrón de 5 bits, los valores:

```
00000 ... 01111
```

corresponden a:

\[ 0\text{ a }15 \]

Mientras que:

```
10000 ... 11111
```

corresponden a:

\[ -16\text{ a }-1 \]

Una forma de traducir un índice $i$ mayor o igual que 16 es:

\[ \text{valor}=i-32 \]

Por ejemplo:

\[ 31-32=-1 \]

Por eso aparece lógica del tipo:

```
if (i >= 16)
    valor_a = i - 32;
else
    valor_a = i;
```

## Formación de la dirección mediante desplazamientos

### Expresión:

Puede calcularse la dirección como:

```
(i << 5) | j
```

La operación:

```
i << 5
```

desplaza los 5 bits de $i$ hacia la parte alta.

Después:

```
| j
```

coloca los bits de $j$ en la parte baja.

Es equivalente conceptualmente a:

```
{i, j}
```

cuando los anchos son los adecuados.

## Portabilidad de la LUT

### En FPGA:

Algunas herramientas permiten inicializar una ROM mediante:

- bloques `initial`;
- archivos `.hex`;
- archivos `.mif`;
- atributos específicos del fabricante.

La herramienta puede utilizar memoria interna de la FPGA.

### En ASIC:

La misma técnica con `initial` no constituye una solución generalmente portable.

Las alternativas presentadas son:

- tabla `case` completa;
- lógica combinacional inferida;
- macro ROM disponible en la tecnología.

Esta diferencia es importante porque una descripción válida para una herramienta FPGA no necesariamente representa una implementación adecuada para ASIC.

## LUT combinacional mediante `case`

### Funcionamiento:

En lugar de una memoria inicializada, puede escribirse explícitamente:

```
always @(*) begin
    case ({a, b})
        ...
    endcase
end
```

Cada dirección posee un producto asociado.

Por ejemplo:

```
10'b00000_00000: resultado = 10'sd0;
```

representa:

\[ 0\times0=0 \]

Y:

```
10'b10000_10000: resultado = 10'sd256;
```

representa:

\[ (-16)(-16)=256 \]

### Problema de escala:

Para cubrir todo el espacio deben existir:

\[ 1024 \]

combinaciones.

Esto genera una descripción muy grande.

Además, una tabla completa puede sintetizarse como:

- decodificación;
- multiplexores;
- lógica combinacional.

Por ello, una macro ROM puede resultar más eficiente cuando existe en la tecnología.

## Crecimiento de una LUT

### Generalización para $N$ bits:

Si ambos operandos tienen $N$ bits, la dirección necesita:

\[ 2N \]

bits.

Por tanto, el número de posiciones es:

\[ 2^{2N} \]

Si cada producto utiliza aproximadamente:

\[ 2N \]

bits, entonces el almacenamiento necesario es:

\[ M(N)=2^{2N}(2N) \]

bits.

### Caso de 5 bits:

Para:

\[ N=5 \]

se obtiene:

\[ M(5)=2^{10}(10) \]\[ M(5)=10240\text{ bits} \]

### Crecimiento exponencial:

El problema aparece al aumentar $N$.

La cantidad:

\[ 2^{2N} \]

crece exponencialmente.

Por ello, la LUT puede resultar razonable para operandos muy pequeños, pero poco escalable para anchos mayores.

El material compara precisamente este crecimiento exponencial con el crecimiento aproximado $N^2$ del hardware basado en productos parciales. Ciclos_FOR_Multiplicadores_Veri…

## Multiplicación mediante productos parciales

### Multiplicación sin signo:

Para un multiplicador de 5 bits:

\[ B=b_4b_3b_2b_1b_0 \]

el producto puede escribirse como:

\[ P=b_0A+b_1(A<<1)+b_2(A<<2)+b_3(A<<3)+b_4(A<<4) \]

Cada bit de $B$ decide si un producto parcial participa.

Si:

\[ b_i=0 \]

el término correspondiente es cero.

Si:

\[ b_i=1 \]

se agrega:

\[ A<<i \]

Así, la multiplicación se descompone en:

```
productos parciales
      +
corrimientos
      +
sumas
```

## Tratamiento del signo

### Separación entre signo y magnitud:

El enfoque mostrado utiliza primero las magnitudes de ambos operandos.

El proceso general es:

```
A y B signed
    │
    ▼
obtener magnitud de A
obtener magnitud de B
    │
    ▼
multiplicar magnitudes
    │
    ▼
aplicar signo final
```

El signo del producto se obtiene mediante XOR:

\[ S_P=A[4]\oplus B[4] \]

La tabla correspondiente es:

|$A[4]$|$B[4]$|XOR|Producto|
|---|---|---|---|
|0|0|0|positivo|
|0|1|1|negativo|
|1|0|1|negativo|
|1|1|0|positivo|

La razón es que el resultado es negativo únicamente cuando los signos son diferentes. Ciclos_FOR_Multiplicadores_Veri…

---

## Conversión a magnitud

### Números positivos:

Si:

```
a[4] = 0
```

el número es no negativo y puede utilizarse directamente como magnitud.

### Números negativos:

Si:

```
a[4] = 1
```

se obtiene la magnitud mediante complemento a dos:

\[ |A|=\overline{A}+1 \]

En Verilog:

```
assign magnitud_a =
    a[4] ? (~a + 5'b00001) : a;
```

El operador ternario:

```
condicion ? valor_1 : valor_0
```

selecciona entre dos valores.

En lógica combinacional, normalmente se sintetiza como un multiplexor 2:1.

```
                 ┌──────── valor si 0
condición ─► MUX ┤
                 └──────── valor si 1
                     │
                     ▼
                   salida
```

---

## Caso especial de $-16$

### Patrón de 5 bits:

En complemento a dos de 5 bits:

\[ -16=10000_2 \]

Su magnitud es:

\[ 16=10000_2 \]

observada ahora como valor **sin signo**.

Esto es importante porque $+16$ no cabe como entero signed de 5 bits, cuyo máximo es $+15$, pero sí cabe como magnitud unsigned de 5 bits.

Por ello, durante la fase intermedia de cálculo de magnitudes se utilizan vectores sin signo.

## Operador `~`

### NOT bit a bit:

La tilde:

```
~
```

invierte individualmente todos los bits.

Por ejemplo:

```
a  = 11101
~a = 00010
```

Si:

\[ a=-3 \]

entonces:

\[ \overline{a}+1=00010+1=00011 \]

que representa la magnitud:

\[ 3 \]

### Diferencia entre `~` y `!`:

`~` es un NOT bit a bit.

Por ejemplo:

```
~1010 = 0101
```

`!` es un NOT lógico.

Produce un único valor booleano.

Por ejemplo:

```
!0000 = 1

!0010 = 0
```

### Negación aritmética:

El operador:

```
-a
```

representa negación aritmética.

La identidad utilizada en complemento a dos es:

\[ -x=\overline{x}+1 \]

siempre considerando cuidadosamente el ancho del dato.

El material advierte precisamente que el ancho debe mantenerse controlado para evitar truncamientos o extensiones inesperadas. Ciclos_FOR_Multiplicadores_Veri…

## Extensión antes de desplazar

### Problema del ancho:

Supóngase que `magnitud_a` posee 5 bits.

Si debe desplazarse hasta cuatro posiciones:

```
magnitud_a << 4
```

el producto parcial puede necesitar hasta 9 bits.

Por ello conviene extender primero la señal.

La descripción mostrada utiliza:

```
wire [9:0] a_extendida;

assign a_extendida = {5'b00000, magnitud_a};
```

Así:

```
magnitud_a
10101
```

se convierte en:

```
0000010101
```

### Razón de la extensión:

Si el ancho se mantiene demasiado pequeño durante un desplazamiento, los bits más significativos pueden perderse.

Por tanto:

```
extender
   ↓
desplazar
   ↓
sumar
```

es más seguro que desplazar primero un vector estrecho.

---

## Productos parciales mediante operador ternario

### Primer término:

```
magnitud_b[0] ? a_extendida : 10'b0
```

significa:

```
si b[0] = 1 → usar A
si b[0] = 0 → usar 0
```

### Segundo término:

```
magnitud_b[1] ? (a_extendida << 1) : 10'b0
```

significa:

```
si b[1] = 1 → usar A × 2
si b[1] = 0 → usar 0
```

### Término general:

\[ PP_i= \begin{cases} A<<i,& b_i=1\\ 0,& b_i=0 \end{cases} \]

Para 5 bits:

\[ P=PP_0+PP_1+PP_2+PP_3+PP_4 \]

## Hardware generado por productos parciales

### Corrimientos:

Los corrimientos constantes pueden representarse principalmente mediante conexiones de bits.

Por ejemplo:

```
A = abcde
```

entonces:

```
A << 2
```

puede verse conceptualmente como:

```
abcde00
```

si existe ancho suficiente.

No necesariamente se necesita un bloque físico complejo denominado “shifter” para un desplazamiento constante.

### Selección de productos parciales:

Cada expresión:

```
b[i] ? valor : 0
```

puede sintetizarse como lógica de selección.

Conceptualmente puede entenderse como una habilitación equivalente a un banco de compuertas AND.

### Sumadores:

Después deben sumarse los productos parciales.

Esto produce una red de sumadores.

La arquitectura general es:

```
Operandos A y B
       │
       ▼
Conversión a magnitud
       │
       ▼
Productos parciales
+ corrimientos
       │
       ▼
Red de sumadores
       │
       ▼
Aplicación del signo
       │
       ▼
Resultado
```

El resultado se obtiene combinacionalmente, sin requerir ciclos de reloj en esta arquitectura. Ciclos_FOR_Multiplicadores_Veri…

---

## Aplicación del signo final

### Producto positivo:

Si:

\[ S_P=0 \]

se utiliza directamente:

\[ P=P_{\text{magnitud}} \]

### Producto negativo:

Si:

\[ S_P=1 \]

se obtiene el complemento a dos del producto:

\[ P=\overline{P_{\text{magnitud}}}+1 \]

En Verilog:

```
assign resultado =
    signo_resultado
        ? (~producto_magnitud + 10'b1)
        : producto_magnitud;
```

El mismo patrón de conversión utilizado para obtener la magnitud de las entradas se utiliza ahora en sentido inverso para producir una salida negativa.

---

## Código conceptual completo del multiplicador por corrimientos

### Flujo:

El diseño puede interpretarse en cuatro partes.

Primero se determina el signo:

```
assign signo_resultado = a[4] ^ b[4];
```

Después se obtienen magnitudes:

```
assign magnitud_a = a[4] ? (~a + 5'b1) : a;
assign magnitud_b = b[4] ? (~b + 5'b1) : b;
```

Después se extiende $A$:

```
assign a_extendida = {5'b0, magnitud_a};
```

Posteriormente se suman productos parciales:

```
assign producto_magnitud =
      (magnitud_b[0] ? a_extendida        : 10'b0)
    + (magnitud_b[1] ? a_extendida << 1   : 10'b0)
    + (magnitud_b[2] ? a_extendida << 2   : 10'b0)
    + (magnitud_b[3] ? a_extendida << 3   : 10'b0)
    + (magnitud_b[4] ? a_extendida << 4   : 10'b0);
```

Finalmente se aplica el signo:

```
assign resultado =
    signo_resultado
        ? (~producto_magnitud + 10'b1)
        : producto_magnitud;
```

El diseño completo es combinacional.

## Cómo leer una declaración en Verilog

### `module` y `endmodule`:

Definen los límites del módulo.

```
module nombre (...);

...

endmodule
```

Puede interpretarse como una unidad de hardware con entradas y salidas.

### `input` y `output`:

Indican la dirección de los puertos respecto al módulo.

```
input wire [4:0] a;
output wire [9:0] resultado;
```

### `wire`:

Representa una conexión continuamente conducida.

No implica por sí sola almacenamiento.

### `signed`:

Determina que el patrón de bits se interprete como número con signo.

Por ejemplo:

```
11111
```

como `unsigned` representa:

\[ 31 \]

pero como `signed` de 5 bits representa:

\[ -1 \]

### Índices:

En:

```
[4:0]
```

el índice 4 corresponde al bit más significativo.

El índice 0 corresponde al bit menos significativo.

Por tanto:

```
a[4]
```

selecciona el bit de signo.

Y:

```
a[3:0]
```

selecciona los cuatro bits inferiores.

## Literales binarios

### Forma general:

Una constante como:

```
5'b00001
```

se interpreta así:

```
5    → ancho
'b   → base binaria
00001→ patrón
```

De forma general:

```
<ancho>'<base><valor>
```

Por ejemplo:

```
10'b0000000000
```

representa diez bits en cero.

### Literales signed:

También pueden aparecer literales como:

```
10'sd256
```

donde:

```
10 → ancho
s  → signed
d  → decimal
256→ valor
```

## Operador XOR

### Uso para determinar el signo:

En Verilog:

```
^
```

representa XOR binario cuando aparece entre dos operandos de un bit.

Así:

```
a[4] ^ b[4]
```

produce `1` si los signos son diferentes.

En términos algebraicos:

\[ S_P=S_A\oplus S_B \]

Esta propiedad reproduce exactamente la regla matemática:

```
+ × + = +
+ × - = -
- × + = -
- × - = +
```

---

## Corrimiento `<<`

### Significado:

La expresión:

```
x << 2
```

desplaza los bits dos posiciones hacia la izquierda.

Si el ancho permite conservar el resultado, equivale a:

\[ x2^2 \]

Por ejemplo:

\[ 3=00011_2 \]

entonces:

\[ 3<<2=01100_2=12 \]

porque:

\[ 3\cdot4=12 \]

En el multiplicador, estos corrimientos generan los diferentes productos parciales.

---

## `assign`

### Asignación continua:

La instrucción:

```
assign y = expresion;
```

describe una relación combinacional continua.

Puede interpretarse como:

```
cada vez que cambien las entradas de la expresión,
la salida se actualiza según esa lógica
```

No existe un reloj asociado.

Por ejemplo:

```
assign signo_resultado = a[4] ^ b[4];
```

describe físicamente una lógica XOR entre los bits de signo.

## `signedness` y mezcla de tipos

### Riesgo:

Mezclar operandos `signed` y `unsigned` puede producir resultados inesperados.

Por ejemplo:

```
wire signed [4:0] a;

```

no posee necesariamente la misma semántica que declarar ambos como `signed`.

Por ello debe controlarse explícitamente:

- ancho;
- extensión;
- interpretación con signo.

En el multiplicador descrito, las magnitudes se manipulan como cantidades sin signo y el signo se maneja por separado.

## Comparación: LUT frente a productos parciales

### Principio de operación:

La LUT funciona mediante **consulta**.

```
A,B
 ↓
dirección
 ↓
buscar producto almacenado
 ↓
P
```

La arquitectura por corrimientos funciona mediante **cálculo**.

```
A,B
 ↓
productos parciales
 ↓
sumas
 ↓
P
```

### Comparación:

|Característica|LUT / ROM|Corrimientos y sumas|
|---|---|---|
|Principio|Consulta de resultados|Generación de productos parciales|
|Memoria|10240 bits para 5 bits|No requiere tabla completa|
|Hardware|ROM o red de multiplexores|Compuertas, mux y sumadores|
|Portabilidad ASIC|Depende de ROM o tabla completa|Alta|
|Retardo|Decodificación y lectura|Propagación por sumadores|
|Escalabilidad|Exponencial|Aproximadamente $N^2$|

La tabla resulta especialmente importante porque muestra que no existe una implementación universalmente superior: cada arquitectura intercambia memoria, lógica, retardo y portabilidad. Ciclos_FOR_Multiplicadores_Veri…

## Escalabilidad

### LUT:

La LUT requiere:

\[ 2^{2N} \]

entradas.

Por tanto su costo de memoria crece exponencialmente.

### Productos parciales:

Un multiplicador convencional genera aproximadamente una matriz de productos parciales relacionada con:

\[ N\times N \]

operaciones elementales.

Por eso el crecimiento puede aproximarse a:

\[ N^2 \]

Esto sigue siendo un aumento importante, pero mucho más manejable que:

\[ 2^{2N} \]

para anchos grandes.

---

## Banco de pruebas exhaustivo

### Objetivo:

Como los operandos signed de 5 bits poseen:

\[ 32 \]

valores posibles cada uno, existen:

\[ 32\times32=1024 \]

combinaciones.

Por ello puede verificarse **todo el espacio de entrada**.

Un testbench puede utilizar:

```
for (i = -16; i <= 15; i = i + 1)
    for (j = -16; j <= 15; j = j + 1)
```

Después se asigna:

```
a = i;
b = j;
```

y se compara la salida con:

```
i * j
```

### Detección de errores:

Conceptualmente:

```
if (resultado !== i * j)
    errores = errores + 1;
```

Así se verifica cada una de las 1024 combinaciones posibles.

### Uso de `#1`:

En un testbench puede aparecer:

```
#1;
```

para permitir que la lógica combinacional se estabilice antes de comprobar el resultado.

Este retardo pertenece a simulación y no al hardware sintetizado.

## Testbench frente a hardware sintetizable

### Testbench:

Puede utilizar construcciones como:

- `initial`;
- `#`;
- $display;
- $finish;
- ciclos utilizados para generar estímulos.

El testbench **no se sintetiza como parte del circuito final**.

### RTL sintetizable:

Describe la lógica que efectivamente se implementará.

Por tanto, el mismo lenguaje Verilog puede utilizarse en dos contextos diferentes:

```
Verilog
 ├── RTL sintetizable
 │     ↓
 │   hardware
 │
 └── testbench
       ↓
    simulación
```

Es importante distinguir ambos para no interpretar incorrectamente construcciones como `initial` o `#1`.

## Decisión de arquitectura

### No existe una única implementación correcta:

Dos arquitecturas pueden producir exactamente el mismo resultado matemático y, sin embargo, tener características físicas completamente distintas.

Para el multiplicador estudiado pueden considerarse al menos:

```
                 multiplicación
                      │
          ┌───────────┴───────────┐
          │                       │
          ▼                       ▼
       LUT / ROM          corrimientos + sumas
          │                       │
          ▼                       ▼
    usa memoria           usa lógica aritmética
```

La elección depende de:

- área disponible;
- frecuencia deseada;
- potencia;
- recursos tecnológicos;
- portabilidad;
- escalabilidad.

Por ello, una implementación debe juzgarse no solo por “funciona” sino también por **qué circuito genera**.

## Relación entre ciclo `for` y multiplicadores

### Función del `for` en este tema:

Los ciclos aparecen en varios contextos diferentes.

En el RTL combinacional pueden utilizarse para describir:

- productos parciales;
- operaciones repetidas;
- procesamiento por bit.

Durante inicialización de una LUT pueden utilizarse para recorrer todas las combinaciones.

En un testbench pueden utilizarse para verificar exhaustivamente todas las entradas.

Pero el significado físico cambia dependiendo del contexto.

```
for en RTL combinacional
        ↓
puede expandirse en lógica

for en bloque secuencial
        ↓
puede describir registros paralelos

for generate
        ↓
replica estructuras

for en testbench
        ↓
genera estímulos de simulación
```

Por eso no debe analizarse el `for` únicamente por su sintaxis.

Debe observarse **dónde está escrito y qué clase de hardware describe**.

## Relación entre descripción y síntesis

### RTL como intención:

Una expresión como:

```
assign resultado = a * b;
```

indica directamente una intención de multiplicación.

En cambio, una descripción mediante productos parciales especifica con más detalle una posible estructura interna.

Por ejemplo:

```
a * b
```

deja más decisiones a la herramienta.

Mientras que:

```
productos parciales
+ corrimientos
+ sumas
```

expresa explícitamente una determinada arquitectura combinacional.

Sin embargo, incluso cuando el diseñador escribe una estructura concreta, las herramientas todavía pueden aplicar optimizaciones durante la síntesis.

# Ideas fundamentales de la clase

Un ciclo `for` en Verilog no debe interpretarse automáticamente como un proceso que tarda varias iteraciones temporales. Cuando el número de repeticiones puede conocerse durante la síntesis, el sintetizador puede desenrollar el ciclo y crear el hardware correspondiente a todas las iteraciones.

El `for` procedural y el `for generate` cumplen funciones diferentes. El primero se utiliza dentro de bloques procedurales para repetir operaciones sobre señales; el segundo se utiliza durante la elaboración para replicar módulos, compuertas o conexiones. La sintaxis puede ser semejante, pero representan mecanismos distintos de construcción del hardware.

Una descripción combinacional debe asignar todos sus resultados en todos los caminos posibles. Si una salida conserva implícitamente su valor anterior, puede inferirse un latch. De forma práctica, se utilizan asignaciones bloqueantes `=` en lógica combinacional y no bloqueantes `<=` en lógica secuencial.

En ASIC, las construcciones deben ser estáticamente analizables y sintetizables. Retardos `#`, $display, ciclos sin límite conocido y determinados usos de `initial` corresponden principalmente a simulación y no deben confundirse con hardware portable.

Dos operandos signed de 5 bits tienen valores entre $-16$ y $15$. El producto requiere 10 bits porque debe poder representar el caso $(-16)(-16)=256$. Una salida signed de 9 bits no es suficiente, ya que su valor positivo máximo es $255$.

Un multiplicador mediante LUT almacena todos los productos posibles y utiliza la concatenación de las entradas como dirección. Para dos operandos de 5 bits se necesitan $2^{10}=1024$ posiciones de 10 bits, es decir, $10240$ bits. La técnica funciona para operandos pequeños, pero su consumo de memoria crece exponencialmente con el ancho.

La multiplicación mediante corrimientos y sumas genera productos parciales. Cada bit del multiplicador determina si se agrega una versión desplazada del multiplicando. Para números con signo, el diseño mostrado obtiene primero las magnitudes, calcula el producto sin signo y después aplica el signo mediante complemento a dos.

Los operadores `~`, `^`, `<<`, `? :`, las concatenaciones `{ }` y las asignaciones `assign` no son simples operaciones abstractas: cada uno describe estructuras lógicas que terminarán transformándose en compuertas, multiplexores, conexiones o sumadores.

Finalmente, verificar funcionalmente un diseño no es suficiente. También deben analizarse área, temporización, ruta crítica, potencia y portabilidad tecnológica. En diseño digital, conocer qué resultado produce el código es solo una parte del trabajo; comprender qué hardware genera es lo que permite realmente diseñar un sistema eficiente.
