## Introducción

Una **máquina de estados finitos**, o **FSM —Finite State Machine—**, es una forma de diseñar sistemas digitales cuyo comportamiento depende de una condición interna llamada **estado**. En lugar de analizar únicamente las entradas presentes en un instante, el circuito conserva información acerca de la situación en la que se encuentra y utiliza esa información para decidir qué debe ocurrir después.

Este tipo de estructura resulta especialmente útil cuando un sistema debe seguir una secuencia de comportamientos. Un semáforo, por ejemplo, no puede decidir qué luz encender observando únicamente una entrada externa: necesita recordar si actualmente se encuentra en verde, amarillo o rojo. De manera similar, un detector de secuencia necesita recordar qué parte del patrón esperado se ha reconocido hasta el momento.

El tema se centra en dos modelos fundamentales de FSM:

- **Moore**, donde la salida depende únicamente del estado actual.
- **Mealy**, donde la salida depende del estado actual y también de las entradas.

Además, se estudia el flujo completo para diseñar estos sistemas en Verilog: partir de la especificación, construir el diagrama de estados, definir las transiciones, codificar los estados y finalmente implementar y verificar el circuito. Los dos casos utilizados son un **semáforo** y un **detector de la secuencia 1011**. maquinas de estados

## Concepto general de una máquina de estados

### Estado actual:

El **estado actual** representa la situación interna en la que se encuentra el sistema.

Por ejemplo, en un semáforo pueden existir:

```
ST_G → estado verde
ST_Y → estado amarillo
ST_R → estado rojo
```

El circuito mantiene uno de estos valores almacenado en registros.

El estado actual cambia normalmente en un flanco de reloj.

Conceptualmente:

```
             entradas
                │
                ▼
        lógica de siguiente estado
                │
                ▼
          next_state
                │
                ▼
        ┌────────────────┐
clk ───►│ Registro estado│
        └────────────────┘
                │
                ▼
              state
```

La variable `state` contiene la condición actual y `next_state` indica cuál será el estado después del siguiente evento de reloj.

### Transición:

Una **transición** es el cambio de un estado a otro.

Por ejemplo:

```
VERDE ──► AMARILLO
```

La transición puede depender de una entrada.

Si se define:

```
t = temporizador agotado
```

entonces:

```
VERDE -- t=1 --> AMARILLO
```

Mientras:

```
t = 0
```

puede mantenerse el mismo estado:

```
VERDE -- t=0 --> VERDE
```

Una FSM puede entenderse, por tanto, mediante tres preguntas:

```
¿En qué estado está?
        ↓
¿Qué entradas recibe?
        ↓
¿A qué estado debe ir y qué debe producir?
```

## Máquinas de Moore

### Definición:

En una **máquina de Moore**, las salidas dependen exclusivamente del **estado actual**.

Puede expresarse conceptualmente como:

\[ Salida=f(Estado) \]

Las entradas pueden determinar hacia qué estado se moverá la máquina, pero no modifican directamente la salida mientras el estado no cambie.

El material caracteriza a Moore por producir salidas más estables y por ser especialmente apropiada cuando se desea una salida sincronizada con los cambios de estado. También señala que suele necesitar una mayor cantidad de estados. maquinas de estados

### Ejemplo conceptual:

Supóngase:

```
Estado = VERDE
```

Entonces:

```
G = 1
Y = 0
R = 0
```

Aunque cambie una entrada externa, mientras el sistema continúe en `VERDE`, las salidas correspondientes a ese estado permanecen iguales.

```
Estado VERDE
     │
     └──► G = 1
```

El cambio de salida ocurre cuando se modifica el estado.

---

## Máquinas de Mealy

### Definición:

En una **máquina de Mealy**, la salida depende tanto del estado actual como de las entradas.

Conceptualmente:

\[ Salida=f(Estado,Entradas) \]

Esto significa que una entrada puede modificar una salida inmediatamente, incluso antes de que la máquina cambie formalmente de estado.

Por ejemplo:

```
Estado = VERDE
emg = 0 → G = 1

Estado = VERDE
emg = 1 → R = 1
```

El estado puede seguir siendo `VERDE`, pero la salida cambia debido a la señal `emg`.

### Consecuencia:

La ventaja es una respuesta más rápida.

Sin embargo, las salidas dependen directamente de lógica combinacional asociada con las entradas, por lo que debe cuidarse la aparición de cambios transitorios no deseados o **glitches**.

El material destaca precisamente que Mealy tiende a responder más rápido, utiliza normalmente menos estados y requiere más cuidado en la lógica combinacional. maquinas de estados

---

## Comparación entre Moore y Mealy

### Diferencias principales:

|Característica|Moore|Mealy|
|---|---|---|
|Salida depende de|Estado|Estado + entradas|
|Respuesta|Asociada al cambio de estado|Puede ser inmediata ante una entrada|
|Robustez de salida|Alta|Media|
|Cantidad de estados|Suele ser mayor|Suele ser menor|
|Uso típico|Salida sincronizada|Respuesta rápida|

Puede recordarse mediante:

```
MOORE
estado ───────► salida

MEALY
estado ──┐
         ├────► salida
entrada ─┘
```

La diferencia fundamental no se encuentra en la existencia de estados —ambas poseen estados— sino en **qué información utiliza la lógica de salida**.

## Metodología para diseñar una FSM

### Flujo general:

El material propone una secuencia de diseño muy clara:

```
Especificación
     ↓
Diagrama de estados
     ↓
Codificación de estados
     ↓
Lógica de next_state
     ↓
Lógica de salida
     ↓
Código Verilog
     ↓
Simulación
```

El proceso comienza definiendo:

- entradas;
- salidas;
- comportamiento esperado.

Después se dibujan los estados y sus transiciones.

A continuación, cada estado recibe una codificación binaria y finalmente se traduce el comportamiento a Verilog. maquinas de estados

---

## Los tres bloques típicos de una FSM

### Registro de estado:

El primer bloque almacena el estado actual.

Una estructura típica es:

```
always @(posedge clk or posedge rst) begin
    if (rst)
        state <= S0;
    else
        state <= next_state;
end
```

Este bloque es **secuencial** porque depende del reloj.

El comportamiento es:

```
rst = 1
   ↓
state = S0

rst = 0
   ↓
en cada flanco de clk:
state = next_state
```

### Lógica de siguiente estado:

El segundo bloque determina cuál será el próximo estado.

Por ejemplo:

```
always @(*) begin
    next_state = state;

    case (state)
        S0:
            if (a)
                next_state = S1;

        S1:
            if (a)
                next_state = S2;

        S2:
            if (a)
                next_state = S0;
    endcase
end
```

Este bloque es combinacional.

Debe responder a:

```
estado actual + entradas
          ↓
      next_state
```

### Lógica de salida:

El tercer bloque calcula las salidas.

En Moore puede utilizarse:

```
always @(*) begin
    y = 1'b0;

    case (state)
        S0: y = 1'b0;
        S1: y = 1'b0;
        S2: y = 1'b1;
    endcase
end
```

Aquí `y` depende únicamente de `state`.

En Mealy, además de `state`, se utilizan las entradas.

---

## Importancia de `next_state = state`

### Valor por defecto:

En la lógica combinacional suele colocarse:

```
next_state = state;
```

antes del `case`.

Esto significa:

> Si ninguna condición indica un cambio de estado, el sistema permanece donde está.

Por ejemplo:

```
state = VERDE
t = 0
```

entonces:

```
next_state = VERDE
```

Este valor por defecto simplifica considerablemente la descripción.

También ayuda a asegurar que `next_state` reciba siempre un valor.

---

## Prevención de latches

### Problema:

Una salida combinacional o `next_state` debe recibir un valor en todos los caminos posibles.

Por ejemplo:

```
always @(*) begin
    if (a)
        next_state = S1;
end
```

si:

```
a = 0
```

no existe ninguna asignación.

Esto implica que `next_state` debe conservar un valor anterior y puede inferirse un latch.

### Solución:

Se proporciona un valor por defecto:

```
always @(*) begin
    next_state = state;

    if (a)
        next_state = S1;
end
```

De forma similar, para salidas:

```
always @(*) begin
    y = 1'b0;

    case (state)
        ...
    endcase
end
```

El material incluye precisamente como parte del flujo de diseño la necesidad de comprobar valores por defecto para evitar latches. maquinas de estados

---

## Codificación de estados

### Uso de `localparam`:

Los estados pueden representarse mediante constantes.

Por ejemplo:

```
localparam S0 = 2'b00,
           S1 = 2'b01,
           S2 = 2'b10;
```

Después el registro:

```
reg [1:0] state, next_state;
```

puede contener cualquiera de esas codificaciones.

El uso de nombres como `S0`, `ST_G` o `ST_R` hace que el código sea mucho más legible que escribir directamente los valores binarios.

Por ejemplo:

```
if (state == ST_G)
```

es más descriptivo que:

```
if (state == 2'b00)
```

## Ejemplo 1: semáforo

### Especificación:

El semáforo utiliza como entradas:

```
t   → temporizador agotado
emg → modo de emergencia
```

Las salidas son:

```
R → rojo
Y → amarillo
G → verde
```

La diferencia entre las versiones Moore y Mealy se manifiesta principalmente en el tratamiento de la señal `emg`.

En Moore, las luces dependen exclusivamente del estado.

En Mealy, una entrada de emergencia puede influir inmediatamente en la salida. maquinas de estados

---

## Semáforo Moore

### Estados:

Se utilizan tres estados:

```
ST_G → verde
ST_Y → amarillo
ST_R → rojo
```

El ciclo normal es:

```
      t           t           t
ST_G ───► ST_Y ─────► ST_R ─────► ST_G
```

Si:

```
t = 0
```

el sistema permanece en su estado actual.

Por tanto:

```
ST_G:
    !t → ST_G
     t → ST_Y

ST_Y:
    !t → ST_Y
     t → ST_R

ST_R:
    !t → ST_R
     t → ST_G
```

El diagrama del material muestra justamente estos tres estados con bucles de permanencia cuando `!t` y avance cuando `t`. maquinas de estados

---

## Salidas del semáforo Moore

### Estado verde:

```
R = 0
Y = 0
G = 1
```

Por tanto:

```
RYG = 001
```

### Estado amarillo:

```
R = 0
Y = 1
G = 0
```

Por tanto:

```
RYG = 010
```

### Estado rojo:

```
R = 1
Y = 0
G = 0
```

Por tanto:

```
RYG = 100
```

La asociación es directa:

```
state = ST_G → G = 1
state = ST_Y → Y = 1
state = ST_R → R = 1
```

Por eso se trata de una máquina de Moore.

---

## Código del semáforo Moore

### Registro de estado:

```
always @(posedge clk or posedge rst)
    if (rst)
        state <= ST_G;
    else
        state <= next_state;
```

El reset coloca al sistema en verde.

### Lógica de transición:

```
always @(*) begin
    next_state = state;

    case (state)
        ST_G:
            if (t)
                next_state = ST_Y;

        ST_Y:
            if (t)
                next_state = ST_R;

        ST_R:
            if (t)
                next_state = ST_G;
    endcase
end
```

Cada flecha del diagrama se transforma prácticamente en una condición dentro del `case`.

### Lógica de salida:

```
always @(*) begin
    R = 1'b0;
    Y = 1'b0;
    G = 1'b0;

    case (state)
        ST_G: G = 1'b1;
        ST_Y: Y = 1'b1;
        ST_R: R = 1'b1;
        default: G = 1'b1;
    endcase
end
```

La salida utiliza solamente `state`, por lo que la estructura corresponde a Moore. maquinas de estados

---

## Semáforo Mealy

### Inclusión de la emergencia:

En la versión Mealy, aparece la entrada:

```
emg
```

La característica importante es que la salida puede responder a ella sin esperar necesariamente un cambio completo de estado.

Por ejemplo, mientras el sistema está conceptualmente en verde:

```
state = ST_G
```

si:

```
emg = 0
```

puede mantenerse:

```
G = 1
```

pero si:

```
emg = 1
```

puede forzarse:

```
R = 1
```

Esta dependencia directa respecto a `emg` convierte a la lógica de salida en una salida de Mealy.

---

## Diagrama de Mealy

### Etiquetas de las transiciones:

En un diagrama de Moore, la salida suele asociarse al estado.

En Mealy, la salida puede colocarse sobre la transición utilizando la notación:

```
entrada / salida
```

Por ejemplo:

```
emg / R=1
```

significa:

> Si ocurre `emg`, durante esa transición la salida roja se activa.

Esto permite representar respuesta inmediata a determinadas entradas.

El material muestra este comportamiento en el semáforo Mealy y enfatiza que las etiquetas de transición incluyen entrada y salida. maquinas de estados

---

## Prioridad entre entradas

### Emergencia antes que temporizador:

En el estado verde se utiliza una estructura como:

```
ST_G: begin
    if (emg)
        next_state = ST_R;
    else if (t)
        next_state = ST_Y;
end
```

Esto significa que `emg` tiene prioridad.

Si simultáneamente:

```
emg = 1
t   = 1
```

se evalúa primero:

```
if (emg)
```

por lo que:

```
next_state = ST_R
```

y no `ST_Y`.

El orden de los `if` representa, por tanto, una prioridad lógica real.

---

## Salidas del semáforo Mealy

### Dependencia directa de `emg`:

Una posible salida es:

```
always @(*) begin
    R = 1'b0;
    Y = 1'b0;
    G = 1'b0;

    case (state)
        ST_G: begin
            if (emg)
                R = 1'b1;
            else
                G = 1'b1;
        end

        ST_Y:
            Y = 1'b1;

        ST_R:
            R = 1'b1;
    endcase
end
```

El aspecto decisivo es:

```
if (emg)
    R = 1'b1;
```

La salida `R` depende del estado **y de la entrada `emg`**.

Por ello la máquina es Mealy. maquinas de estados

## Ejemplo 2: detector de secuencia 1011

### Objetivo:

El segundo ejemplo recibe una entrada serial:

```
x
```

y produce:

```
z
```

La salida debe activarse cuando los bits recibidos formen:

```
1011
```

Se permiten **traslapes**.

Por ejemplo, en una corriente de bits:

```
1011011
```

el sistema debe poder utilizar bits de una detección anterior como comienzo de una nueva detección cuando corresponda.

El material utiliza este caso para mostrar que, en Moore, la detección necesita un estado dedicado, mientras que en Mealy puede producirse directamente sobre la transición final. maquinas de estados

---

## Significado de los estados del detector

### Estado `S0`:

No se posee coincidencia relevante.

```
S0 → nada reconocido
```

### Estado `S1`:

Se ha reconocido:

```
1
```

### Estado `S2`:

Se ha reconocido:

```
10
```

### Estado `S3`:

Se ha reconocido:

```
101
```

En una versión Moore se añade:

```
S4
```

que representa que ya se detectó:

```
1011
```

y en ese estado:

```
z = 1
```

Esta interpretación es crucial: los estados representan **cuánto del patrón se ha reconocido hasta ese momento**.

---

## Detector Moore de 1011

### Estructura general:

El detector Moore posee:

```
S0
S1
S2
S3
S4
```

El estado `S4` existe exclusivamente para indicar:

```
z = 1
```

La salida no se activa mientras se está realizando la transición final; se activa una vez que el sistema entra a `S4`.

El material señala expresamente que la existencia de este estado extra es característica de Moore. maquinas de estados

---

## Transiciones principales del detector Moore

### Desde `S0`:

Si llega:

```
x = 0
```

no se ha iniciado el patrón:

```
S0 → S0
```

Si llega:

```
x = 1
```

se ha encontrado el primer bit:

```
S0 → S1
```

### Desde `S1`:

Ya existe un `1`.

Si llega otro `1`:

```
11
```

el último `1` todavía puede servir como comienzo de `1011`.

Por eso:

```
S1 --1--> S1
```

Si llega `0`:

```
10
```

se avanza:

```
S1 --0--> S2
```

### Desde `S2`:

Se posee:

```
10
```

Si llega `1`:

```
101
```

entonces:

```
S2 → S3
```

Si llega `0`, se pierde la coincidencia:

```
S2 → S0
```

### Desde `S3`:

Se posee:

```
101
```

Si llega `1`, se completa:

```
1011
```

y en Moore:

```
S3 → S4
```

Si llega `0`, el patrón parcial restante se utiliza según las transiciones mostradas en el diagrama.

---

## Salida Moore del detector

### Estado de detección:

La lógica puede escribirse de manera muy sencilla:

```
always @(*) begin
    z = (state == S4);
end
```

Esto equivale a:

```
state = S4 → z = 1

cualquier otro estado → z = 0
```

La salida depende únicamente del estado.

El material destaca que la salida no se activa en la flecha final, sino cuando se alcanza `S4`; ese retraso de un estado es característico del modelo Moore. maquinas de estados

---

## Traslape en el detector

### Concepto:

Permitir traslapes significa que después de una detección no se descarta necesariamente toda la información anterior.

Considérese:

```
1011011
```

La primera aparición es:

```
1011
^^^^
```

Sin embargo, los bits finales de esa aparición pueden ser el comienzo de otra.

Por ello, después de detectar la secuencia, el sistema no necesariamente vuelve siempre a `S0`.

Puede regresar a un estado que represente un prefijo válido.

Esta es la razón de transiciones como:

```
S4 --1--> S1
```

o hacia otro estado que represente información todavía útil.

---

## Detector Mealy de 1011

### Eliminación del estado de detección:

En la versión Mealy no se necesita `S4`.

Los estados son:

```
S0
S1
S2
S3
```

Cuando el sistema ya ha reconocido:

```
101
```

se encuentra en:

```
S3
```

Si llega:

```
x = 1
```

se completa:

```
1011
```

En ese mismo momento se activa:

```
z = 1
```

La detección ocurre directamente en la transición.

El material muestra esta transición como:

```
S3 -- 1/1 --> S1
```

donde:

```
1/1
```

significa:

```
entrada x = 1
salida  z = 1
```

No se necesita un estado adicional. maquinas de estados

---

## Etiquetas del detector Mealy

### Forma `entrada/salida`:

Las transiciones pueden etiquetarse como:

```
0/0
1/0
1/1
```

Por ejemplo:

```
S3 --1/1--> S1
```

se interpreta como:

```
estado actual = S3
entrada x = 1
salida z = 1
siguiente estado = S1
```

El retorno a `S1` permite aprovechar el último `1` como inicio potencial de una nueva secuencia.

---

## Código del detector Mealy

### Valores por defecto:

El bloque combinacional comienza con:

```
always @(*) begin
    next_state = state;
    z = 1'b0;
```

De esta forma, si ninguna transición genera detección:

```
z = 0
```

### Estado final parcial:

En `S3`:

```
S3: begin
    if (x) begin
        next_state = S1;
        z = 1'b1;
    end
    else begin
        next_state = S2;
    end
end
```

Cuando:

```
state = S3
x = 1
```

se ejecutan simultáneamente:

```
z = 1
next_state = S1
```

La salida se genera en el mismo bloque donde se evalúa `x`.

Por ello es una FSM de Mealy. maquinas de estados

---

## Diferencia temporal en un detector Moore y Mealy

### Moore:

Supóngase que llegan:

```
1 → 0 → 1 → 1
```

Los estados evolucionan:

```
S0
 ↓ 1
S1
 ↓ 0
S2
 ↓ 1
S3
 ↓ 1
S4
```

Solo cuando:

```
state = S4
```

se produce:

```
z = 1
```

### Mealy:

La progresión es:

```
S0
 ↓ 1
S1
 ↓ 0
S2
 ↓ 1
S3
```

Cuando llega el último `1`:

```
S3 --1/1--> S1
```

la salida se activa sobre esa transición.

Por eso:

```
Moore → detección asociada al estado final

Mealy → detección asociada a la transición final
```

## Del diagrama al código

### Paso 1: nombrar estados:

Los nombres deben representar el significado físico o lógico.

Por ejemplo:

```
ST_G
ST_Y
ST_R
```

o:

```
S0 = nada detectado
S1 = detectado "1"
S2 = detectado "10"
S3 = detectado "101"
```

### Paso 2: interpretar cada flecha:

Cada transición se convierte en una condición.

Por ejemplo:

```
S2 --x=1--> S3
```

se convierte en:

```
S2:
    if (x)
        next_state = S3;
```

### Paso 3: codificar los estados:

Con `localparam`:

```
localparam S0 = 2'd0,
           S1 = 2'd1,
           S2 = 2'd2,
           S3 = 2'd3;
```

### Paso 4: decidir Moore o Mealy:

Se analiza de qué depende la salida.

```
solo state
   ↓
Moore

state + entrada
   ↓
Mealy
```

### Paso 5: valores por defecto:

Se agregan:

```
next_state = state;
z = 1'b0;
```

para obtener una lógica combinacional completa.

El material resume este procedimiento mediante la secuencia de nombrar estados, convertir transiciones en expresiones booleanas, crear `localparam`, traducir flechas a `next_state` y decidir si la salida depende solo del estado o también de las entradas. maquinas de estados

## Plantilla general de una FSM Moore

### Estructura:

Una plantilla conceptual puede escribirse como:

```
module fsm_moore (
    input  wire clk,
    input  wire rst,
    input  wire x,
    output reg  y
);

    reg [1:0] state, next_state;

    localparam S0 = 2'b00,
               S1 = 2'b01,
               S2 = 2'b10;

    // Registro de estado
    always @(posedge clk or posedge rst) begin
        if (rst)
            state <= S0;
        else
            state <= next_state;
    end

    // Siguiente estado
    always @(*) begin
        next_state = state;

        case (state)
            S0:
                if (x)
                    next_state = S1;

            S1:
                if (x)
                    next_state = S2;

            S2:
                if (x)
                    next_state = S0;
        endcase
    end

    // Salida Moore
    always @(*) begin
        y = 1'b0;

        case (state)
            S2:
                y = 1'b1;
        endcase
    end

endmodule
```

La característica decisiva es:

```
bloque de salida
       ↓
solo consulta state
```

## Plantilla general de una FSM Mealy

### Estructura:

```
module fsm_mealy (
    input  wire clk,
    input  wire rst,
    input  wire x,
    output reg  y
);

    reg [1:0] state, next_state;

    localparam S0 = 2'b00,
               S1 = 2'b01,
               S2 = 2'b10;

    always @(posedge clk or posedge rst) begin
        if (rst)
            state <= S0;
        else
            state <= next_state;
    end

    always @(*) begin
        next_state = state;
        y = 1'b0;

        case (state)
            S0: begin
                if (x) begin
                    next_state = S1;
                    y = 1'b1;
                end
            end

            ...
        endcase
    end

endmodule
```

La característica fundamental aparece aquí:

```
state + x
   ↓
   y
```

Por tanto, la salida puede modificarse sin esperar a entrar a otro estado.

## Lógica secuencial y combinacional

### Parte secuencial:

El registro de estado contiene memoria.

```
always @(posedge clk ...)
```

representa flip-flops.

Su función es recordar:

```
¿en qué estado está la máquina?
```

### Parte combinacional:

Los bloques:

```
always @(*)
```

calculan:

```
next_state
salidas
```

a partir de las condiciones presentes.

Puede visualizarse como:

```
                  ┌─────────────────────┐
Entradas ────────►│ Lógica combinacional│
                  │  de next_state      │
Estado ──────────►│                     │
                  └──────────┬──────────┘
                             │
                             ▼
                         next_state
                             │
                             ▼
                         Registro
                             │
                             ▼
                           state
```

La separación clara entre estas dos partes facilita tanto la síntesis como la depuración del diseño.

## Reset

### Función:

El `reset` establece un estado inicial conocido.

Por ejemplo:

```
if (rst)
    state <= S0;
```

Sin reset, el circuito podría comenzar en una codificación de estado no deseada.

En los ejemplos estudiados:

- el semáforo puede comenzar en `ST_G`;
- el detector comienza en `S0`.

Esto garantiza un comportamiento inicial predecible.

---

## Reset asíncrono en la plantilla

### Uso de `posedge rst`:

La estructura mostrada utiliza:

```
always @(posedge clk or posedge rst)
```

Esto significa que el reset puede modificar el estado sin esperar al siguiente flanco de reloj.

Si:

```
rst = 1
```

el estado inicial se carga inmediatamente según la descripción.

Cuando:

```
rst = 0
```

los cambios normales de estado vuelven a producirse mediante `clk`.

## Buenas prácticas

### Valores por defecto:

Debe colocarse un valor inicial en:

```
next_state
```

y en todas las salidas combinacionales.

Esto ayuda a evitar latches.

### Separación de lógica:

Debe mantenerse claramente separada:

```
lógica secuencial
       ≠
lógica combinacional
```

Esto hace más legible el diseño y reduce errores.

### Nombres descriptivos:

Es preferible:

```
ST_GREEN
ST_YELLOW
ST_RED
```

o nombres equivalentes descriptivos frente a codificaciones sin significado.

### Documentación de transiciones:

Cada condición debe corresponder claramente con una flecha del diagrama.

### Simulación:

Deben probarse:

- casos normales;
- casos extremos;
- reset;
- secuencias inesperadas.

### Entradas físicas:

Cuando se implementa en FPGA y se utilizan entradas mecánicas como switches, debe considerarse la sincronización de dichas entradas.

## Cómo reconocer Moore o Mealy en código

### Moore:

Si se encuentra algo como:

```
case (state)
    S0: y = 0;
    S1: y = 0;
    S2: y = 1;
endcase
```

entonces:

```
y depende únicamente de state
```

por lo que es Moore.

### Mealy:

Si aparece:

```
case (state)
    S0:
        if (x)
            y = 1;
endcase
```

entonces:

```
y depende de state y x
```

por lo que es Mealy.

Esta es normalmente la forma más directa de distinguirlas en Verilog.

---

## Cómo reconocer Moore o Mealy en un diagrama

### Moore:

Las salidas aparecen escritas **dentro de los estados**.

Por ejemplo:

```
   ┌──────────┐
   │   S4     │
   │  z = 1   │
   └──────────┘
```

### Mealy:

Las salidas aparecen sobre las **transiciones**.

Por ejemplo:

```
S3 ── 1/1 ──► S1
```

donde:

```
entrada / salida
```

Esta diferencia visual permite identificar rápidamente el modelo.

---

## Relación entre Moore y Mealy

### Mismo comportamiento general:

Una misma función puede implementarse con Moore o Mealy.

Por ejemplo:

```
detectar 1011
```

puede resolverse mediante ambos modelos.

La diferencia está en **cuándo y dónde se produce la salida**.

En Moore:

```
transición final
      ↓
estado de detección
      ↓
z = 1
```

En Mealy:

```
transición final
      ↓
z = 1 directamente
```

Por eso Mealy puede eliminar estados dedicados únicamente a indicar una salida.

---

## Robustez frente a rapidez

### Moore:

Su salida depende únicamente de información registrada.

Conceptualmente:

```
estado almacenado
      ↓
salida
```

Esto produce un comportamiento más estable.

### Mealy:

Las entradas participan directamente:

```
estado ──┐
         ├──► lógica ──► salida
entrada ─┘
```

Esto permite una respuesta más rápida, pero también significa que cambios en las entradas pueden afectar inmediatamente la salida.

Así aparece el compromiso:

```
Moore
↑ estabilidad
↓ respuesta inmediata

Mealy
↑ respuesta inmediata
↓ mayor cuidado combinacional
```

## FSM como controlador

### Función de control:

Una máquina de estados resulta especialmente útil para determinar **qué debe hacer un sistema en cada momento**.

Por ejemplo, una FSM puede controlar:

- semáforos;
- protocolos;
- secuencias de comunicación;
- multiplicadores iterativos;
- divisores;
- interfaces;
- señales `start`, `busy` y `done`.

La máquina no tiene que realizar necesariamente el cálculo principal.

Puede actuar como la parte de **control** que ordena a otros bloques qué operación ejecutar.

En términos conceptuales:

```
        FSM
         │
         ├── enable
         ├── load
         ├── shift
         ├── clear
         └── done
            │
            ▼
         Datapath
```

La lógica de estados decide **cuándo** deben ocurrir las operaciones.

## Interpretación física

### Registro de estado:

La variable:

```
state
```

termina implementándose mediante flip-flops.

### Lógica de transición:

El bloque que calcula:

```
next_state
```

se implementa mediante lógica combinacional.

### Lógica de salida:

En Moore:

```
state → lógica → salida
```

En Mealy:

```
state + entradas → lógica → salida
```

Por tanto, una FSM sintetizada puede visualizarse como:

```
                ┌───────────────────┐
Entradas ──────►│ Lógica siguiente │
                │      estado       │
state ─────────►│                   │
                └─────────┬─────────┘
                          │
                          ▼
                     next_state
                          │
                          ▼
                    ┌──────────┐
clk ───────────────►│ Registro │
                    └────┬─────┘
                         │
                         ▼
                       state
                         │
                ┌────────┴────────┐
                ▼                 ▼
          lógica Moore      lógica Mealy
             +state          +entradas
                │                 │
                └────────┬────────┘
                         ▼
                       salida
```

### Especificación:

Primero se define lo que debe hacer el sistema.

# Ideas fundamentales de la clase

Una máquina de estados finitos almacena una condición interna llamada estado. Las entradas y el estado actual determinan el comportamiento futuro del sistema, mientras que un registro sincronizado por reloj conserva el estado entre ciclos.

En una máquina de Moore, las salidas dependen únicamente del estado actual. Esto suele generar salidas más estables, pero puede requerir estados adicionales. En una máquina de Mealy, las salidas dependen del estado y de las entradas, lo que permite reaccionar más rápidamente y normalmente utilizar menos estados.

Una FSM en Verilog se divide normalmente en tres partes: el registro del estado actual, la lógica combinacional que calcula `next_state` y la lógica de salida. El primer bloque representa memoria mediante flip-flops, mientras que los otros dos representan lógica combinacional.

El semáforo muestra cómo una FSM puede emplearse como controlador. En Moore, los estados verde, amarillo y rojo determinan directamente qué luz se activa. En Mealy, una entrada como `emg` puede modificar una salida inmediatamente, demostrando la dependencia entre estado e entrada.

El detector de secuencia `1011` muestra con claridad la diferencia temporal entre ambos modelos. Moore necesita un estado adicional de detección en el que `z=1`, mientras que Mealy activa `z` directamente sobre la transición que completa la secuencia.

Los estados de un detector de secuencias representan cuánto del patrón se ha reconocido. Esto permite diseñar correctamente las transiciones e implementar traslapes sin perder información útil de bits anteriores.

Al traducir un diagrama a Verilog, cada estado debe convertirse en una codificación, cada flecha debe transformarse en una condición de `next_state` y debe definirse explícitamente si la salida depende únicamente del estado o también de las entradas.

Finalmente, un buen diseño de FSM debe incluir valores por defecto para evitar latches, mantener separadas la lógica secuencial y combinacional, utilizar nombres descriptivos, documentar las transiciones y verificarse mediante simulación. El flujo fundamental es **especificación → diagrama de estados → Verilog → simulación**.
