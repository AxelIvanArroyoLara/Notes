## Introducción

La seguridad de la información estudia cómo proteger la información, los sistemas que la almacenan y procesan, las aplicaciones que la utilizan y las redes que permiten transportarla frente a accesos no autorizados, modificaciones, interrupciones, engaños y otros eventos capaces de comprometer su funcionamiento.

En este bloque del curso se construye una progresión lógica. Primero se define **qué significa proteger información**, posteriormente se estudian las amenazas y ataques que pueden comprometerla, después aparecen los servicios y mecanismos de seguridad y, finalmente, estos conceptos se trasladan a redes mediante TCP/IP, IDS, IPS, Snort, firewalls, ACL, DMZ y ataques DoS/DDoS. El programa coloca estos contenidos dentro de las unidades **Introduction to Information Security** y **Hacking and Intrusion Detection Systems**, antes del estudio formal de cifrados simétricos.

El enfoque general de la seguridad utilizado en el curso puede resumirse mediante tres acciones:

```
PREVENT
   ↓
Evitar que ocurra una violación

DETECT
   ↓
Descubrir que una violación
está ocurriendo o ya ocurrió

CORRECT
   ↓
Corregir las consecuencias
y recuperar el sistema
```

El material define Internet e Information Security precisamente como el conjunto de medidas utilizadas para **prevenir, detectar y corregir** violaciones que involucren la transmisión o almacenamiento de información.

Otra idea fundamental es que **la seguridad no es un producto, sino un proceso**. Instalar un firewall, un antivirus o un IDS no convierte automáticamente una organización en segura. Deben identificarse los activos, comprenderse las amenazas, analizarse los riesgos, implementarse controles, monitorearse los sistemas, responderse a los incidentes y actualizarse continuamente las defensas.

Una visión general del bloque puede representarse como:

```
                       SEGURIDAD DE LA INFORMACIÓN

                ┌─────────────────┴─────────────────┐
```

## Principios fundamentales de seguridad

### Seguridad frente a facilidad de acceso:

El material comienza con un ejemplo en el que Alice intenta proteger un objeto utilizando progresivamente más controles. El resultado es que se vuelve más difícil para otra persona acceder, pero también se vuelve más lento y complicado para Alice recuperar aquello que ella misma protegió.

Esto introduce un principio importante:

```
Más controles de seguridad
        ↓
Mayor dificultad para el atacante
        +
Mayor dificultad para usuarios legítimos
```

Por tanto, la seguridad no consiste únicamente en maximizar las restricciones. Una solución real debe encontrar un equilibrio entre:

- seguridad;
- funcionalidad;
- disponibilidad;
- usabilidad;
- costo;
- rendimiento.

Las diapositivas acompañan este ejemplo con dos frases fundamentales:

- **Security is Everyone's Responsibility.**
- **A chain is only as strong as its weakest link.**

La segunda significa que la seguridad global de un sistema puede quedar limitada por su componente más débil. Una organización puede tener cifrado avanzado, firewalls y sistemas de detección, pero seguir siendo vulnerable si una cuenta administrativa utiliza una contraseña extremadamente débil o un empleado cae ante phishing.

### Primer principio de seguridad:

El primer principio señalado explícitamente por el profesor consiste en **comprender las necesidades de seguridad de la organización**.

Para hacerlo debe comprenderse su **threat environment**, es decir, el conjunto de amenazas que enfrenta actualmente y aquellas que podría enfrentar en el futuro.

```
ORGANIZACIÓN
     ↓
ACTIVOS
     ↓
THREAT ENVIRONMENT
     ↓
RIESGOS
     ↓
CONTROLES ADECUADOS
```

No existe una única configuración de seguridad correcta para todas las organizaciones. Un hospital, un banco, una universidad y una tienda en línea poseen activos diferentes y enfrentan consecuencias distintas.

### Evolución de los mecanismos de protección:

Las diapositivas presentan una evolución histórica sencilla.

Tradicionalmente se utilizaban principalmente:

```
Mecanismos físicos
+
Mecanismos administrativos
```

La aparición de sistemas computacionales exigió:

```
Herramientas automáticas
        ↓
Protección de archivos
y datos almacenados
```

La aparición de redes añadió otra necesidad:

```
Protección de datos
durante la transmisión
```

Esto explica por qué la seguridad de red no sustituye controles físicos o administrativos, sino que se añade como otra capa de protección.

## Activos, amenazas, vulnerabilidades, riesgos y vectores

### Activos:

Un **activo** es cualquier elemento que posee valor para una organización y que, por tanto, necesita protección.

Puede incluir:

- información;
- contraseñas;
- cuentas;
- bases de datos;
- servidores;
- aplicaciones;
- infraestructura;
- servicios;
- disponibilidad;
- propiedad intelectual;
- reputación.

Por ejemplo, para un sitio de comercio electrónico pueden considerarse activos:

- nombres y direcciones de clientes;
- números de tarjeta;
- contraseñas;
- cuentas;
- servidor web;
- base de datos;
- disponibilidad del servicio.

### Cinco pasos para mejorar la seguridad:

El profesor plantea cinco preguntas principales.

```
1. ASSETS
   ↓
¿Qué debe protegerse?

2. RISKS
   ↓
¿Qué amenazas, vectores,
vulnerabilidades y riesgos existen?

3. PROTECTION
   ↓
¿Cómo se protegerán los activos?

4. TOOLS
   ↓
¿Qué herramientas implementarán
esa protección?

5. PRIORITIES
   ↓
¿En qué orden deben
implementarse los controles?
```

El orden también importa. Por ejemplo, poner en producción un servidor web antes de configurar mecanismos básicos de protección puede crear una ventana innecesaria de exposición.

### Threat:

Una **threat** representa la posibilidad de que ocurra una violación de seguridad.

La existencia de una amenaza no significa necesariamente que el ataque ya haya ocurrido.

### Vulnerability:

Una **vulnerabilidad** es una debilidad que puede ser aprovechada.

```
Servidor
   ↓
Software vulnerable
   ↓
VULNERABILITY
```

### Attack:

Un **ataque** representa la ejecución deliberada de acciones destinadas a evadir los mecanismos de seguridad o violar una política de seguridad.

La relación general puede entenderse así:

```
VULNERABILITY
      +
THREAT
      ↓
Posibilidad de explotación
      ↓
ATTACK
      ↓
IMPACT
```

### Threat Vector:

Un **threat vector** describe qué amenaza existe y mediante qué medio puede llegar al objetivo.

Ejemplo:

```
Atacante
   ↓
Correo con archivo malicioso
   ↓
Empleado
   ↓
Sistema
```

El correo electrónico funciona como el vector mediante el cual la amenaza alcanza a la organización.

## Cybersecurity, Information Security, Network Security y Computer Security

### Cybersecurity:

La **cybersecurity** comprende prácticas, procesos y tecnologías destinadas a proteger:

- dispositivos;
- redes;
- programas;
- sistemas;
- datos;

frente a ataques y accesos no autorizados.

Su alcance no se limita a los datos, ya que también protege los recursos y tecnologías utilizadas para almacenarlos.

### Information Security:

La **information security** se concentra en proteger información y recursos de información, incluyendo datos y comunicaciones.

### Network Security:

La **network security** comprende medidas utilizadas para proteger datos durante su transmisión a través de redes.

### Computer Security:

La **computer security** agrupa herramientas destinadas a proteger datos y sistemas frente a atacantes.

### Internet Security:

La **Internet security** se refiere a la protección de datos durante su transmisión mediante redes interconectadas.

Estos conceptos se superponen. No representan disciplinas completamente independientes.

## La triada CIA

### Confidentiality:

La **confidencialidad** protege información frente a acceso y divulgación no autorizados.

Ejemplos:

- robo de credenciales;
- exposición de números de tarjeta;
- lectura de mensajes privados;
- acceso a información empresarial sin autorización.

```
DATOS
 │
 ├── Usuario autorizado ──→ acceso permitido
 │
 └── Usuario no autorizado ──X──→ bloqueado
```

### Integrity:

La **integridad** protege la información frente a modificaciones no autorizadas.

Ejemplo:

```
Saldo original
$1,000
   ↓
Modificación no autorizada
   ↓
Saldo almacenado
$10,000
```

No es necesario que alguien robe información para que exista una violación. Modificarla también compromete la seguridad.

### Availability:

La **disponibilidad** garantiza que los recursos permanezcan accesibles para usuarios autorizados.

```
Usuarios ─────→ Servicio
                  ↓
              Disponible
```

Durante un ataque:

```
Usuarios ──X──→ Servicio
                  ↑
               Saturado
```

Las diapositivas relacionan explícitamente estos conceptos con robo de credenciales, modificación de información y servicios inaccesibles.

## Ataques pasivos y activos

### Passive Attacks:

Un ataque pasivo intenta obtener o utilizar información sin afectar los recursos del sistema.

El material identifica dos formas principales:

- obtener el contenido de mensajes;
- monitorizar flujos de tráfico.

Además, señala que son difíciles de detectar porque no implican una alteración de los datos.

### Eavesdropping:

El **eavesdropping** consiste en interceptar o escuchar comunicaciones.

```
Alice ─────────────────→ Bob
          │
          │ copia
          ▼
        Trudy
```

### Traffic Analysis:

Incluso cuando el contenido está cifrado puede observarse:

- quién se comunica;
- cuándo;
- durante cuánto tiempo;
- cuánto tráfico genera;
- con qué frecuencia.

---

### Active Attacks:

Los ataques activos intentan alterar recursos o afectar su funcionamiento. El profesor los divide en cuatro categorías.

#### Masquerade:

Una entidad pretende ser otra.

#### Replay:

Una unidad de datos válida se captura y posteriormente se retransmite para provocar un efecto no autorizado.

```
Alice ── mensaje válido ──→ Servidor
              │
              ▼
           Atacante
              │
          guarda copia

Después:

Atacante ── mismo mensaje ──→ Servidor
```

#### Modification of Messages:

Una parte del mensaje es modificada.

#### Data Alteration:

**Data Alteration** es otra forma utilizada en el material para referirse a modificación no autorizada de información.

Compromete principalmente:

```
INTEGRITY
```

#### Denial of Service:

Impide o inhibe el uso normal de servicios de comunicación.

Compromete principalmente:

```
AVAILABILITY
```

## Malware

### Malware:

**Malware** significa software desarrollado con intención maliciosa.

### Virus:

Código que puede integrarse con archivos o programas y propagarse cuando estos son ejecutados.

### Worm:

Programa capaz de propagarse automáticamente, frecuentemente mediante redes.

### Trojan Horse:

Software que aparenta tener una función legítima pero contiene comportamiento malicioso.

### Spyware:

Software utilizado para recopilar información.

### Ransomware:

Software malicioso que bloquea, cifra o amenaza con dañar información.

### Adware:

Software relacionado con publicidad que puede presentar comportamiento invasivo.

### Bot:

Programa instalado sobre una máquina comprometida que permite controlarla remotamente.

### Anti-Malware:

El **anti-malware** es software destinado a detectar, bloquear o eliminar software malicioso. El material lo presenta entre las tecnologías de seguridad.

## Ingeniería social

### Social Engineering:

La **ingeniería social** utiliza engaño o manipulación psicológica en lugar de depender únicamente de vulnerabilidades técnicas.

### Phishing:

Utiliza mensajes engañosos para conseguir que una víctima realice una acción.

### Spear Phishing:

Es phishing dirigido específicamente contra una persona u organización.

### Vishing:

Phishing mediante llamadas telefónicas.

### Smishing:

Phishing mediante SMS.

### Pretexting:

Construcción de una historia falsa destinada a convencer a una víctima de entregar información.

## Otras amenazas

### Pharming:

Manipula DNS o archivos locales para redirigir automáticamente usuarios hacia sitios falsos.

### Drive-By Attack:

Utiliza un sitio web para distribuir o descargar material no deseado o malicioso.

### Cryptojacking:

Utiliza recursos computacionales sin autorización para realizar minería de criptomonedas.

### SQL Injection:

Explota aplicaciones que incorporan incorrectamente entradas del usuario dentro de consultas SQL.

### Supply Chain Attack:

Compromete a un proveedor o tercero más débil para alcanzar posteriormente una organización mayor.

```
Atacante
   ↓
Proveedor
   ↓
Producto / servicio
   ↓
Organización objetivo
```

### Man-in-the-Middle:

El atacante intercepta comunicaciones entre dos participantes.

### Zero-Day:

Una vulnerabilidad **zero-day** es explotada antes de que exista un parche disponible.

### Insider Threat:

Una **insider threat** es una amenaza originada desde dentro de la propia organización.

Puede surgir por:

- comportamiento malicioso;
- negligencia;
- abuso de privilegios;
- error humano;
- cuentas comprometidas.

### Credential Theft:

Consiste en obtener credenciales pertenecientes a otra persona.

```
Credential Theft
      ↓
Usuario + contraseña válidos
      ↓
Login aparentemente legítimo
      ↓
Compromiso de la cuenta
```

### Brute-Force Account Takeover:

Consiste en realizar repetidos intentos de autenticación hasta conseguir credenciales válidas y obtener control sobre una cuenta.

```
Password Guessing
      ↓
Intentos repetidos
      ↓
Credencial correcta
      ↓
ACCOUNT TAKEOVER
```

Las diapositivas relacionan explícitamente insider threats, credential theft y brute-force account takeovers.

## Mecanismos de seguridad X.800

### Security Mechanism:

Un mecanismo está diseñado para:

- detectar;
- prevenir;
- recuperarse

de un ataque.

Además, el profesor destaca que ningún mecanismo único proporciona todos los servicios necesarios y que las técnicas criptográficas sustentan muchos de ellos.

Los mecanismos mencionados son:

- Encipherment
- Data Integrity
- Digital Signature
- Authentication Exchange
- Traffic Padding
- Routing Control
- Notarization
- Access Control

### Encipherment:

Transforma información mediante criptografía.

### Data Integrity Mechanism:

Permite detectar o prevenir modificaciones.

### Digital Signature:

Mecanismo criptográfico asociado con autenticidad, integridad y no repudio.

### Authentication Exchange:

Intercambio de información destinado a comprobar identidad.

```
Entidad A
   ↓
Credential / Challenge
   ↓
Entidad B
   ↓
Verification
```

### Traffic Padding:

Introduce datos artificiales para dificultar el análisis del tráfico.

### Routing Control:

Selecciona o cambia rutas para dificultar el eavesdropping sobre una ruta concreta.

### Notarization:

Utiliza un tercero confiable que participa en el control de la comunicación.

### Access Control Mechanism:

Implementa reglas destinadas a restringir el acceso.

## Introducción a la criptografía vista en clase

### Encryption:

Conceptualmente:

$$ C=E(K,M) $$

donde:

- $M$ es el mensaje;
- $K$ es la clave;
- $E$ representa el proceso de cifrado;
- $C$ es el ciphertext.

Para recuperar el mensaje:

$$ M=D(K,C) $$

### Symmetric Encryption:

Utiliza conceptualmente una misma clave compartida.

```
Alice                        Bob
   │                          │
   └────── misma K ───────────┘
```

### Asymmetric Encryption:

Utiliza pares de claves.

```
Alice:
KA+
KA-

Bob:
KB+
KB-
```

Conceptualmente:

```
PUBLIC KEY
+
PRIVATE KEY
```

El desarrollo formal de estos algoritmos corresponde a unidades posteriores.

### Hash:

Una función hash produce un resumen:

$$ H(M)=h $$

```
MESSAGE
   ↓
HASH
   ↓
MESSAGE DIGEST
```

### Hash y Digital Signature:

Las anotaciones complementarias relacionan:

```
MESSAGE
   ↓
HASH
   ↓
DIGEST
   ↓
DIGITAL SIGNATURE
```

## ACK y conexiones nuevas

Un nuevo intento de conexión TCP suele comenzar:

```
SYN = 1
ACK = 0
```

Mientras que tráfico de una conexión existente normalmente contiene:

```
ACK = 1
```

Por ello un firewall stateless puede utilizar `ACK=0` como aproximación para detectar nuevos intentos de conexión desde Internet.

Esto no equivale a mantener el estado real de la conexión; un firewall stateful resulta más preciso.

## Fragmentación IP

Se parte de un datagrama total de:

$$ 4000\text{ bytes} $$

Header:

$$ 20\text{ bytes} $$

Data:

$$ 4000-20=3980\text{ bytes} $$

Si:

$$ MTU=1500\text{ bytes} $$

cada fragmento puede transportar:

$$ 1500-20=1480\text{ bytes de datos} $$

Por tanto:

$$ 3980=1480+1480+1020 $$

|Fragmento|Datos|Header|Total|
|---|---|---|---|
|1|$1480$|$20$|$1500$|
|2|$1480$|$20$|$1500$|
|3|$1020$|$20$|$1040$|

## Signature-Based IDS

### Funcionamiento:

```
1. SNIFF TRAFFIC
       ↓
2. COMPARE WITH SIGNATURES
       ↓
3. MATCH?
       ↓
4. WARN ADMINISTRATOR
```

### Signature:

Conjunto de reglas asociadas con una actividad típica de intrusión.

Ejemplos:

```
ICMP packet > 10,000 bytes
```

o:

```
>1000 SYN
a diferentes puertos
del mismo host
en menos de 1 segundo
```

### Configuración:

El administrador puede:

- excluir firmas;
- modificar parámetros;
- actualizar la base.

### Alertas:

Cuando una firma coincide pueden enviarse:

- email;
- SMS;
- mensajes a sistemas de administración de red.

### Limitaciones:

Necesita conocimiento previo.

```
Known attack
↓
Known signature
↓
Detection
```

Mientras que:

```
Unknown attack
↓
No signature
↓
Possible miss
```

Además, una base de firmas muy grande puede incrementar el procesamiento y hacer que el IDS pierda paquetes.

# Ideas fundamentales de la clase

La seguridad de la información debe entenderse como un proceso continuo de prevención, detección y corrección. Antes de seleccionar herramientas deben identificarse los activos, comprenderse el entorno de amenazas y determinarse los riesgos. La tecnología sólo resulta efectiva cuando se combina con políticas, capacitación, monitoreo, auditoría y respuesta.

Confidencialidad, integridad y disponibilidad forman la triada CIA y representan tres objetivos diferentes. Una violación puede revelar información, modificarla o impedir su acceso. Threat, vulnerability y attack tampoco son equivalentes: la amenaza representa una posibilidad, la vulnerabilidad representa una debilidad y el ataque representa la explotación deliberada.

Los servicios de seguridad describen qué protección debe proporcionar el sistema, mientras que los mecanismos explican cómo implementarla. Authentication, access control, confidentiality, integrity, non-repudiation y availability son servicios; encipherment, digital signature, authentication exchange, routing control, traffic padding y notarization son mecanismos.

La autenticación verifica identidad, la autorización determina permisos y auditing registra acciones. Juntas forman AAA. La autenticación puede basarse en posesión, conocimiento o biometría y puede reforzarse mediante MFA y OTP.

TCP/IP proporciona la base técnica para comprender la seguridad de red. Las aplicaciones generan mensajes, TCP y UDP utilizan puertos, IP utiliza direcciones, Ethernet utiliza frames y la información finalmente se transmite como bits. La encapsulación permite comprender qué campos puede observar cada dispositivo de seguridad.

TCP utiliza SYN, SYN-ACK y ACK para establecer conexiones. Una conexión full-open completa este proceso y una half-open queda incompleta. Esta diferencia permite comprender tanto ciertos tipos de escaneo como el SYN flood y la ventaja de un firewall stateful frente a un stateless.

IPv4 utiliza direcciones de $32$ bits y CIDR permite definir qué bits pertenecen al prefijo. El ejemplo `/29` permite comprender subnetting, network address, broadcast y hosts; `/32` representa un único host. Estos conceptos reaparecen directamente en ACL y Snort.

La fragmentación IP permite adaptar datagramas a una MTU determinada mediante DF, MF y fragment offset. Esta funcionalidad legítima puede convertirse en un problema de seguridad cuando un atacante manipula los fragmentos para dificultar el reensamblado de un IDS o consumir recursos.

Nmap representa reconnaissance: permite descubrir hosts, puertos y servicios antes de un posible ataque. Un IDS puede detectar estos patrones mediante firmas, flags TCP, behavioral analysis o Deep Packet Inspection. El atacante puede intentar evadir esta detección distribuyendo el escaneo temporalmente o utilizando múltiples orígenes.

Un IDS detecta y alerta; un IPS puede actuar automáticamente. Un HIDS observa el host y un NIDS observa la red. Los sistemas basados en firmas detectan patrones conocidos, mientras que los sistemas basados en anomalías comparan el comportamiento actual con un perfil normal. Los falsos positivos y falsos negativos representan errores diferentes que deben minimizarse.

Snort implementa de forma práctica muchos de estos conceptos mediante packet decoder, preprocessors, detection engine y alert generation. Sus reglas pueden incluir protocolos, IP, CIDR, puertos, rangos, direcciones, negación, flags TCP, tipos ICMP, fragment bits y contenido de aplicación.

Los firewalls traducen políticas de seguridad a reglas técnicas. Los stateless filters analizan paquetes de manera independiente, los stateful mantienen el estado de las conexiones y los application gateways funcionan como proxies. Las ACL se procesan de arriba hacia abajo y pueden variar por interfaz.

Una DMZ separa servicios públicos de la red interna. Firewall, IDS, IPS, DMZ y SIEM cumplen funciones complementarias: controlar tráfico, detectar amenazas, prevenir acciones, segmentar sistemas y correlacionar eventos.

Los ataques DoS comprometen principalmente availability. Pueden explotar vulnerabilidades, saturar connection queues o consumir bandwidth. SYN flood utiliza half-open connections, LAND falsifica origen y destino, Ping of Death utiliza tráfico anormalmente grande, Jolt2 abusa de fragmentación y DDoS distribuye el ataque entre numerosos bots.

Finalmente, los mismos protocolos que permiten la comunicación también crean estados, campos y comportamientos que un atacante puede aprovechar. Comprender seguridad de redes exige comprender simultáneamente cómo funciona la comunicación, cómo puede abusarse de ella, cómo puede detectarse ese abuso y qué mecanismos técnicos y organizacionales pueden utilizarse para reducir el riesgo.
