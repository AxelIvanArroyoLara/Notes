## Introducción

En módulos previos se ha llevado a cabo el estudio de la manera en la que la información atraviesa las capas de una red y la relación que esto tiene con amenazas como el phishing, malware, spoofing y DoS. Ahora bien, resulta necesario organizar estos conceptos dentro de un modelo de seguridad más integral.

El cuestionamiento principal dentro de este campo, yace en conocer cómo puede una organización comprender los ataques a los que se enfrenta para así seleccionar los servicios y mecanismos para llevar a cabo una defensa adecuada. Para responderlo, debe tomarse como base la **arquitectura de seguridad OSI**, la diferencia entre los ataques activos y pasivos, los servicios de seguridad, los mecanismos empleados para proporcionarlos, la planificación organizacional y los distintos métodos de autenticación disponibles.

## Tendencias en los Ataques

Una de las **tendencias** más relevantes en el estudio de la ciberseguridad, es que la capacidad técnica necesaria para ejecutar ciertos ataques ha disminuido.

Esto no quiere decir que los ataques sean menos complejos. En realidad, sucede lo contrario: las herramientas son cada vez más poderosas, pero también más automatizadas y fáciles de utilizar.

Hace décadas, un atacante tenía que conocer profundamente:

- Programación.
- Sistemas operativos.
- Protocolos de red.
- Arquitectura de computadoras.
- Vulnerabilidades específicas.
- Creación manual de paquetes.

Actualmente existen herramientas, scripts y plataformas que automatizan muchas de esas tareas. Una persona con conocimientos limitados puede utilizar una herramienta creada por alguien más y ejecutar un ataque relativamente sofisticado.

Podemos representarlo de esta forma:

```
Capacidad de los ataques
         ▲
         │                         Herramientas modernas
         │                    ───────────────────────────
         │              ──────
         │        ──────
         │  ──────
         └──────────────────────────────────────────────► tiempo

Conocimiento necesario para utilizarlas
         ▲
         │  ──────
         │        ──────
         │              ──────
         │                    ───────────────────────────
         └──────────────────────────────────────────────► tiempo
```

La capacidad del ataque puede aumentar mientras la barrera de entrada disminuye.

Esto da lugar a los llamados _script kiddies_: usuarios que ejecutan herramientas o scripts creados por otras personas sin comprender completamente su funcionamiento. Aunque su conocimiento sea limitado, las consecuencias de sus acciones pueden ser graves.

No debemos concluir que las herramientas de seguridad sean malas. Nmap, Wireshark o Kali Linux tienen usos legítimos en administración, diagnóstico y pruebas autorizadas. El problema depende de la autorización, el propósito y el sistema sobre el cual se utilicen.

## Reconocimiento

Antes de lanzar un ataque, el adversario normalmente necesita obtener información sobre su objetivo. A esta etapa se le llama **reconocimiento**.

El atacante quiere contestar preguntas como:

- ¿Qué equipos están conectados?
- ¿Qué direcciones IP responden?
- ¿Qué puertos están abiertos?
- ¿Qué servicios se ejecutan?
- ¿Qué versiones de software se utilizan?
- ¿Qué sistema operativo podría estar instalado?
- ¿Existen vulnerabilidades conocidas?

Una herramienta de barrido o _sweeper_ puede examinar muchas direcciones IP para descubrir cuáles corresponden a equipos activos.

```
Rango de direcciones:

192.168.1.1   → responde
192.168.1.2   → no responde
192.168.1.3   → responde
192.168.1.4   → responde
192.168.1.5   → no responde
```

Después se puede realizar un escaneo de puertos:

```
Equipo 192.168.1.3

Puerto 22   → abierto → posiblemente SSH
Puerto 53   → abierto → posiblemente DNS
Puerto 80   → abierto → posiblemente HTTP
Puerto 443  → abierto → posiblemente HTTPS
Puerto 3306 → cerrado
```

Esta información permite construir un mapa de la red.

```
Descubrir equipos
       │
       ▼
Descubrir puertos
       │
       ▼
Identificar servicios y versiones
       │
       ▼
Buscar vulnerabilidades
       │
       ▼
Intentar explotar una vulnerabilidad
```

El escaneo no siempre es un ataque. Un administrador puede escanear su propia red para crear un inventario y encontrar servicios que deberían estar cerrados. Sin embargo, cuando una persona no autorizada lo hace para preparar una intrusión, forma parte del reconocimiento ofensivo.

Nmap es una herramienta común para descubrir equipos, puertos y servicios. Wireshark, en cambio, permite capturar y analizar tráfico. Aunque ambas pueden ayudar a comprender una red, sus funciones principales son diferentes:

```
Nmap      → envía consultas para descubrir equipos y servicios.
Wireshark → observa y analiza paquetes que pasan por una interfaz.
```
### Problema de los Puertos:

Una medida básica de seguridad consiste en cerrar los puertos que no se necesitan. Sin embargo, una organización no puede cerrar todos sus puertos porque algunos son indispensables para proporcionar servicios.

Por ejemplo:

```
DNS    → puerto 53
HTTP   → puerto 80
HTTPS  → puerto 443
SMTP   → puerto 25, entre otros
FTP    → puertos 20 y 21 en su funcionamiento tradicional
```

Si una empresa cierra el puerto 443 de su servidor web, reduce la superficie de ataque, pero también impide que sus clientes utilicen el sitio HTTPS.

Esto genera un problema fundamental:

> Un servicio público tiene que ser accesible, pero precisamente por ser accesible también queda expuesto a solicitudes maliciosas.

La solución no es dejarlo completamente abierto ni cerrarlo por completo. Se deben establecer controles que permitan el tráfico legítimo y reduzcan el tráfico peligroso.

## Arquitectura de una Red Empresarial

Una red empresarial normalmente se organiza de la siguiente manera:

```
                          INTERNET
                              │
                              ▼
                    ┌──────────────────┐
                    │ Router/Firewall  │
                    │       ACL        │
                    └────────┬─────────┘
                             │
                 ┌───────────┴────────────┐
                 │                        │
                 ▼                        ▼
        ┌────────────────┐       ┌────────────────────┐
        │   Red interna  │       │        DMZ         │
        │      LAN       │       │                    │
        │ PCs, impresoras│       │ DNS    Web    SMTP │
        │ sistemas internos      │ FTP    otros       │
        └────────────────┘       └────────────────────┘
```
En donde se tienen componentes como:

### LAN:

LAN significa _Local Area Network_. Es la red interna donde se encuentran los equipos de usuarios, impresoras y otros recursos organizacionales.

La LAN no debe quedar directamente expuesta a Internet.

### DMZ:

DMZ significa _Demilitarized Zone_ o zona desmilitarizada. Es una red separada donde se colocan servicios que deben aceptar conexiones desde Internet.

Ejemplos:

- Servidor web.
- Servidor DNS público.
- Servidor de correo.
- Gateway de VPN.
- Proxy inverso.

La DMZ no es una zona “sin protección”. Es una zona expuesta, pero aislada y controlada.

Su objetivo es evitar que un servidor público comprometido proporcione acceso directo a la red interna.

```
Internet puede comunicarse con el servidor web de la DMZ.

Internet no debería poder comunicarse directamente
con las computadoras internas.

El servidor web de la DMZ solamente debería acceder
a los recursos internos estrictamente necesarios.
```

Por ejemplo, un servidor web puede necesitar consultar una base de datos, pero esa comunicación debe limitarse a una dirección y un puerto específicos. No debe obtener acceso general a toda la LAN.

### Router:

Un router permite que los paquetes pasen de una red a otra. Examina las direcciones IP de destino y selecciona una ruta.

Su función principal es el encaminamiento, no la protección completa de la organización.

### Firewall:

Un firewall decide qué tráfico puede atravesar un punto de la red.

Ejemplos de reglas:

```
Permitir conexiones HTTPS hacia el servidor web.
Bloquear conexiones de Internet hacia las computadoras internas.
Permitir DNS hacia el servidor DNS público.
Bloquear el acceso externo a la base de datos.
```

Un firewall no bloquea automáticamente todo el malware. Puede impedir ciertas comunicaciones o inspeccionar determinado tráfico, pero un archivo malicioso todavía podría llegar mediante una conexión permitida, por ejemplo, a través de HTTPS o correo electrónico.

Por eso se necesitan diferentes controles:

```
Firewall + antimalware + filtrado de correo + IDS/IPS
+ actualizaciones + autenticación + capacitación
```

### ACL:

ACL significa _Access Control List_ o lista de control de acceso. Es un conjunto ordenado de reglas que permite o deniega ciertas comunicaciones.

Una ACL puede considerar:

- Dirección IP de origen.
- Dirección IP de destino.
- Protocolo.
- Puerto de origen.
- Puerto de destino.
- Dirección de la comunicación.

Ejemplo conceptual:

```
1. Permitir TCP desde Internet hacia 203.0.113.10 puerto 443.
2. Permitir UDP hacia 203.0.113.20 puerto 53.
3. Bloquear cualquier tráfico de Internet hacia la LAN.
```

Las ACL también pueden aplicarse a archivos, sistemas y otros recursos, pero en el contexto del pizarrón se relacionan principalmente con el filtrado de red.

### Punto de colocación para un IDS:

Un sistema IDS tiene la capacidad de observar el tráfico desde diferentes puntos de una red:

```
Internet
   │
Firewall
   │
   ├──────── Sensor IDS ───────► analiza tráfico del perímetro
   │
   ├──────── LAN
   │
   └──────── DMZ
                │
                ├── servidor web
                ├── servidor DNS
                ├── servidor SMTP
                └── servidor FTP
```

En este caso, un **Network IDS** analiza el tráfico que atraviesa un segmento determinado, pudiendo colocarse:

- Cerca del perímetro.
- Entre el firewall y la DMZ.
- Entre la DMZ y LAN.
- En segmentos internos importantes.

O bien, puede colocarse también un **Host IDS** en cada servidor para el análisis de eventos del propio equipo:

- Cambios en archivos.
- Intentos de inicio de sesión.
- Procesos.
- Registros del sistema.
- Modificaciones en configuraciones.

En este caso, no siempre resulta necesaria la instalación de un NIDS independiente en cada servidor, sino que puede existir un sensor capaz de observar todo el segmento DMZ acompañado además por agentes o controles específicos en los hosts más relevantes.

Ahora bien, cabe destacar que el DNS no necesariamente convierte todo ataque en una firma, sino que estas vienen preconfiguradas por los proveedores:

```
Tráfico observado
       │
       ▼
Comparación con firmas conocidas
       │
       ├── coincide → alerta
       └── no coincide → continúa el análisis
```

El IDS puede guardar paquetes, eventos y alertas para que un analista los estudie. Algunos sistemas avanzados pueden aprender comportamientos o generar reglas con asistencia, pero no debemos asumir que todo ataque observado se convierte automáticamente en una firma correcta.

## Tecnologías y Mecanismos de Seguridad

A lo largo de los temas previos se ha analizado una serie de mecanismos y tecnologías:

- Firewalls.
- Antimalware.
- ACL de servidor.
- IDS e IPS.
- SIEM.
- Cifrado.
- Contraseñas de un solo uso.
- MFA.
- Herramientas forenses.
- Analítica de comportamiento.
- PKI.
- Sistemas de seguridad inalámbrica.
- Biometría.
- Inteligencia artificial.
- Seguridad de IoT.
- Blockchain.
- Seguridad en la nube.

Estas tecnologías no realizan exactamente la misma función.

### SIEM:

Un **Security Information and Event Management** es un sistema encargado de centralizar todos los registros producidos por una gran cantidad de sistemas:

```
Firewall ───────┐
Servidor ───────┤
IDS ────────────┤
Antivirus ──────┼────► SIEM ───► correlación y alertas
Aplicaciones ───┤
Autenticación ──┘
```

Asúmase que el sistema SIEM observa:

1. Muchos intentos fallidos de inicio de sesión.
2. Un inicio de sesión exitoso desde una ubicación inusual.
3. Una descarga masiva de archivos.
4. La desactivación de un agente de seguridad.

Por separado, cada uno de estos eventos podría llegar a parecer poco concluyente, pero juntos pueden indicar que la seguridad ha sido comprometida.

### Analítica de comportamiento:

La analítica de comportamiento busca identificar desviaciones respecto del comportamiento normal.

Ejemplo:

```
Comportamiento habitual:
Alice accede de lunes a viernes, desde México, entre 8:00 y 18:00.

Evento anómalo:
La cuenta de Alice descarga 20 GB a las 3:00 desde otro país.
```

Una anomalía no demuestra por sí sola que ocurrió un ataque. Solo señala que el evento merece investigación.

## Amenaza y Ataque

En lenguaje cotidiano, amenaza y ataque pueden parecer sinónimos, pero en seguridad representan ideas diferentes.

### Amenaza:

Una amenaza es una posibilidad de que ocurra una violación de seguridad.

Ejemplos:

- Existe malware capaz de explotar una vulnerabilidad.
- Una inundación puede dañar el centro de datos.
- Un empleado podría copiar información.
- Un atacante podría robar una contraseña.

La amenaza todavía no tiene que haberse materializado.

### Ataque:

Un ataque es una acción deliberada que intenta evadir los controles y violar la política de seguridad.

Ejemplos:

- El atacante envía el archivo malicioso.
- Se utilizan credenciales robadas.
- Se altera una transferencia.
- Se inunda un servidor con solicitudes.

```
Amenaza
    │
    │ encuentra una vulnerabilidad
    ▼
Posibilidad de daño
    │
    │ alguien la ejecuta
    ▼
Ataque
```

Una forma sencilla de recordarlo es:

```
Amenaza = podría ocurrir.
Ataque  = alguien intenta hacerlo realidad.
```
#### Ataques pasivos

En un **ataque pasivo**, el adversario intenta obtener información sin modificar los datos ni afectar directamente el sistema.

El atacante observa, escucha o analiza.

Las dos categorías principales son:

1. Obtención del contenido de los mensajes.
2. Análisis del tráfico.

##### Obtención del contenido

El atacante intenta leer la información transmitida.

```
Alice ───────── mensaje ─────────► Bob
                    │
                    ▼
                  Trudy
             lee el contenido
```

Si el mensaje no está cifrado, podría revelar:

- Contraseñas.
- Correos electrónicos.
- Documentos.
- Números de tarjetas.
- Información médica.
- Conversaciones privadas.

Este ataque compromete principalmente la **confidencialidad**.

##### Análisis de tráfico

Aunque el contenido esté cifrado, el atacante todavía puede observar ciertos metadatos:

- Quién se comunica con quién.
- A qué hora.
- Con qué frecuencia.
- Cuánto duran las conexiones.
- Cuántos datos se transfieren.
- Qué direcciones participan.

###### Ejemplo:

Un adversario no puede leer los mensajes cifrados entre una embajada y una base militar, pero observa un aumento repentino en la cantidad de comunicaciones. Ese patrón podría revelar que está ocurriendo un evento importante.

Los ataques pasivos no cambian los datos. Si el adversario se limita a escuchar una señal o copiar paquetes, puede no dejar rastros visibles en los sistemas de Alice y Bob.

No debe implicarse que son absolutamente imposibles de detectar, porque algunas formas de interceptación requieren cambios en la red que sí pueden generar indicios. Sin embargo, la escucha puramente pasiva es especialmente difícil de descubrir.

Por esta razón, la defensa principal consiste en impedir que la información observada sea útil:

- Cifrado.
- Protección física.
- Redes seguras.
- Control del acceso a medios.
- Ocultamiento de patrones.
- Relleno de tráfico.

#### Ataques activos

En un ataque activo, el adversario altera datos, introduce mensajes o afecta el funcionamiento del sistema.

La clasificación presentada en X.800 incluye cuatro categorías:

1. Masquerade o suplantación.
2. Replay o repetición.
3. Modificación de mensajes.
4. Denegación de servicio.

##### Masquerade

_Masquerade_ significa que una entidad pretende ser otra.

```
Trudy ──“Soy el banco”──► Alice
```

Ejemplos:

- Un sitio falso se presenta como el banco.
- Un atacante utiliza una cuenta robada.
- Un correo falso aparenta provenir del director.
- Un servidor falso suplanta a uno legítimo.

Se relaciona con spoofing, robo de credenciales y phishing.

##### Replay

En un ataque de repetición, el adversario captura una unidad de datos válida y la transmite posteriormente para provocar un efecto no autorizado.

Supongamos que un sistema abre una puerta al recibir:

```
Usuario: Alice
Acción: abrir puerta
Código: 749201
```

Trudy captura el mensaje y lo retransmite más tarde:

```
Alice ─── mensaje válido ───► puerta
                 │
                 └──► Trudy guarda una copia

Más tarde:

Trudy ─── mismo mensaje ───► puerta
```

Aunque Trudy no comprenda o modifique el mensaje, podría conseguir que la acción se repita.

Las defensas incluyen:

- Números únicos o _nonces_.
- Marcas de tiempo.
- Números de secuencia.
- Contraseñas de un solo uso.
- Ventanas de validez.
- Protocolos que rechazan mensajes repetidos.

##### Modificación de mensajes

El atacante cambia alguna parte de un mensaje:

```
Mensaje original:
“Transferir $100 a Bob”

Mensaje modificado:
“Transferir $900 a Trudy”
```

También puede:

- Eliminar mensajes.
- Reordenarlos.
- Retrasarlos.
- Insertar información.
- Cambiar campos de control.

Este ataque afecta principalmente la integridad.

##### Denegación de servicio

La denegación de servicio impide o dificulta el uso normal de una instalación de comunicaciones.

Puede:

- Saturar la red.
- Agotar conexiones.
- Bloquear una aplicación.
- Consumir memoria o CPU.
- Interrumpir un enlace.
- Destruir o cifrar recursos.

Su objetivo principal es comprometer la disponibilidad.

### Prevención y detección de ataques pasivos y activos:

Los ataques pasivos y activos requieren prioridades defensivas diferentes.

|Tipo|Característica|Prioridad defensiva|
|---|---|---|
|Pasivo|Observa sin modificar|Prevenir que la información sea comprensible|
|Activo|Modifica o interrumpe|Detectar, limitar y recuperarse|

Para un ataque pasivo, el cifrado es especialmente importante. Aunque el atacante capture los datos, no debería entenderlos.

Para un ataque activo, impedir absolutamente todas las acciones puede resultar imposible. Por eso se necesitan:

- Autenticación.
- Integridad.
- Monitoreo.
- Registros.
- IDS/IPS.
- Redundancia.
- Recuperación.
- Respuesta a incidentes.

## Alice, Bob y Trudy

En seguridad de redes es habitual representar una comunicación mediante tres personajes:

- **Alice:** la emisora legítima.
- **Bob:** el receptor legítimo.
- **Trudy:** la intrusa.

```
              Canal de comunicación

Alice ─────────────────────────────────► Bob
   │                                       │
   │            Trudy puede:               │
   │                                       │
   ├── interceptar                         │
   ├── copiar                              │
   ├── eliminar                            │
   ├── modificar                           │
   ├── retrasar                            │
   └── agregar mensajes                    │
```

Si Trudy solo escucha, el ataque es pasivo. Si cambia, elimina, añade o retransmite mensajes, realiza un ataque activo.

Este modelo permite pensar en las propiedades que Alice y Bob necesitan:

- Confidencialidad para que Trudy no lea.
- Integridad para que no modifique.
- Autenticación para reconocer al otro extremo.
- Protección contra replay.
- Disponibilidad para mantener el canal funcionando.

## Texto Plano y Cifrado

Para lograr la confidencialidad de un mensaje, el emisor puede aplicar una transformación criptográfica:

```
Texto plano                    Texto cifrado
     M                              C
     │                              │
     ▼                              ▼
[Mensaje legible] ──cifrado──► [Datos no comprensibles]
```

Que puede ser representado mediante la expresión:

$$C=E(K,M)$$

En donde:

- `M` es el mensaje original.
- `K` es la clave.
- `E` es el algoritmo de cifrado.
- `C` es el texto cifrado.

Bob realiza la operación inversa:


$$M = D(K, C)$$


Donde `D` es el algoritmo de descifrado.

Trudy puede interceptar `C`, pero no debería poder obtener `M` sin la clave correspondiente.

### Cifrado simétrico:

En esta forma de cifrado, Alice y Bob utilizan una misma clave secreta o directamente relacionada:

```
                clave secreta K
                     │
Alice                │                 Bob
  │                  │                   │
  └── M ─► cifrar ─► C ─► descifrar ─► M
          con K              con K
```

$$C = E(K, M)$$
$$M = D(K, C)$$
En donde cada expresión expresa las operaciones para Alice y Bob individualmente.

Este sistema es ventajoso dado que suele ser rápido y eficiente para manipular grandes cantidades de información; sin embargo, en caso de que la clave secreta se comparta en un mismo canal inseguro, esta podría ser interceptada; la gestión y distribución de claves son partes fundamentales para el funcionamiento del sistema.

### Cifrado asimétrico:

En la **criptografía asimétrica**, cada participante cuenta con dos claves distintas: una pública y otra privada.

En un caso que requiere mantener la confidencialidad, Alice cifra el mensaje utilizando la clave pública de Bob:

```
Alice                         Bob

Mensaje M
    │
    ▼
Clave pública de Bob
    │
    ▼
Texto cifrado C ───────────► clave privada de Bob
                                      │
                                      ▼
                                  mensaje M
```

En donde las operaciones:

$$C = E(K \space \text{pública de Bob}, M)$$
$$M = D(K \space \text{privada de Bob}, C)$$
En donde:
- `M` es el mensaje original.
- `K` es la clave.
- `E` es el algoritmo de cifrado.
- `C` es el texto cifrado.
- `D` es el algoritmo de desencriptado.

Como su nombre lo indica, la clave pública puede ser distribuida, pero la privada debe mantenerse en secreto obligatoriamente.

#### Firma

El cifrado suele realizarse dependiendo de las condiciones requeridas:

- **Confidencialidad:** Se cifra con la clave pública del receptor y se descifra con la clave privada del receptor.
- **Firma digital:** El emisor firma con su clave privada, y los demás verifican con la clave pública de este mismo.

#### Claves públicas falsas

Si bien, una clave pública no debe mantenerse oculta, siempre debe asegurarse que esta sea auténtica.

Supóngase que Alice solicita la clave pública de Bob y Trudy sustituye la respuesta recibida:

```
Alice solicita clave de Bob
             │
             ▼
Trudy responde con su propia clave pública
             │
             ▼
Alice cree que pertenece a Bob
```

Este mensaje es cifrado con la clave de Trudy; por lo tanto, este intruso puede descifrarlo, leerlo y volver a cifrarlo para reenviarlo a Bob. Esto es un ataque *man in the middle*.

Para prevenir una situación como esta, se requiere asociar correctamente una identidad con la clave pública a través de:

- Certificados digitales.
- Autoridades certificadoras.
- PKI.
- Verificación de huellas.
- Canales confiables.

Un ataque de DNS spoofing puede dirigir a Alice hacia un servidor falso, pero si utiliza HTTPS correctamente, el navegador validará el certificado, obligando al atacante a presentar uno válido o lograr que la víctima ignore las advertencias.

## Servicios de Seguridad

Un **servicio de seguridad** es una función de procesamiento o comunicación que proporciona un tipo específico de protección a los recursos de un sistema.

Un servicio responde:

> ¿Qué propiedad queremos proporcionar?

Un mecanismo responde:

> ¿Qué técnica utilizaremos para proporcionarla?

La clase presenta seis servicios principales:

1. Autenticación.
2. Control de acceso.
3. Confidencialidad.
4. Integridad.
5. No repudio.
6. Disponibilidad.

### Autenticación:

La autenticación comprueba una identidad o el origen de ciertos datos.

Puede intentar responder:

- ¿Quién está iniciando sesión?
- ¿El servidor es realmente el banco?
- ¿Este mensaje provino de Alice?
- ¿Este dispositivo está autorizado?

Mecanismos:

- Contraseñas.
- Certificados.
- Tokens.
- Biometría.
- MFA.
- Firmas o códigos de autenticación.

Debe distinguirse entre autenticación de una persona y autenticación del origen de un mensaje. Ambas buscan comprobar identidad u origen, pero operan en contextos diferentes.

### Control de acceso:

El control de acceso determina quién puede utilizar un recurso y qué operaciones puede realizar.

```
Alice se autentica correctamente.
              │
              ▼
El sistema consulta sus permisos.
              │
       ┌──────┴───────┐
       │              │
       ▼              ▼
Leer archivo      Modificar archivo
permitido          denegado
```

Los mecanismos incluyen:

- ACL.
- Roles.
- Permisos.
- Políticas.
- Reglas de firewall.
- Principio de mínimo privilegio.

Autenticarse no significa recibir acceso ilimitado.

### Confidencialidad:

La confidencialidad protege los datos contra su divulgación no autorizada.

Puede proteger:

- El contenido completo de un mensaje.
- Campos específicos.
- Archivos almacenados.
- Comunicaciones.
- Incluso ciertos patrones de tráfico.

Mecanismos:

- Cifrado.
- Permisos.
- Redes privadas.
- Controles físicos.
- Traffic padding.

---

### Integridad:

La integridad busca garantizar que los datos no sean modificados sin autorización.

Puede aplicarse:

- A un mensaje.
- A una secuencia de mensajes.
- A un archivo.
- A una base de datos.
- A la configuración de un sistema.

Mecanismos:

- HMAC.
- Firmas digitales.
- Hashes autenticados.
- Controles de cambios.
- Registros.
- Restricciones de permisos.

Un hash aislado no autentica al emisor, porque cualquiera puede calcular otro hash después de modificar los datos.

### No repudio:

El término correcto es **no repudio**, no “non-retaliation”.

Este servicio proporciona evidencia que dificulta que una de las partes niegue una acción.

Puede proteger contra:

- El emisor que niega haber enviado un mensaje.
- El receptor que niega haberlo recibido.
- Una persona que niega haber aprobado una operación.

Mecanismos:

- Firmas digitales.
- Sellos de tiempo.
- Certificados.
- Registros protegidos.
- Terceros confiables.

No repudio no es sinónimo de autenticación. La autenticación comprueba una identidad durante una interacción; el no repudio intenta conservar evidencia verificable para una posible disputa posterior.

### Disponibilidad:

La disponibilidad busca que los sistemas y datos puedan utilizarse cuando las personas autorizadas los necesiten.

Amenazas:

- DoS y DDoS.
- Ransomware.
- Fallas eléctricas.
- Errores humanos.
- Desastres.
- Sabotaje.
- Fallas de hardware.
- Actualizaciones defectuosas.

Mecanismos:

- Redundancia.
- Respaldos.
- Balanceo de carga.
- Sistemas alternativos.
- Protección DDoS.
- Recuperación ante desastres.
- Mantenimiento.
- Monitoreo.

---

## Mecanismos de Seguridad

Un **mecanismo de seguridad** se define como una característica especialmente diseñada para llevar a cabo la detección, prevención o recuperación de un ataque. 

Ahora bien, cabe destacar que no existe un mecanismo único capaz de lograr proporcionar todos estos servicios:

```
Una organización segura no depende de:

“un firewall”
“un antivirus”
“un algoritmo”
“una contraseña”

Depende de varias capas coordinadas.
```

Por ejemplo, la criptografía sustenta muchos mecanismos, pero tampoco resuelve todos los problemas. No impide por sí sola que un empleado autorizado copie información, que un servidor deje de funcionar o que alguien revele voluntariamente su contraseña.

### Cifrado:

_Encipherment_ significa cifrado. Transforma datos utilizando un algoritmo y una clave para proteger su confidencialidad.

Puede utilizarse:

- En comunicaciones.
- En discos.
- En archivos.
- En respaldos.
- En bases de datos.

El cifrado debe acompañarse de gestión de claves. Un algoritmo fuerte no sirve si la clave se almacena en un archivo público o se comparte inseguramente.

### Firma digital:

Una firma digital relaciona un mensaje con una clave privada.

Puede proporcionar:

- Autenticidad del origen.
- Integridad.
- Apoyo al no repudio.

No proporciona confidencialidad por sí sola. Un mensaje firmado puede seguir siendo visible. Si también se necesita confidencialidad, debe cifrarse.

### Intercambio de autenticación:

El intercambio de autenticación es un protocolo mediante el cual dos entidades demuestran su identidad.

Puede utilizar:

- Contraseñas.
- Retos y respuestas.
- Certificados.
- Nonces.
- Tokens.
- Claves criptográficas.

Un reto y respuesta evita enviar directamente un secreto reutilizable:

```
Servidor ───── reto aleatorio ─────► cliente
Servidor ◄── respuesta calculada ─── cliente
```

El reto debe cambiar para evitar ataques de replay.

### Traffic padding:

_Traffic padding_ consiste en introducir tráfico o datos de relleno para dificultar el análisis de patrones.

Supongamos que Alice solo envía mensajes cuando ocurre una emergencia. Trudy no puede leerlos porque están cifrados, pero sabe que cada aumento de tráfico significa que algo ocurrió.

Alice podría enviar tráfico de relleno incluso cuando no hay una emergencia:

```
Tráfico real:      ███         █████
Tráfico observado: █████████████████████
```

Esto no busca engañar sobre el contenido del mensaje, sino reducir la información que puede obtenerse observando volumen, tiempos y frecuencia.

Tiene un costo: consume ancho de banda y recursos.

### Routing control:

El **control de rutas** permite seleccionar rutas consideradas seguras o modificar el camino cuando se detectan problemas.

No significa necesariamente cambiar las rutas continuamente sin motivo. La idea es contar con control sobre el camino seguido por la información.

Ejemplos:

- Evitar una red considerada insegura.
- Utilizar enlaces privados para datos sensibles.
- Cambiar de ruta después de detectar una interceptación.
- Mantener rutas alternativas para disponibilidad.

### Notarización:

La **notarización** utiliza un tercero confiable para proporcionar evidencia o supervisar una operación.

Es similar a un notario en el mundo físico.

El tercero puede:

- Confirmar la hora de una transacción.
- Registrar que un documento existía.
- Certificar la identidad de una parte.
- Conservar evidencia.
- Participar en la resolución de disputas.

Ejemplos tecnológicos:

- Autoridades certificadoras.
- Servicios de sello de tiempo.
- Registros auditables.
- Entidades certificadoras de transacciones.

---
## Relación entre Servicios y Mecanismos

| Servicio          | Mecanismos posibles                           |
| ----------------- | --------------------------------------------- |
| Autenticación     | Contraseñas, certificados, biometría, tokens  |
| Control de acceso | ACL, roles, permisos, firewall                |
| Confidencialidad  | Cifrado, traffic padding                      |
| Integridad        | HMAC, firmas digitales, controles de cambios  |
| No repudio        | Firmas, sellos de tiempo, notarización        |
| Disponibilidad    | Redundancia, rutas alternativas, recuperación |

Un mismo mecanismo puede apoyar varios servicios. Por ejemplo, una firma digital puede proporcionar autenticidad, integridad y evidencia para el no repudio.

La seguridad no es solamente un problema técnico. Es también un problema de gestión.

Una organización puede comprar las mejores herramientas y continuar siendo vulnerable si:

- Nadie revisa las alertas.
- No existen responsables definidos.
- Los empleados no reciben capacitación.
- Las cuentas antiguas no se eliminan.
- Los respaldos nunca se prueban.
- Los parches no se instalan.
- No existe un plan de respuesta.
- Los permisos se conceden sin control.

La tecnología solo funciona dentro de procesos adecuados.

## Ciclo Plan–Protect–Respond

La seguridad debe administrarse como un ciclo continuo:

```
          ┌─────────┐
          │  PLAN   │
          └────┬────┘
               │
               ▼
          ┌─────────┐
          │ PROTECT │
          └────┬────┘
               │
               ▼
          ┌─────────┐
          │ RESPOND │
          └────┬────┘
               │
               └──────────► regresar a PLAN
```

### Plan:

Se identifican:

- Activos.
- Riesgos.
- Amenazas.
- Vulnerabilidades.
- Responsables.
- Políticas.
- Prioridades.
- Requisitos legales y operativos.

### Protect:

Se aplican controles:

- Firewalls.
- Cifrado.
- MFA.
- IDS/IPS.
- Capacitación.
- Parches.
- Respaldos.
- Segmentación.
- Políticas.

Esta fase suele consumir gran parte del tiempo de gestión porque los controles deben mantenerse y revisarse constantemente.

### Respond:

Cuando ocurre un incidente, se debe:

- Detectarlo.
- Contenerlo.
- Eliminar la causa.
- Recuperar los sistemas.
- Notificar a las partes correspondientes.
- Investigar.
- Aprender del evento.

Después se regresa a la planificación para corregir las debilidades encontradas.

## ISO/IEC 27001 e ISMS

ISMS significa _Information Security Management System_ o sistema de gestión de seguridad de la información.

No es un programa informático. Es un conjunto coordinado de:

- Políticas.
- Responsabilidades.
- Procesos.
- Evaluaciones de riesgo.
- Controles.
- Auditorías.
- Mejora continua.

ISO/IEC 27001 establece requisitos para crear, implementar, mantener y mejorar continuamente un ISMS. Su enfoque es administrar riesgos y proteger la confidencialidad, integridad y disponibilidad de la información. La edición vigente continúa siendo ISO/IEC 27001:2022. [Familia ISO/IEC 27000](https://www.iso.org/standard/iso-iec-27000-family).

El objetivo no es instalar todos los controles posibles, sino seleccionar controles adecuados y proporcionales a los riesgos de la organización.

## AAA: Autenticación, Autorización y Auditoría

El plan de seguridad incluye tres funciones conocidas como AAA.

### Authentication:

La autenticación comprueba la identidad.

```
“¿Quién eres?”
```

### Authorization:

La autorización determina qué puede hacer la identidad autenticada.

```
“¿Qué tienes permitido hacer?”
```

### Auditing:

La auditoría registra las acciones para analizarlas posteriormente.

```
“¿Qué hiciste, cuándo y desde dónde?”
```

En muchos textos, la tercera A significa _Accounting_, que registra y mide el uso de recursos. La diapositiva utiliza _Auditing_. Ambas ideas se relacionan con la conservación de registros, aunque no son exactamente idénticas.

Ejemplo:

```
Alice escribe su contraseña.
→ autenticación

El sistema permite que consulte expedientes, pero no que los elimine.
→ autorización

El sistema registra la consulta, la hora y el expediente abierto.
→ auditoría
```

## Modelo de Seguridad de Red

El modelo presentado incluye un emisor, un receptor, un canal inseguro y un adversario:

```
                  Trudy
                    │
                    ▼
Alice ── transformación ── canal ── transformación ──► Bob
              ▲                            ▲
              │                            │
            clave                        clave
```

Para construir un sistema seguro se necesitan cuatro elementos.

### 1. Diseñar o seleccionar una transformación adecuada:

Puede tratarse de:

- Cifrado.
- Firma digital.
- HMAC.
- Protocolo de autenticación.

No es recomendable inventar algoritmos criptográficos propios. Normalmente se seleccionan algoritmos estandarizados y analizados públicamente.

### 2. Generar las claves:

Las claves deben generarse con suficiente aleatoriedad. Una clave predecible destruye la seguridad aunque el algoritmo sea fuerte.

### 3. Distribuir y compartir las claves:

Se necesita un método seguro para entregar las claves a quienes deben utilizarlas.

Opciones:

- Intercambio de claves.
- Certificados.
- Canales físicos.
- Servidores de gestión de claves.
- Terceros confiables.

### 4. Definir un protocolo:

El protocolo especifica:

- Qué se envía.
- En qué orden.
- Qué claves se utilizan.
- Cómo se validan los mensajes.
- Qué sucede si algo falla.
- Cómo se evita un replay.

No basta con decir “usaremos cifrado”. Es necesario especificar todo el procedimiento.

## Modelo de Seguridad de Acceso de Red

Otro modelo se concentra en lograr impedir que un adversario acceda directamente a los recursos de un sistema:

```
Atacante
   │
   ▼
Canal de acceso
   │
   ▼
┌────────────────────┐
│ Función guardiana  │
│ autenticación, ACL │
│ firewall, IDS/IPS  │
└─────────┬──────────┘
          │
          ▼
┌────────────────────┐
│ Sistema protegido  │
│ datos, procesos,   │
│ software y recursos│
└────────────────────┘
```

Esta función **gatekeeper** es la encargada de decidir si una solicitud puede continuar. Para ello, se necesitan dos capacidades:

- Identificar usuarios a través de procedimientos apropiados.
- Monitorear la actividad para comprobar que solo puedan acceder a los recursos autorizados.

Un firewall o ACL no “identifica personas” necesariamente; puede identificar direcciones, conexiones y servicios. La autenticación de usuarios requiere mecanismos adicionales.

### Cifrado de datos:

Utiliza características humanas para identificar o verificar identidades.

## Autenticación

Las tres categorías tradicionales de autenticación pueden ser descritas por sus iniciales:

```
P = Possession  → algo que tienes
K = Knowledge   → algo que sabes
B = Biometrics  → algo que eres o haces
```

Algo que tienes:

- Llave.
- Pasaporte.
- Tarjeta bancaria.
- Smartcard.
- Token.
- Teléfono.

Algo que sabes:

- Contraseña.
- PIN.
- Frase de paso.

Datos que pueden identificar, pero que no siempre son verdaderos secretos:

- Nombre de usuario.
- Color favorito.
- Apellido de la madre.
- Respuestas a preguntas personales.

Muchas respuestas personales pueden descubrirse en redes sociales. Por ello, las preguntas de seguridad no deben considerarse un factor fuerte.

Algo que eres o haces:

- Huella.
- Rostro.
- Iris.
- Retina.
- Forma de la mano.
- ADN.

Características de comportamiento:

- Patrón de escritura.
- Forma de caminar.
- Voz.
- Movimiento de labios.
- Forma de utilizar un dispositivo.

### ## Identificación, verificación y autorización:

Estos conceptos suelen confundirse.

#### Identificación

La persona afirma una identidad:

```
“Soy Alice.”
```

#### Verificación o autenticación

El sistema comprueba si realmente es Alice:

```
“Demuestra que eres Alice.”
```

#### Autorización

Una vez autenticada, se determinan sus permisos:

```
“Alice puede consultar este archivo,
pero no modificarlo.”
```

En biometría existen dos usos principales:

```
Verificación 1:1
“¿Esta huella coincide con la huella registrada de Alice?”

Identificación 1:N
“¿A quién pertenece esta huella dentro de toda la base?”
```

La identificación suele ser más costosa porque debe comparar la muestra con muchas identidades.

### Autenticación multifactor:

La autenticación multifactor combina factores de categorías diferentes.

Ejemplos:

```
Tarjeta + PIN
posesión + conocimiento

Contraseña + aplicación autenticadora
conocimiento + posesión

Pasaporte + rostro
posesión + biometría
```

Dos contraseñas no forman MFA porque ambas son “algo que sabes”.

Dos dispositivos tampoco necesariamente representan factores distintos porque ambos pueden ser “algo que tienes”.

La fortaleza surge de combinar categorías diferentes, de modo que robar un factor no sea suficiente.

### Contraseñas de un solo uso:

Una **OTP** es una contraseña válida para una sola autenticación o durante un periodo muy corto.

Un token desconectado puede calcularla mediante:

```
Hora actual + secreto compartido + algoritmo
                         │
                         ▼
                    código temporal
```

El servidor realiza un cálculo compatible. Si el código coincide y está dentro de la ventana de tiempo, permite el acceso.

Como el código cambia, capturarlo tiene menos valor que capturar una contraseña permanente.

#### OTP mediante SMS

Enviar códigos por SMS es mejor que depender únicamente de una contraseña en muchos escenarios, pero tiene debilidades:

- Duplicación o transferencia fraudulenta de SIM.
- Interceptación.
- Malware en el teléfono.
- Phishing en tiempo real.
- Acceso indebido a mensajes.

Las aplicaciones autenticadoras y las llaves físicas resistentes al phishing pueden proporcionar mayor seguridad.

### Biometría:

La **biometría** identifica o verifica personas mediante características fisiológicas o conductuales.

Su proceso general es:

```
Persona
   │
   ▼
Sensor captura una muestra
   │
   ▼
Extracción de características
   │
   ▼
Plantilla biométrica
   │
   ▼
Comparación con plantilla almacenada
   │
   ▼
Puntuación de similitud
   │
   ▼
Aceptar o rechazar
```

El sistema normalmente no necesita guardar una fotografía completa. Puede guardar una plantilla que representa determinadas características.
 
La biometría no es una coincidencia perfecta: dos capturas de la misma huella o del mismo rostro no son idénticas. Puede cambiar:

- La iluminación.
- El ángulo.
- La presión.
- La posición.
- La calidad del sensor.
- El estado físico de la persona.

Por ello, la comparación produce una puntuación y se define un umbral.

Si el umbral es muy estricto, usuarios legítimos pueden ser rechazados. Si es muy flexible, impostores podrían ser aceptados.

#### Errores biométricos

##### Falso rechazo

El sistema rechaza a una persona legítima.

```
Alice auténtica → sistema dice “no es Alice”
```

Afecta la comodidad y disponibilidad.

##### Falsa aceptación

El sistema acepta a un impostor.

```
Trudy → sistema dice “es Alice”
```

Afecta directamente la seguridad.

Existe un compromiso:

```
Umbral más estricto
→ menos falsas aceptaciones
→ más falsos rechazos

Umbral más flexible
→ menos falsos rechazos
→ más falsas aceptaciones
```

La configuración adecuada depende del riesgo. Un teléfono personal y una instalación militar no necesariamente deben usar el mismo umbral.

#### Morphing biométrico

El _morphing_ combina características visuales de dos o más rostros para producir una imagen intermedia:

```
Rostro de Alice + rostro de Trudy
                 │
                 ▼
          imagen combinada
```

Si un sistema biométrico acepta esa imagen como documento de referencia, podría reconocer posteriormente a más de una persona como suficientemente parecida.

Este ataque se ha estudiado especialmente en documentos de identidad y sistemas de reconocimiento facial.

Las defensas incluyen:

- Detección de imágenes manipuladas.
- Captura supervisada.
- Comprobaciones de vida.
- Comparación con múltiples fuentes.
- Revisión humana.
- Protección del proceso de enrolamiento.

El enrolamiento es crítico. Si se registra una plantilla falsa desde el principio, un algoritmo preciso puede autenticar correctamente contra una identidad que ya fue contaminada.

## Cinco Pasos para Mejorar la Seguridad

### 1. Activos: ¿qué se debe proteger?

Un activo es algo valioso para la organización.

En un comercio electrónico:

- Datos de clientes.
- Direcciones.
- Números de tarjeta.
- Cuentas.
- Servidor web.
- Disponibilidad.
- Reputación.

### 2. Riesgos: ¿qué podría ocurrir?

Se analizan:

- Amenazas.
- Vectores.
- Vulnerabilidades.
- Probabilidad.
- Consecuencias.

Un vector de amenaza describe el camino utilizado.

Ejemplo:

```
Correo con archivo adjunto
          │
          ▼
Empleado abre el archivo
          │
          ▼
Malware explota una vulnerabilidad
```

### 3. Protección: ¿cómo se protegerán los activos?

Se crean políticas y controles:

- Firewalls.
- Cifrado.
- IDS/IPS.
- MFA.
- Respaldos.
- Segmentación.
- Capacitación.

### 4. Herramientas: ¿qué productos implementarán los controles?

Primero se define la política y después se seleccionan las herramientas.

No debe comprarse una herramienta solo porque es popular. Debe evaluarse si realmente satisface el requisito.

### 5. Prioridades: ¿en qué orden se actuará?

No todos los controles pueden implementarse al mismo tiempo. Debe atenderse primero lo que reduzca los riesgos más graves.

Por ejemplo, no sería razonable publicar un servidor web sin configurarlo, actualizarlo y protegerlo previamente.

## Construcción de una Organización Segura

La seguridad no es un producto. Es un proceso continuo.

Una organización segura debe:

1. Evaluar riesgos y amenazas.
2. Capacitar permanentemente al personal técnico.
3. Pensar creativamente sobre posibles ataques.
4. Capacitar a todos los empleados.
5. Utilizar las funciones de seguridad existentes.
6. Monitorear los sistemas.
7. Realizar auditorías independientes.
8. Mantener buenas prácticas básicas.
9. Instalar parches.

### Cultura de seguridad:

La seguridad no debe depender únicamente del departamento de TI.

Un empleado que detecta un correo sospechoso, un administrador que elimina una cuenta antigua y un directivo que financia respaldos están participando en la seguridad.

### Auditorías externas:

Un tercero puede encontrar problemas que el equipo interno no observa por familiaridad, falta de tiempo o conflictos de interés.

La auditoría no sustituye la responsabilidad interna. Complementa el proceso.

### Parches:

Los parches corrigen vulnerabilidades conocidas. Cuando se publica una corrección, los atacantes pueden estudiar el cambio para descubrir exactamente cuál era la falla.

Esto crea una carrera:

```
Se publica vulnerabilidad y parche
              │
       ┌──────┴────────┐
       │               │
Defensor actualiza   Atacante busca sistemas
                     todavía vulnerables
```

Por eso “Patch, patch, patch” aparece como una recomendación central.

## Contraseñas: Longitud, Unicidad y Cambios

La frase del pizarrón transforma:

```
I like to eat imported cheese from Holland
```

en una contraseña basada en iniciales y sustituciones.

La intención es mostrar que una frase larga puede ayudar a crear una contraseña recordable. Sin embargo, una transformación predecible basada en iniciales y sustituciones comunes también puede ser adivinada por programas especializados.

Las recomendaciones más útiles son:

- Utilizar contraseñas largas.
- No reutilizarlas.
- Evitar frases conocidas.
- Emplear un administrador de contraseñas.
- Activar MFA.
- Bloquear intentos automatizados.
- Cambiar una contraseña cuando exista evidencia de compromiso.

La recomendación antigua de cambiar contraseñas obligatoriamente cada pocas semanas puede producir variaciones débiles como `ClaveAgosto1` y `ClaveSeptiembre2`. La orientación actual de NIST indica que no deben exigirse cambios periódicos arbitrarios, pero sí cuando exista evidencia de compromiso. [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html).

## Ejemplo Integrador: ataque contra una organización

Supongamos que Trudy quiere atacar una tienda en línea.

### Reconocimiento:

Trudy realiza un barrido y descubre:

```
203.0.113.10 → HTTPS, puerto 443
203.0.113.20 → DNS, puerto 53
203.0.113.30 → SMTP, puerto 25
```

### Selección del objetivo:

Encuentra que el servidor web utiliza una versión vulnerable.

### Ataque al perímetro:

El firewall permite el puerto 443 porque el sitio debe ser público. El tráfico llega al servidor web de la DMZ.

Esto demuestra que un puerto permitido no significa que todo su tráfico sea confiable.

### Detección:

El IDS identifica un patrón relacionado con la vulnerabilidad y genera una alerta. El SIEM correlaciona:

- La alerta del IDS.
- Errores del servidor.
- Una cuenta creada de forma inusual.
- Conexiones hacia una dirección externa.

### Contención:

El equipo de seguridad:

- Bloquea la dirección.
- Aísla el servidor.
- Activa un servidor alternativo.
- Cambia credenciales.
- Conserva evidencia.

### Recuperación:

Se reinstala o restaura el servidor desde una fuente confiable, se aplica el parche y se revisan otros equipos.

### Mejora:

La organización actualiza:

- Sus reglas de IDS.
- Su proceso de parches.
- La segmentación.
- Los permisos.
- El plan de respuesta.

El ciclo vuelve a comenzar:

```
Plan ─► Protect ─► Respond ─► Plan
```

# Ideas fundamentales de la clase

La arquitectura de seguridad OSI organiza la seguridad mediante tres conceptos: ataques, servicios y mecanismos. El ataque describe la acción que amenaza al sistema; el servicio indica qué tipo de protección necesitamos; y el mecanismo es la técnica que se utiliza para proporcionarla.

Los ataques pasivos observan información sin modificarla. Sus dos formas principales son la lectura del contenido y el análisis de tráfico. Como pueden no dejar rastros, la protección se concentra en el cifrado y en reducir la información obtenida a partir de los patrones.

Los ataques activos modifican datos o afectan el funcionamiento. Se dividen en suplantación, replay, modificación de mensajes y denegación de servicio. Requieren autenticación, controles de integridad, monitoreo, redundancia y capacidad de recuperación.

Una DMZ no es una red sin protección, sino un segmento aislado para servicios públicos. El firewall y las ACL limitan el tráfico, mientras que IDS, IPS, HIDS y SIEM ayudan a detectar, bloquear o correlacionar actividades sospechosas.

Los seis servicios estudiados son autenticación, control de acceso, confidencialidad, integridad, no repudio y disponibilidad. Ningún mecanismo puede proporcionarlos todos; por ello se emplea defensa en profundidad.

La seguridad no depende únicamente de herramientas. Es un proceso de gestión basado en planificación, protección y respuesta. ISO/IEC 27001 representa este enfoque mediante un sistema de gestión de seguridad de la información.

La autenticación puede utilizar algo que sabemos, algo que tenemos y algo que somos o hacemos. La autenticación multifactor debe combinar categorías diferentes. La biometría tampoco es perfecta: puede producir falsas aceptaciones, falsos rechazos y ataques como el morphing facial.

Finalmente, una organización segura debe identificar sus activos, comprender sus riesgos, definir políticas, seleccionar herramientas según esas políticas, establecer prioridades, capacitar continuamente a sus integrantes, monitorear sus sistemas y aplicar parches.
