Ningún ataque ocurre simplemente en "internet", sino que siempre tiene como objetivo vulnerar una parte concreta de la comunicación: una capa. Es por este motivo que se desea conocer la capa exacta que está siendo atacada, lo que revelará la clase de información que se puede manipular en ese punto.

En forma de esquema:

```
HTTP / HTTPS / SMTP / FTP / VoIP
            ↓
     APPLICATION LAYER
          Messages

		TCP / UDP
			↓
	 TRANSPORT LAYER
	    Segments

		    IP
			↓
	  NETWORK LAYER
		Datagrams

		 Ethernet
			↓
	  DATA LINK LAYER
          Frames

    Physical Medium
            ↓
           Bits
```

De esta manera es posible determinar que, por ejemplo, si un ataque manipula la dirección IP, este está relacionado con la *capa de red*, mientras que uno que manipula las conexiones TCP se relaciona con la *capa de transporte*. Esto permite colocar las defensas en el lugar adecuado.

## Ataques y Amenazas

Todos los problemas de ciberseguridad tienen una serie de características y funcionamientos distintos y directamente relacionados con los elementos que pretenden afectar. Clasificándolos:

```
DNS spoofing
IP spoofing
data alteration
phishing
malware
DoS
DDoS
social engineering
```

### - DNS spoofing:

El objetivo del DNS es convertir una dirección legible como `udlap.mx` en una dirección IP. Por ejemplo, conceptualmente:

```
udlap.mx
      ↓ DNS
140.x.x.x
```

Por su parte, el **DNS spoofing** es un ataque que trata de provocar que la víctima reciba una respuesta DNS falsa. Por ejemplo, un cliente que trata de acceder a su banco:

```
banco.com → servidor_del_atacante
```

Es decir, el usuario puede escribir correctamente el dominio y aun así terminar en un servidor comprometido. Esto permite que el DNS spoofing se lleve a cabo en ataques como *pharming*.

### - IP spoofing:

La dirección IP identifica, a nivel de red, el origen o destino lógico de un paquete.

A través de un ataque **IP spoofing**, un atacante falsifica la dirección indicada como origen de un paquete, haciendo parecer que este proviene de otra máquina:

```
Atacante real:
10.0.0.55

Paquete enviado:
Source IP = 192.168.0.10
```

Es decir, suplanta el origen declarado del paquete.

Se utiliza en distintos tipos de ataques en donde el atacante no necesita recibir las respuestas, sino engañar a la víctima haciendo uso de su confianza.

### - Data alteration:

Este ataque implica modificar información sin autorización. Asumiendo el caso de una transferencia bancaria:

```
Original:
Transferir $100

Manipulado:
Transferir $10,000
```

La integridad es el prospecto que se ve vulnerado en este tipo de ataque.

El objetivo central de la seguridad no se centra en impedir que los datos sean accesados por terceros, sino que estos lleguen íntegramente y sin modificaciones maliciosas. Esto se conecta más adelante con:

- Hashes
- MAC
- Firmas digitales
- Checksums
- CRC

## - Phishing y social engineering:

Una cadena es tan fuerte como su eslabón más débil.

Estos ataques son completamente dirigidos a explotar a las personas. El **social engineering** trata de lograr que la víctima sea voluntaria en acciones que benefician al atacante. Por ejemplo:

```
"Tu cuenta será suspendida.
Entra aquí inmediatamente para verificarla."
```

La computadora puede estar funcionando perfectamente.

El atacante simplemente logra que la propia víctima proporcione:

```
usuario
contraseña
código MFA
información personal
```

#### Phishing

Este es un método de engaño con base en mensajes falsos:

```
From: "Banco"

Detectamos actividad sospechosa.
Verifica tu cuenta aquí:
banco-verificacion-falsa.com
```

En donde el objetivo normalmente consiste en lograr una acción del usuario.

#### Spear phishing

Esta clase de ataque se diferencia del phishing debido a que aquí se toma como objetivo a una persona específica. En lugar de enviar el mismo mensaje a un millón de personas, al atacante investiga primero los datos personales de la víctima; dígase:

- Nombre
- Escuela
- Puesto
- Compañeros
- Proyectos
- Nombres de conocidos

Enviando un mensaje como:

```
Hola Bruno,

Detectamos un problema con tu cuenta institucional.
Ingresa nuevamente usando este portal UDLAP...
```

Lo que convierte al engaño en algo mucho más convincente.

#### Smishing

Es phishing a través de **SMS**:

```
Tu paquete no pudo entregarse.
Paga $20 aquí:
...
```

#### Vishing

Es ingeniería social a través de *voz* o *llamadas telefónicas*:

```
"Somos del banco.
Necesitamos que nos lea el código que acaba de recibir."
```

### - Malware:

El **malware** puede definirse como software malicioso diseñado para dañar, de manera autónoma un sistema computacional personal u organizacional.

#### Ransomware

Este tipo de ataques busca bloquear o cifrar información, exigiendo rescates a las víctimas:

```
Tus archivos han sido cifrados.

Paga 3 BTC para obtener la clave.
```

Ataca disponibilidad, confidencialidad e integridad.

### - Worm:

Un **worm** o gusano puede propagarse entre máquinas, aprovechando redes o vulnerabilidades. Conceptualmente:

```
PC A
 ↓
PC B
 ↓
PC C
 ↓
Servidor
 ↓
PC D
```

Un gusano exitoso puede propagarse enormemente sin requerir que una persona copie manualmente el malware.

### - Trojan:

Un **troyano** aparenta ser un software legítimo, pero conteniendo comportamientos maliciosos en su interior. Por ejemplo:

```
Minecraft_Free.exe
```

aparentemente instala un juego, pero también instala:

```
backdoor
keylogger
spyware
```

La idea del nombre viene del caballo de Troya: el usuario permite entrar voluntariamente algo que aparentemente es legítimo.

### - Backdoor:

Una **backdoor** es una forma oculta o no autorizada de obtener acceso a un sistema.

Por ejemplo, un malware podría crear:

```
puerto 5555
        ↓
shell remota
```

y permitir posteriormente que el atacante vuelva a entrar.


### - Spyware:

El **spyware** recopila información del usuario sin autorización.

Puede intentar obtener:

- historial;
- contraseñas;
- pulsaciones de teclado;
- archivos;
- capturas de pantalla;
- actividad del navegador.

Un **keylogger** es un ejemplo particularmente conocido: registra lo que escribe el usuario.

### - Botnets:

Una **botnet** es un conjunto de computadoras comprometidas controladas remotamente.

Cada dispositivo infectado puede llamarse:

```
bot
zombie
```

Conceptualmente:

```
            atacante
               |
       Command & Control
        /      |      \
      PC      PC      PC
      |       |       |
     IoT     IoT    servidor
```

La potencia de una botnet proviene precisamente de tener muchas máquinas.

Puede emplearse para:

- enviar spam;
- propagar malware;
- robar información;
- hacer DDoS.

### - Pharming:

Está directamente asociado con la **DNS**; esto, al intentar modificar la resolución hacia un sitio con comportamientos maliciosos:

```
banco.com
    ↓
IP falsa
```

Mientras que el phishing desea convencer a a víctima, en el pharming puede escribirse una dirección correcta y aun así ser redirigido. 


### - Drive-by attacks:

La idea es que visitar un sitio comprometido puede provocar la ejecución o descarga de contenido malicioso.

El usuario podría no buscar explícitamente malware.

Simplemente visita una página vulnerable o comprometida.

# 14. DoS y DDoS

Aquí empezamos a conectar directamente con lo que el profesor dibujó sobre TCP.

**DoS** significa:

**Denial of Service**

El objetivo es afectar la **disponibilidad** de un servicio.

Por ejemplo:

```
Servidor normal:

Usuario ───→ servidor
Usuario ───→ servidor
Usuario ───→ servidor
```

Un atacante puede intentar provocar:

```
MILES/MILLONES DE SOLICITUDES
             ↓
          SERVIDOR
             ↓
        saturación
```

y los usuarios legítimos dejan de poder utilizar el servicio.

---

## 14.1 DDoS

**Distributed Denial of Service**

Es el mismo objetivo, pero el ataque proviene de muchas máquinas.

Por ejemplo, una botnet:

```
Bot ─┐
Bot ─┤
Bot ─┤
Bot ─┼──→ servidor
Bot ─┤
Bot ─┤
Bot ─┘
```

Esto es mucho más difícil de bloquear porque ya no existe necesariamente un único origen.

# 15. TCP es connection-oriented

Aquí entra una de las partes más importantes del pizarrón.

TCP es un protocolo **orientado a conexión**.

Antes de intercambiar datos normalmente establece la conexión mediante un proceso llamado:

# Three-Way Handshake

Entre dos máquinas:

```
A                       B
|                       |
| ------ SYN ---------->|
|                       |
|<---- SYN + ACK -------|
|                       |
| ------ ACK ---------->|
|                       |
```

Después de eso tenemos una conexión establecida.

---

# 16. ¿Qué significa SYN?

En el encabezado TCP existen varios **flags** o banderas.

Una de ellas es:

```
SYN
```

abreviación relacionada con **synchronize**.

Sirve durante el establecimiento de una conexión.

En el pizarrón el profesor también mencionó otras banderas TCP, que suelen incluir:

```
SYN
ACK
FIN
RST
URG
PSH
```

No necesitas memorizar todavía todos sus detalles.

Pero sí:

- **SYN:** iniciar/sincronizar una conexión.
- **ACK:** confirmar recepción.
- **FIN:** finalizar ordenadamente.
- **RST:** reiniciar/abortar una conexión.

# 17. Half-open connection

Ahora podemos entender lo escrito en tus apuntes:

> Si no se recibe de regreso → half-open connection.

Supongamos:

```
Cliente                 Servidor
   |                        |
   | ----- SYN ------------>|
   |                        |
   |<--- SYN + ACK ---------|
   |                        |
   X
```

El servidor está esperando el ACK final.

Todavía reserva cierta información para esa conexión.

La conexión queda parcialmente establecida:

**half-open connection**.

---

# 18. SYN flood

Un atacante puede abusar de esto.

Envía una enorme cantidad de:

```
SYN
SYN
SYN
SYN
SYN
SYN
```

El servidor responde:

```
SYN+ACK
SYN+ACK
SYN+ACK
...
```

pero nunca recibe el ACK final.

Por tanto acumula muchas conexiones **half-open**.

```
          Servidor

connection 1 → esperando ACK
connection 2 → esperando ACK
connection 3 → esperando ACK
connection 4 → esperando ACK
connection 5 → esperando ACK
...
```

Si consume suficientes recursos, deja de atender usuarios legítimos.

Esto es un ejemplo clásico de **DoS usando TCP**.

Con muchos atacantes:

**DDoS**.

UDP funciona distinto porque **no establece una conexión mediante handshake**.

TCP:

```
conexión → transferencia
```

UDP:

```
datagrama
datagrama
datagrama
datagrama
```
