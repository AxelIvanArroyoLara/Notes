## Introducción

Lo primero a tomar en consideración durante la toma de esta asignatura, es que el **Machine Learning** es un proceso que no puede ser resuelto simplemente mediante la llamada a una función `model.fit()` para obtener resultados, sino que deben efectuarse procedimientos experimentales completos en donde cada resultado debe ser imperativamente justificable.

El flujo general consiste en definir una problemática con significado, inspeccionar y preparar los datos, entrenar y evaluar un modelo y finalmente interpretar los resultados obtenidos (y sus riesgos). Como se puede observar, el entrenamiento es tan solo una parte del proceso completo. 


### Definición de Problemas:

Previo a cuestionar el tipo de algoritmo a utilizar, debe determinarse qué se desea resolver. Una frase como:

> "Quiero utilizar Machine Learning con datos de estudiantes"

no define realmente al problema que se está deseando resolver. El planteamiento debe ser algo similar a:

> "Quiero predecir si un estudiante aprobará una materia usando sus asistencia, horas de estudio y calificaciones anteriores".

Esto establece una realidad bastante más concreta.

Debe ser posible identificar:

- Qué se observa (características del estudiante).
- Qué se desea obtener (si el estudiante aprobará).
- Qué datos podrían utilizarse (asistencia, estudio, desempeño previo).
- Qué resultado tiene significado (aprobar o no aprobar).

Este conjunto exacto de datos es reutilizable en cualquier formulación de problemas para ML.

### Inspección y preparación de datos:

Los algoritmos pueden aprender a partir de los datos que se les proporcionan. Es por este motivo, que antes de entrenar debe entenderse con mucha claridad:

- Qué representa cada variable.
- Qué variables se utilizarán.
- Qué información falta.
- Si existen valores extraños.
- Qué escalas utilizan las variables.
- Qué variable representa, si existe, la respuesta correcta.

Por ejemplo:

|Estudiante|Horas de estudio|Asistencia|Promedio anterior|Aprobó|
|---|--:|--:|--:|---|
|A|3|60 %|5.5|No|
|B|8|90 %|8.0|Sí|
|C|6|75 %|6.8|Sí|
|D|2|85 %|7.2|No|
Dependiendo de la pregunta planteada durante la definición, la columna *Aprobó* podría utilizarse o eliminarse, lo que cambiaría por completo el tipo de aprendizaje. 

### Evaluación y entrenamiento:

Una vez habiéndose definido el problema y ya teniendo los datos preparados, es momento de entrenar al modelo.

El proceso de entrenamiento tiene la finalidad de que el algoritmo sea capaz de hallar patrones útiles dentro de los ejemplos, aunque cabe señalar que obtener un buen modelo no es sinónimo de que la experimentación haya funcionado correctamente. La evaluación consiste en determinar:

- Qué tan bien predice
- Cómo se sabe que funcionará con datos nuevos
- Qué clase de errores comete
- Qué métrica está utilizando
- Si la métrica realmente representa lo que se desea.

Es por esto que el entrenamiento y la evaluación se tratan en una misma parte del flujo.

### Interpretación de los resultados:

Por último, debe entenderse lo que significan los resultados producidos por el modelo. Un número por sí solo es un dato, y eso es insuficiente; por ejemplo:

```
Accuracy = 85%
```

Si bien podría parecer un resultado aceptable, aún se desconoce sobre qué datos se toma ese porcentaje, qué ocurre con el restante, qué tipo de errores están dentro de ese 15% y si son igual de graves.

## Reproductibilidad

Otro concepto importante a señalar, es que todo procedimiento experimental debe ser capaz de reproducirse. El entorno sugerido para la toma del curso contiene las siguientes herramientas:

```
Python
  ↓
Jupyter
  ↓
scikit-learn
  ↓
Git
```

En donde:

- **Python:** Es el lenguaje en el que se desarrollarán los experimentos.
- **Jupyter:** Permite combinar código con resultados, gráficas, explicaciones, fórmulas y experimentos.
- **scikit-learn:** Proporciona implementaciones de numerosos algoritmos y herramientas ML.
- **Git:** Permite mantener control sobre las distintas versiones del experimento.

Ahora bien, cabe destacar que el objetivo no se encuentra en aprender la mayor cantidad de software posible, sino en lograr que cada resultado pueda repetirse fácilmente. Asumiendo el mismo 85% de accuracy en los resultados, debe poderse identificar:

- Qué código produjo el resultado
- Qué versión del dataset se utilizó
- Qué parámetros tenía el modelo
- Qué librerías se utilizaron
- Cómo se dividieron los datos

De lo contrario, los resultados pierden valor experimental.

## Inteligencia Artificial

Previo a establecer una definición formal para Machine Learning, debe distinguirse de **Inteligencia Artificial**; estudia sistemas capaces de realizar tareas asociadas con comportamientos inteligentes:

```
        Razonar
           ↑
Actuar ←   IA   → Percibir
           ↓
        Aprender
```

La IA, entonces, puede involucrar:

- **Razonamiento:** Se infieren conclusiones haciendo uso de conocimiento disponible. Por ejemplo: "Todos los mamíferos respiran, un perro es un mamífero → Un perro respira".
- **Planeación:** Se eligen acciones para alcanzar una meta. Por ejemplo, un robot que requiere llegar de *A* a *B*, planifica una secuencia de movimientos para lograrlo.
- **Percepción:** Interpretar información procedente del mundo: imágenes, audio, sensores, video, señales.
- **Aprendizaje:** Mejorar el comportamiento a través de datos o experiencia. Es este punto en el que aparece el Machine Learning.

## Relación entre IA, ML y DL

Con regularidad se utilizan los términos IA, ML y DL como sinónimos los unos de los otros, pero su relación es mucho más profunda que esto. 

La relación que puede establecerse viene dada por el siguiente esquema: 

```
Artificial Intelligence
│
├── Planning
├── Expert Systems
│
└── Machine Learning
      │
      ├── Decision Trees
      ├── SVM
      ├── k-NN
      │
      └── Deep Learning
            ├── CNN
            └── Transformers
```

```
┌──────────────────────────────┐
│ Artificial Intelligence      │
│                              │
│   ┌──────────────────────┐   │
│   │ Machine Learning     │   │
│   │                      │   │
│   │   ┌──────────────┐   │   │
│   │   │ Deep Learning│   │   │
│   │   └──────────────┘   │   │
│   └──────────────────────┘   │
└──────────────────────────────┘
```

Es decir, todo Deep Learning es una forma de Machine Learning, pero no todo el Machine Learning utiliza Deep Learning, que a su vez, es tan solo una manera de construir comportamiento inteligente a través de la IA.

A su vez, también existen técnicas de IA que no son meramente dependientes del aprendizaje a partir de datos. Entre estos se encuentran algunos sistemas expertos, algoritmos de planificación y sistemas basados en reglas.

## Machine Learning como Paradigma

A diferencia de la programación basada en reglas, el Machine Learning no define directamente todas las reglas, sino que se le deben proporcionar ejemplos para que un algoritmo trate de descubrir las relaciones dentro de ellos de manera autónoma:

```
Ejemplos + resultados conocidos
               ↓
      Algoritmo de aprendizaje
               ↓
              Modelo
               ↓
          Nuevas entradas
               ↓
          Nueva predicción
```

##### Ejemplo:

Supóngase que se desea determinar si un estudiante aprobará una materia. 

Aplicando una metodología por reglas:

```
if attendance > 80 and study_hours > 5:
    pass
```

Al establecer parámetros tan rígidos, aspectos como las calificaciones previas o la cantidad de estudio respecto a sus asistencias quedan completamente descartados. Podría ser sumamente complejo lograr establecer manualmente todas las reglas apropiadas. Por otro lado, si se tienen cientos o miles de ejemplos históricos como:

```
study_hours
attendance
previous_grade
...
passed
```

se erige la posibilidad de entrenar a un algoritmo para descubrir patrones en esos datos.

## Usos del Machine Learning

El Machine Learning debe utilizarse únicamente en aquellos casos en los que las reglas son sumamente complejas de especificar, pero se tienen ejemplos disponibles. 

En otras palabras, el paradigma se hace presente cuando existe una relación entre entrada y salida que es:

- Demasiado compleja
- Difícil de expresar manualmente
- Dependiente de muchas variables
- Estadística
- Aproximada
- Variable entre distintos casos

## Tipos de Aprendizaje

Esta es la idea conceptual más importante en el estudio introductorio del tema. 

Retomando el ejemplo de los estudiantes, se pueden formular tres problemas diferentes, dependiendo de qué retroalimentación se encuentra disponible:

```
Ejemplos + etiquetas de aprobación
            ↓
      SUPERVISADO

Ejemplos sin etiquetas
            ↓
     NO SUPERVISADO

Acciones + recompensas
            ↓
       REFUERZO
```

El dominio se mantiene, al igual que el tema, pero la estructura del problema cambia fuertemente.

### - Aprendizaje supervisado:

En **aprendizaje supervisado**, los ejemplos utilizados para llevar a cabo el entrenamiento del modelo siempre contienen una respuesta conocida:

$$X→y$$
En donde:

- $X$ representa las *features* o características de entrada.
- $y$ representa el *target*; es decir, la respuesta que se desea aprender a predecir.

El objetivo final es aprender una función:

$$f:X→y$$

#### Features

Las **features** son las variables utilizadas para realizar la descripción de un ejemplo. Asumiendo el caso de un estudiante:

```
X = {horas de estudio, asistencia, promedio anterior}
```

Donde: 

```
Horas de estudio = 8
Asistencia = 90 %
Promedio anterior = 8.0
```

#### Target o label

El **target** es lo que se desea predecir. Para este ejemplo:

```
Passed = Yes
```

o 

```
Passed = No
```

Por estos motivos, normalmente se verá:

```
X = datos_de_entrada
y = respuesta
```

#### Categorías

Existen dos categorías fundamentales dentro del paradigma de aprendizaje supervisado:

- **Clasificación:** El modelo predice una categoría (perro / caballo / gato).
- **Regresión:** El modelo predice un valor numérico (8.5 / 10).

##### Ejemplo:

Asúmanse aproximadamente estos datos:

| Study h | Attendance | Previous | Passed |
| ------- | ---------- | -------- | ------ |
| 3       | 60 %       | 5.5      | No     |
| 8       | 90 %       | 8.0      | Yes    |
| 6       | 75 %       | 6.8      | Yes    |
| 2       | 85 %       | 7.2      | No     |

Aquí:

```
X =
Study h
Attendance
Previous
```

mientras que:

```
y = Passed
```

El modelo observa parejas como:

```
X → y

(3, 60 %, 5.5) → No
(8, 90 %, 8.0) → Yes
(6, 75 %, 6.8) → Yes
(2, 85 %, 7.2) → No
```

Después intentará contestar:

> **¿Aprobará un estudiante nuevo?**

---

Cabe destacar que un modelo no siempre devuelve únicamente una categoría. Una salida supervisada puede ser `Sí`o `P(aprueba) = 0.83`, que puede interpretarse como una puntuación o como una probabilidad estimada que posteriormente puede transformarse en una categoría:

```
>= 0.5 → Aprueba
< 0.5  → No aprueba
```

Es decir, puede devolverse una **clase** o una **probabilidad**.

### - Aprendizaje no supervisado:

El **aprendizaje no supervisado** surge tras eliminar un aspecto fundamental de la metodología anterior: el *target*. De manera particular, se mantiene:

$$X$$

pero se elimina:

$$y$$
Entonces, al no existir una respuesta correcta proporcionada al modelo de manera explícita, este trata de hallar estructura / patrones en los datos:

#### Clustering

El **clustering** cpnsiste en identificar agrupaciones formadas con base en observaciones similares. Asúmase que se tienen estudiantes descritos por:

```
Study hours
Attendance
Previous grade
```

En este caso, el algoritmo sería capaz de hallar grupos similares a los siguientes:

```
Grupo A
- muchas horas de estudio
- asistencia alta
- promedio alto
```

```
Grupo B
- pocas horas de estudio
- asistencia media
- promedio medio
```

```
Grupo C
- baja asistencia
- comportamiento muy variable
```

Ahora bien, cabe destacar que, aunque K-Means logre hallar un número $n$ de Clusters, estos no vendrán con un nombre determinado, sino que deben analizarse manualmente para asignarles uno con base en sus características primordiales. 

Sin embargo, cabe destacar que si bien el algoritmo puede hallar grupos matemáticamente similares, esto no implica que sean significativos en la realidad; es decir, pueden existir casos como: 

```
Cluster A
Study: 7.8
Attendance: 62 %
Previous: 8.1
```

```
Cluster B
Study: 3.1
Attendance: 91 %
Previous: 7.9
```

En donde los nombres pueden ser complicados de determinar dada la dispersión en la información. De colocar "buen estudiante" o "mal estudiante", podría estarse introduciendo una interpretación errónea de los datos. 

##### - Reducción de dimensionalidad:

Otro de los aspectos presentes en el aprendizaje no supervisado, es la **reducción de dimensionalidad**. Para el caso de los estudiantes, si cada uno estuviera descrito por 50 variables:

```
x1
x2
x3
...
x50
```

Utilizar una dimensionalidad tan alta podría llegar a ser sumamente complejo, por lo que puede generarse una nueva representación haciendo uso de un método de reducción:

```
z1
z2
z3
```

en donde estas nuevas características deben preservar una parte importante de la estructura original.

Conceptualmente hablando:

```
Muchas variables
      ↓
Representación más compacta
      ↓
Menos dimensiones
```

Lo que puede beneficiar al modelo y al desarrollador en términos de:

- Visualización
- Compresión
- Eliminación de redundancias
- Descubrimiento de estructuras
- Preparación de datos para otros algoritmos

##### - Exploración de anomalías:

Otra de las posibilidades presentes en esta forma de trabajo es la de buscar observaciones poco comunes; por ejemplo:

```
Study = 1 h
Attendance = 100 %
Previous grade = 10
```

En donde la combinación puede llegar a ser extremadamente rara respecto a los datos habituales. En este caso, el algoritmo puede detectar el caso como una anomalía, misma que debe ser interpretada manualmente para determinar si se trata de:

- Un caso extraño real
- Un error de captura
- Un comportamiento poco frecuente
- Una población distinta

##### - Similaridad y distancia:

Es aquí en donde se introduce el concepto de **silhouette score**: métrica que permite determinar si dos puntos en el mapa se perciben como más similares que otros en términos de distancia:

```
A • • B          • C
```

En donde `A` y `B` se consideran como pertenecientes a un mismo grupo al estar mucho más cerca entre sí de lo que están de `C`.

De manera particular, el silhouette score se basa en la evaluación de dos conceptos simultáneamente:

- Qué tan cerca que encuentra una observación de los elementos de su propio cluster
- Qué tan separada se encuentra la observación de los demás clusters

Es decir:

```
Clusters compactos
+
Clusters bien separados
=
mejor silhouette score
```

Matemáticamente, el valor de esta métrica está dado en un rango:

$$(-1 \leq s \leq 1)$$

```
cerca de +1
→ los grupos parecen bien separados

cerca de 0
→ existen grupos que se traslapan

valor negativo
→ algunas observaciones quizá estén asignadas
  a un cluster menos apropiado
```

##### Ejemplo:

Ahora volvemos al dataset anterior, pero eliminamos la columna `Passed`.

Antes:

|Study h|Attendance|Previous|Passed|
|---|---|---|---|
|3|60 %|5.5|No|
|8|90 %|8.0|Sí|
|6|75 %|6.8|Sí|
|2|85 %|7.2|No|

Ahora:

|Study h|Attendance|Previous|
|---|---|---|
|3|60 %|5.5|
|8|90 %|8.0|
|6|75 %|6.8|
|2|85 %|7.2|

Ya no podemos preguntar directamente:

> "¿Aprobará este estudiante?"

porque eliminamos la información que representaba ese resultado.

En cambio podemos preguntar:

> **¿Qué perfiles de estudiantes aparecen en estos datos?**


### - Aprendizaje por refuerzo:

El tercer paradigma es conocido como **aprendizaje por refuerzo** y se basa en la existencia de un agente capaz de interactuar con el ambiente. La estructura general puede ser descrita de la siguiente manera:

```
        acción aₜ
Agente ─────────────→ Ambiente
   ↑                      │
   └──────────────────────┘
      estado sₜ₊₁
      recompensa rₜ₊₁
```

En donde:

- **Agente:** Es aquel que toma las decisiones (dígase un sistema que recomienda acciones para apoyar a un estudiante).
- **Ambiente:** Es aquello con lo que interactúa el agente (el estudiante y su situación académica).
- **Estado:** Describe la situación actual (características actuales en la tabla. Se escribe como $s_t$).
- **Acción:** El agente debe escoger qué acciones tomar (recomendar asesorías, mostrar un video, etc. La acción escogida en el momento se escribe como $a_t$).
- **Recompensa:** Tras ejecutar la acción, el agente recibe una recompensa positiva o negativa según los resultados ($r_{t+1}$).

A su vez, este paradigma es ejecutado en un ciclo de acciones:

```
Estado actual
     ↓
Elegir acción
     ↓
Observar recompensa
     ↓
Actualizar política
     ↓
Nuevo estado
     ↓
...
```

En donde una *política* es aquella que representa la acción que debería realizar el agente dado cierto estado. Puede representarse como:

$$\pi(s)\rightarrow a$$
Es decir:

```
Estado:
baja asistencia
bajo promedio
pocos ejercicios

↓

Política

↓

Acción:
Schedule tutoring
```

Adicionalmente, debe destacarse que la recompensa se basa en la evaluación de una acción; no indica al agente qué elegir después. Dado el caso, por ejemplo: 

```
+10 si mejora el desempeño
-2 si no mejora
```

Esto no le indica al modelo si debería aplicar una acción como recomendar una tutoría o mostrar un video, sino que simplemente se limita a evaluar los resultados. El aprendizaje viene cuando el modelo logra aprender qué acciones pueden producir mejores recompensas. 

Ahora bien, las recompensas deben considerarse como un esfuerzo acumulativo, no instantáneo. En otras palabras, una buena acción en un momento determinado, podría no ser la mejor estrategia a largo plazo. 

###### Ejemplo:

La presentación menciona:

### Navegación robótica

```
Estado:
posición del robot

Acción:
moverse

Recompensa:
alcanzar objetivo / evitar obstáculos
```

---

### Videojuegos

```
Estado:
situación actual del juego

Acción:
movimiento del jugador

Recompensa:
puntos / victoria / progreso
```

---

### Control secuencial

Por ejemplo:

```
temperatura actual
       ↓
acción de control
       ↓
nuevo estado
       ↓
recompensa
```

## Conclusión

Asúmase que se tiene exactamente el mismo dominio: 

 > Estudiantes
 
 Sin embargo, es posible establecer tres preguntas de estudio diferentes que determinarán el enfoque a utilizar:

| Paradigma          | Pregunta                                      | Información disponible                      |
| ------------------ | --------------------------------------------- | ------------------------------------------- |
| **Supervisado**    | ¿Aprobará este estudiante?                    | Datos históricos + `Passed`                 |
| **No supervisado** | ¿Qué perfiles de comportamiento aparecen?     | Features, sin etiquetas de perfiles         |
| **Refuerzo**       | ¿Qué intervención debería realizarse después? | Estados, acciones, resultados y recompensas |
Es decir, el dominio no es el que determina el paradigma, sino la pregunta planteada y el feedback disponible conjuntamente.
