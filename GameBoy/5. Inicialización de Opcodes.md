## Fetch, Decode, Execute

El procesador funciona a grandes rasgos como una máquina de estados que recorre una serie de pasos para cada instrucción, repitiéndolos mientras el sistema continua. De manera general, solo ocurren tres pasos centrales:

- **Fetch:** El CPU lee el byte de RAM al que apunta el Program Counter.
- **Decode:** El byte recuperado del paso anterior se decodifica; es decir, el procesador utiliza su valor para determinar la operación a ejecutar.
- **Execute:** Por último, se ejecuta la instrucción (esto podría requerir bytes adicionales a ser accesados en la RAM o los registros del CPU).

Una vez se finaliza este proceso, el Program Counter avanza hacia la próxima instrucción y el ciclo se repite. 

La implementación comienza con el fetch y sus helpers en `mod.rs`:

```
pub fn fetch(&mut self) -> u8 {
        let val = self.read_ram(self.pc);
        self.pc += 1;
        val
    }
```

Aquí, `fetch` toma un valor mutable para incrementar el contador en uno y poder pasar a la siguiente instrucción. Cabe destacar que el `val` del final es el valor devuelto por la función: no se necesita escribir el `return`.

Para la operación en 16 bits se repite el mismo procedimiento, pero tomando los valores individuales en 8 bits y después combinándolos:

```
pub fn fetch_u16(&mut self) -> u16 {
        let low = self.fetch();
        let high = self.fetch();
        let val = merge_bytes(high, low);
        val
    }
```

Es importante resaltar que la lectura se hace inversamente respecto al orden que ya se había establecido en secciones previas: se comienza por `low-byte` y termina en `high-byte`.

A continuación, se añade la estructura para leer los valores almacenados en una dirección particular de la RAM:

```

        todo!();
    }

    pub fn write_ram(&mut self, addr: u16, val: u8) {
        todo!();
    }
```

El `decode` curiosamente solo toma el valor `u8` retornado por el paso anterior y lo usa para decidir la instrucción a ejecutar.

## Tablas de Opcodes

Para la implementación del `decode`, se comienza por las **tablas de opcodes**, de las cuales llevaremos a cabo la implementación de la primera, que tiene un tamaño de $16*16$, en donde cada celda corresponde a una operación distinta del procesador. Pueden identificarse mediante numeración hex, comenzando desde arriba a la izquierda con `0x00`, que va incrementando en 1 con cada columna hasta la fila `0x0F` y continuando en `0x10` en la segunda.   

![[Pasted image 20260616190928.png]]

En esta tabla se contienen tres piezas de información relevantes para cada opcode:

- **Nombre de la operación:** Utiliza la sintaxis del Game Boy assembly. Estas abreviaciones indican el tipo de operación y el tipo de entradas que podría utilizar.
- **Lista de flags a modificar:** Las instrucciones modifican las flags del registro `F` como parte de la operación.
- **Número de ciclos:** Indica el tiempo en ciclos que la operación tarda en ejecutarse en el procesador. Este número se retorna desde `execute`.

## NOP

Esta es la primera operación a implementar, y su trabajo es, literalmente, no hacer nada. Su nombre es entonces *no operation* y se determina en `0x00`. Por lo general se utiliza para dar espacio o alineación al código.

La implementación de `NOP` utiliza el mismo patrón que se sigue para todas las instrucciones: primero, se crea una nueva función con los mismos parámetros de la tabla (`mut Cpu`) y se retorna un `u8`. A esta se le nombrará como `nop_00` y no tiene comportamiento (además de retornar el valor de 8 bits):

```
fn nop_00(_cpu: &mut Cpu) -> u8 {
  // Do nothing 1
}
```
