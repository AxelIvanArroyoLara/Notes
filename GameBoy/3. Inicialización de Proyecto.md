
La arquitectura planteada funciona a manera de aplicación híbrida, teniendo un enfoque basado en el funcionamiento en escritorio al igual que dentro de un entorno web. Para ello, se plantean dos sistemas de frontend (uno por plataforma) y uno de backend (*core*) para el manejo de los recursos. 

## Inicialización de Módulos

Para crear las carpetas, se comienza con 

`$ cargo init core --name gb_core --lib`

Este comando permite crear una librería RUST para su uso en las otras carpetas y el propio core, que se contiene en esta misma carpeta.

Para los frontends, se utiliza:

```
$ cargo init desktop
$ cargo init wasm --lib
```

Uno para la versión de escritorio y otro para WebAssembly.

Tras esto, queda la siguiente estructura:

```
.
├── core
│   ├── Cargo.toml
│   └── src
│       └── lib.rs
├── desktop
│   ├── Cargo.toml
│   └── src
│       └── main.rs
└── wasm
    ├── Cargo.toml
    └── src
        └── lib.rs
```

Para el último paso, se apuntan ambas carpetas de frontend hacia `core` mediante sus archivos `Cargo.toml`, en `[dependencies]`.

```
# In desktop/Cargo.toml

[dependencies]
gb_core = { path = "../core" }
```

## Estructura de Backend

Dada la naturaleza para los permisos de RUST, se debe tener mucho cuidado respecto a cómo se organiza la información. La arquitectura seleccionada toma en cuenta que el CPU requiere accesar a la memoria, lo que llevará a cabo mediante un bus que pueda dotarle de esas capacidades, inclusive también para otros módulos como los datos de los cartuchos, el manejo de video, etc.
