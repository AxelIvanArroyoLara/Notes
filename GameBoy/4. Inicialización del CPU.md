## Estructura

La implementación del CPU es una de las partes centrales en el desarrollo de un sistema como este, por lo que se le dedicará su propio archivo en `core/src/cpu/`, llamado `mod.rs`, al igual que un `utils.rs` para las funciones helper.

A partir de ahora, se tiene esta estructura:

```
.
├── core
│   ├── Cargo.toml
│   └── src
│       ├── lib.rs
│       ├── utils.rs
│       └── cpu
│           └── mod.rs
├── desktop
│   ├── Cargo.toml
│   └── src
│       └── main.rs
└── wasm
    ├── Cargo.toml
    └── src
        └── lib.rs
```

Ambos módulos entonces, se añaden a `core/src/lib.rs`:

```
// In core/src/lib.rs

pub mod cpu;
pub mod utils;
```

## Desarrollo

### Registros:

Ahora, la implementación estructural se llevará a cabo por completo dentro de la clase `Cpu`, declarada como estructura:

```
// In cpu/mod.rs

pub struct Cpu {
}
```

Al ser una clase, debemos definir sus atributos; en este caso, los registros con sus tipos. Cabe destacar que, si bien, en Rust no existen las clases y objetos de la misma manera que en un lenguaje como C++, la funcionalidad de estos componentes es compartida con las estructuras (aunque solo guardan valores de un mismo tipo) y sus instancias respectivamente, por lo que los conceptos de POO nos dan más que nada, una forma de aproximarnos al código.

En este caso, la implementación es la siguiente: 

La asignación de tipos tiene una particularidad; ya que se otorgan a las variables *unasigned values* para 8 bits en los registros, y 16 bits en el *counter* (guarda la dirección de memoria de la próxima instrucción) y el *stack pointer* (apunta a la parte actual de la pila). 

```
pub struct Cpu {
    pc: u16,
    sp: u16,
    a: u8,
    b: u8,
    c: u8,
    d: u8,
    e: u8,
    f: u8,
    h: u8,
    l: u8,
}
```

Posteriormente, se añaden funciones mediante `impl Cpu`:

```
impl Cpu {
    pub fn new() -> Self {
        pc: 0x0000,
        sp: 0x0000,
        a: 0x00,
        b: 0x00,
        c: 0x00,
        d: 0x00,
        e: 0x00,
        f: 0x00,
        h: 0x00,
        l: 0x00,
    }
}
```

En donde:

- `pub` indica que la función es pública.
- `fn new()` declara una nueva función.
- `-> Self` indica que la función devolverá un valor del mismo tipo `Cpu` (pasan a ser sinónimos).

Por lo tanto, al ser `Cpu` un `struct` que pide los valores de los registros, se construye de esta manera:

```
// Para crear una struct, se escribe:
        
         Tipo {
           campo: valor,
	     }
```

Por lo tanto:

```
impl Cpu {
    pub fn new() -> Self {
        pc: 0x0000,
        sp: 0x0000,
        a: 0x00,
        b: 0x00,
        c: 0x00,
        d: 0x00,
        e: 0x00,
        f: 0x00,
        h: 0x00,
        l: 0x00,
    }
}
```

De esta manera, creamos una función constructor que asigna estos valores a manera de placeholders; es decir, se les inicializa temporalmente.

### Enums:

Ahora bien, se pasan a definir enumeraciones con elementos correspondientes para cada uno de los registros ya declarados. Esto es importante ya que el procesador del GameBoy suele interpolar el comportamiento de muchísimas instrucciones; por ejemplo, una operación realizada en B es sumamente distinta de una hecha en el registro C, incluso aunque su implementación sea similar. Estos `enum` nos permitirán, entonces, crear funciones helper para distintas categorías de instrucciones, en lugar de crear una para cada operación posible.

Hablando de sintaxis, `enum` define un tipo que puede tener varios valores posibles. Adicionalmente, se añade `#[derive(Copy, Clone)]`, que le dice a Rust que este tipo puede copiarse fácilmente. Esta funcionalidad es importante debido a que, de no utilizarla, al pasar un tipo `Regs` a una función, se podría mover su locación en memoria; en lugar de eso, al aplicar `Copy`, simplemente se copia como un número pequeño.

Este `enum` representa a todos los registros de 8 bits:

```
#[derive(Copy, Clone)]

pub enum Regs {
    A,
    B,
    C,
    D,
    E,
    F,
    H,
    L,
}
```

Y este siguiente, a los de 16:

```
#[derive(Copy, Clone)]

pub enum Regs16 {
    AF,
    BC,
    DE,
    HL,
    SP,
}
```

Recordemos que `AF`, `BC`, `DE` y `HL` son pares de registros de 8 bits, mientras que `SP` es el stack pointer, mismo que al manipular direcciones de memoria, requiere de esta capacidad de almacenamiento.

Ahora bien, se procede a crear el `enum` correspondiente a las flags, que se guardarán en el registro `F`:

```

pub enum Flags {
    Z,
    N,
    H,
    C,
}

```

En donde:

- `Z` es Zero flag.
- `N` es Substract flag.
- `H` es Half Carry flag.
- `C` es Carry flag.

### Funciones helper:

Ahora bien, deben seguirse los procedimientos de encapsulamiento para clases, por lo que se declaran *getters* y *setters* para cada uno de los registros. Comencemos por los de 8 bits:

```
// In cpu/mod.rs
// Unchanged code omitted

impl Cpu {
    pub fn get_r8(&self, r: Regs) -> u8 {
        match r {
            Regs8::A => { self.a },
            Regs8::B => { self.b },
            Regs8::C => { self.c },
            Regs8::D => { self.d },
            Regs8::E => { self.e },
            Regs8::F => { self.f },
            Regs8::H => { self.h },
            Regs8::L => { self.l },
        }
    }
}
```

En donde:

- `&self` indica que el método recibe una referencia inmutable al "objeto" `Cpu` actual; es decir, puede leer sus atributos pero no modificarlos.
- `&r: Regs` indica que se recibe un parámetro `r` de tipo `Regs`.
- `->` implica que la función regresa un valor de tipo `u8`.

Posterior a la declaración:

- `match` es una estructura similar a un `switch`, pero más poderosa.
- `Regs::A => self.a` significa que si `r` es `Regs::A`, se devuelve `self.a`.

Una curiosidad de la sintaxis es que si en Rust una expresión no termina en `;`, la expresión se devuelve automáticamente.

Ahora el setter:

```
pub fn set_r8(&mut self, r: Regs, val: u8) {
        match r {
            Regs8::A => { self.a = val },
            Regs8::B => { self.b = val },
            Regs8::C => { self.c = val },
            Regs8::D => { self.d = val },
            Regs8::E => { self.e = val },
            // Note: The bottom four bits of F shall always be 0
            Regs8::F => { self.f = val & 0xF0 },
            Regs8::H => { self.h = val },
            Regs8::L => { self.l = val },
        }
    }
```

Donde:

- `&mut self` indica que el valor de los atributos de `self` se puede modificar.
- `val & 0xF0` limpia los bits bajos del registro para que estos siempre sean 0. Esto se conoce como *masking*.

Se debe aclarar que en Rust, cuando no se coloca el asignador `-> Tipo`, la función devuelve `()`, lo que significa `unit` (`void` en otros lenguajes).

Ahora bien, para generar las funciones de encapsulamiento de los registros de 16 bits, se requerirá fusionar los valores de 8 bits mediante una función helper, que será creada en el archivo `utils.rs`.

```
pub fn merge_bytes(high: u8, low: u8) -> u16{
    ((high as u16) << 8) | (low as u16)
}
```

Donde:

- `(high as u16)` se castea a 16 bits.
- `<< 8` recorre 8 bits a la derecha: `0000 0001 -> 0001 0000`.
- `|` OR concatena el valor `low` en la posición que ya está libre: `0001 0011`.

Aquí se define la función `merge_bits`, que recibirá un valor `high` de 8 bits y otro `low` del mismo tamaño, regresando un número combinado de 16 bits totales. 

Ahora, también debe definirse una función que haga lo contrario; es decir, que tome un valor de 16 bits y logre separarlo en dos diferentes de 2:

```
// In utils.rs
// Unchanged code omitted

pub trait ByteOps {
    fn high_byte(&self) -> u8;
    fn low_byte(&self) -> u8;
}

impl ByteOps for u16 {
    fn high_byte(&self) -> u8 {
        (self >> 8) as u8
    }

    fn low_byte(&self) -> u8 {
        (self & 0xFF) as u8
    }
}
```

En donde:

- `trait` representa una interfaz para tipos de dato.

Una vez ya teniendo las funciones de `utils`, se mandan a llamar en `cpu/mod.rs`, y se mandan a llamar dentro de la implementación de los getters para los valores de 16 bits:

```
// In cpu/mod.rs
// Unchanged code omitted

use crate::utils::*;

impl Cpu {
    pub fn get_r16(&self, r: Regs16) -> u16 {
        match r {
            Regs16::AF => { merge_bytes(self.a, self.f) },
            Regs16::BC => { merge_bytes(self.b, self.c) },
            Regs16::DE => { merge_bytes(self.d, self.e) },
            Regs16::HL => { merge_bytes(self.h, self.l) },
            Regs16::SP => { self.sp },
        }
    }
}
```

Aquí, los registros combinados se obtienen mediante la función `merge_bytes` establecida previamente; todos, a excepción de `SP`, que ya es de 16 bits por defecto.

Ahora, en el setter:

```
pub fn set_r16(&mut self, r: Regs16, val: u16) {
        let high = val.high_byte();
        let low = val.low_byte();
        match r {
            Regs16::AF => {
                self.set_r8(Regs::A, high);
                self.set_r8(Regs::F, low);
            },
            Regs16::BC => {
                self.set_r8(Regs::B, high);
                self.set_r8(Regs::C, low);
            },
            Regs16::DE => {
                self.set_r8(Regs::D, high);
                self.set_r8(Regs::E, low);
            },
            Regs16::HL => {
                self.set_r8(Regs::H, high);
                self.set_r8(Regs::L, low);
            },
            Regs16::SP => { self.sp = val; },
        }
    }
```

Aquí se requiere separar los valores de 16 bits a dos de 8: `val = '0x1234 -> high = 0x12, low = 0x34`, asumiendo que tanto `high_byte()` como `low_byte()` vienen de `utils:ByteOps` y se asignan cada uno con su registro correspondiente (posicionalmente hablando).

### Flags:

Por último, se proceden a establecer los helpers para las banderas; es decir, sus getters y setters.

```
// In cpu/mod.rs

impl Cpu {
    // Unchanged code omitted

    pub fn get_flag(&self, f: Flags) -> bool {
        match f {
            Flags::Z => { (self.f & 0b1000_0000) != 0 },
            Flags::N => { (self.f & 0b0100_0000) != 0 },
            Flags::H => { (self.f & 0b0010_0000) != 0 },
            Flags::C => { (self.f & 0b0001_0000) != 0 },
        }
    }

    pub fn set_flag(&mut self, f: Flags, val: bool) {
        if val {
            match f {
                Flags::Z => { self.f |= 0b1000_0000 },
                Flags::N => { self.f |= 0b0100_0000 },
                Flags::H => { self.f |= 0b0010_0000 },
                Flags::C => { self.f |= 0b0001_0000 },
            }
        } else {
            match f {
                Flags::Z => { self.f &= 0b0111_0000 },
                Flags::N => { self.f &= 0b1011_0000 },
                Flags::H => { self.f &= 0b1101_0000 },
                Flags::C => { self.f &= 0b1110_0000 },
            }
        }
    }
}
```

Estas funciones utilizan la técnica de enmascaramiento para extraer los bits uno por uno. Dentro del registro correspondiente a cada flag, el séptimo siempre tiene el valor de la bandera `Z`, el sexto el de `N` y el quinto y cuarto los de `H` y `C` respectivamente, dejando los cuatro finales vacíos. La función `get_flag()` se aprovecha de esto aplicando una máscara con `&` sobre el registro `f`. Cada máscara tiene un único bit activado en la posición de la bandera que se quiere consultar. Por ejemplo, para `Z` se usa `0b1000_0000`, que conserva solo el bit 7 y descarta el resto. Si el resultado es distinto de cero, significa que esa bandera está activada; si es cero, está desactivada.

La función `set_flag()` hace lo contrario: modifica el valor de una bandera concreta. Si `val` es `true`, usa `|=` con una máscara para poner ese bit en `1` sin alterar los demás bits. Si `val` es `false`, usa `&=` con una máscara que tiene un `0` justo en la posición de la bandera que se quiere borrar y `1` en las demás posiciones relevantes. Así se apaga únicamente esa bandera.

Por ejemplo, si queremos activar la bandera `C`, se aplica `self.f |= 0b0001_0000`. Esto fuerza el cuarto bit a `1`. En cambio, para desactivarla se usa `self.f &= 0b1110_0000`, lo que fuerza ese bit a `0`. De esta forma, el registro `f` puede guardar varias banderas al mismo tiempo dentro de un solo byte.
