En el capítulo previo se incluyó la nomenclatura utilizada para la escritura de código ensamblador para la GameBoy en forma de los opcodes: el nombre de la instrucción viene primero, seguido por el registro sobre el que la instrucción opera, seguido por una coma y una segunda entrada de registro.

Por ejemplo, el opcode `0x04`:

![[Pasted image 20260623141911.png]]

En donde:

- `INC` es la abreviación de incremento y suma 1.
- `B` refiere al registro del mismo nombre.
- `Z0H-` es la lista de las banderas `Z N H C` en donde:
	- `1` indica que siempre tiene valor.
	- `0` indica que siempre se limpia y vale 0.
	- `-` indica que no se utiliza.
	- Si se tiene solo su nombre, se asume el comportamiento base de la bandera.

Ahora, en este caso particular conviene analizar el motivo del comportamiento para cada una de las banderas:

- `Z` toma su comportamiento base; es decir, vale 1 si el resultado de la suma es 0.
- `N = 0` dado que, al ser una suma, no hay valores negativos, por lo que siempre se mantiene en 0.
- `H` vale 1 en caso de que exista un acarreo (half-carry) del bit 3 al 4.
- `C = -` No se utiliza.

En un segundo ejemplo, se toma el opcode `0x80`, que afecta a dos registros por igual:

![[Pasted image 20260623143443.png]]

Esta instrucción suma los valores almacenados en los registros `A` y `B`, guardando el resultado en el primero; utiliza la convención de que para las instrucciones que utilizan dos registros que usan dos registros, la salida se almacena en el de la izquierda. Para una instrucción como `0x43`, que es `LD B, E` se sigue la misma regla: el valor de la derecha se copia al registro de la izquierda.

Otro concepto importante, es que cuando algunos de los registros se rodean por un paréntesis, estos indican que no se ejecuta la instrucción en el valor almacenado en esos registros, sino con los valores en la dirección de memoria almacenada dentro de los mismos: 

![[Pasted image 20260623143930.png]]

En donde:

- `H` almacena el valor `0x12`.
- `L` almacena el valor `0x34`.
- `INC (HL)` incrementa en 1 el valor guardado en la dirección `0x1234`. 

En este caso, el valor en `HL` no se modifica.

De igual manera, existen algunas instrucciones que permiten modificar el valor del registro. La instrucción `0x2A`, `LD A, (HL+)` lee el valor en la RAM apuntado por `HL` y lo copia al registro `A`; al terminar incrementa esta dirección en 1 gracias al operador `+`. Esto también puede hacerse con el decremento `-`.

Gracias a esto, es posible asimilar patrones; por ejemplo: las instrucciones desde `0x80` hasta `0x87` son adiciones entre el registro `A` y algún otro registro de 8 bits. Gracias a esto, es posible construir helpers que permitan utilizar un enum para los registros y aplicar la suma.

## Incremento y Decremento

Las funciones para el incremento y decremento son sumamente sencillas, estando indicadas por las abreviaciones `INC` y `DEC` respectivamente.

El Game Boy cuenta con doce instrucciones de cada tipo, separadas en columnas de cuatro en la tabla de opcodes. Para `INC`, estas columnas comienzan desde `0x03`, `0x04` y `0x0C`, mientras que el decremento son los cuatro primeros elementos en las columnas comenzando en `0x05`, `0x0B` y `0x0D`.

![[Pasted image 20260623145453.png]]

Si bien existen doce instrucciones `INC` en total, no son las mismas. Las dos columnas en `0x04` y `0x0C` modifican un valor de 8 bits, toman un solo ciclo, pero nunca ajustan las banderas. Esto significa que durante la implementación, se deben crear dos funciones helper: un incremento de 8 bits y uno de 16, de manera que sea posible gestionar todos los casos. Esto es igualmente aplicable para el decremento.

Se comenzará creando las funciones en `cpu/mod.rs`. Cada una aceptará uno de los registros de 16 bits y lo utilizará para incrementar o decrecer el valor de los mismos según corresponda. 

```
// In cpu/mod.rs

impl Cpu {
    // Unchanged code omitted

    pub fn dec_r16(&mut self, r: Regs16) {
        let val = self.get_r16(r);
        let dec = val.wrapping_sub(1);
        self.set_r16(r, dec);
    }

    pub fn inc_r16(&mut self, r: Regs16) {
        let val = self.get_r16(r);
        let inc = val.wrapping_add(1);
        self.set_r16(r, inc);
    }
}
```

En donde las funciones `wrapping_...` se encargarán de manejar los overflows por nosotros para no romper el sistema.

## Carry y Half-Carry

Respecto a las versiones de 8 bits, aquí se modifican las flags de una manera que complica el procedimiento. De acuerdo con la tabla, todos los incrementos de este tamaño (como `INC B`, `INC D`, etc.) mantienen el mismo comportamiento `Z0H-`; mientras que por el contrario, los decrementos lo tienen en `Z1H-`.

Si bien, las banderas `Z` y `N` son sencillas de comprender, las de acarreo tienen una complejidad adicional. Estas dos revisan el overflow desde sus bytes más significativos: `C` lo hace con el séptimo al (inexistente) octavo bit y el `H` con el tercero y cuarto. A continuación se detallan algunos ejemplos:

![[Pasted image 20260623173150.png]]

![[Pasted image 20260623173158.png]]

Asúmase que se tiene el valor `0xAA` en hex, que se corresponde con `10101010` en binario. Tras aplicar una adición a este, se obtendrá `0xAB`; es decir `10101011`. En este caso, ninguno de los dos bits analizados (7 o 3) tuvo acarreo, por lo que ambas banderas se establecen en 0. Ahora, si se añade 8 a `0xAA`, se obtiene `10110010`: el tercer bit tuvo acarreo hacia el cuarto, por lo que `H = 1` y `C = 0`.

Respecto a los valores de 16 bits, estos también terminan por afectar a las banderas; sin embargo, aquí solo se analizan los bits en el *high byte*, efectuándose el análisis sobre los bits 12 y 15, no tomándose en cuenta ningún acarreo en el otro segmento.

Adicionalmente, dado el caso de que un bit requiera "pedir prestado" al de adelante, las banderas también deben establecerse en 1.

Rust provee de una funcionalidad especial para validar si ocurrió un acarreo: `checked_add` y `checked_sub`.

```
// In utils.rs
// Unchanged code omitted

pub fn check_c_carry_u8(lhs: u8, rhs: u8) -> bool {
    lhs.checked_add(rhs).is_none()
}

pub fn check_c_carry_u16(lhs: u16, rhs: u16) -> bool {
    lhs.checked_add(rhs).is_none()
}

pub fn check_c_borrow_u8(lhs: u8, rhs: u8) -> bool {
    lhs.checked_sub(rhs).is_none()
}

pub fn check_c_borrow_u16(lhs: u16, rhs: u16) -> bool {
    lhs.checked_sub(rhs).is_none()
}
```

Ahora, para los Half-Carries, al no existir un overflow real en los bytes superiores, se valida si alguno de los valores tras operar en la derecha, pasa a los últimos cuatro bits. Para ello, se enmascaran los cuatro bits superiores y se ejecuta la adición, solo verificando lo descrito previamente.

```
// In utils.rs
// Unchanged code omitted

pub fn check_h_carry_u8(lhs: u8, rhs: u8) -> bool {
    ((lhs & 0xF) + (rhs & 0xF)) & 0xF0 != 0
}

pub fn check_h_carry_u16(lhs: u16, rhs: u16) -> bool {
    ((lhs & 0xFFF) + (rhs & 0xFFF)) & 0xF000 != 0
}
```

Estas funciones hacen uso del operador `AND` para remover los cuatro bits superiores de cada entrada, los compacta juntos y valida si existen residuos (acarreos) provenientes de los cuatro menores; si eso ocurrió, entonces solo se retorna 1.

Para los borrow, se utiliza la versión modificada:

```
// In utils.rs
// Unchanged code omitted

pub fn check_h_borrow_u8(lhs: u8, rhs: u8) -> bool {
    (lhs & 0xF).checked_sub(rhs & 0xF).is_none()
}

pub fn check_h_borrow_u16(lhs: u16, rhs: u16) -> bool {
    (lhs & 0xFFF).checked_sub(rhs & 0xFFF).is_none()
}
```

Mediante esto se enmascaran los cuatro bits superiores primero, pero cuando esto ocurre, el préstamo termina por resultar en un underflow, que es validado por `checked_sub`.

Ya teniendo estos dos sistemas funcionando, se puede proceder a completar los helpers de incremento y decremento. Tal como las versiones de 16 bits, se aceptará un registro de 8 bits mediante un enum, y se efectuará la operación sobre el registro respectivo. Sin embargo y a diferencia de las versiones de 16 bits, las funciones también analizarán la salida de la instrucción y actualizarán las banderas según corresponda. Se toma `Z0H-` para incremento y `Z1H-` para decremento:

```
// In cpu/mod.rs

impl Cpu {
    // Unchanged code omitted

    pub fn dec_r8(&mut self, r: Regs) {
        let val = self.get_r8(r);
        let dec = val.wrapping_sub(1);
        let set_h = check_h_borrow_u8(val, 1);

        self.set_r8(r, dec);
        self.set_flag(Flags::N, true);
        self.set_flag(Flags::Z, dec == 0);
        self.set_flag(Flags::H, set_h);
    }

    pub fn inc_r8(&mut self, r: Regs) {
        let val = self.get_r8(r);
        let inc = val.wrapping_add(1);
        let set_h = check_h_carry_u8(val, 1);

        self.set_r8(r, inc);
        self.set_flag(Flags::N, false);
        self.set_flag(Flags::Z, inc == 0);
        self.set_flag(Flags::H, set_h);
    }
}
```

Esta modificación se mantiene igual que en los registros de 16 bits, pero actualizando las flags por igual. Gracias a las funciones `check_h_carry_u8` y `check_h_borrow_u8`, simplemente se informa cómo establecer la bandera `H`. Para la `Z` se valida si el resultado es cero, y para la `N` simplemente se asigna un valor constante y dependiente de la operación realizada.

Gracias a los helpers, es ahora posible codificar 22 de las 24 instrucciones `INC` y `DEC`, dejando las que utilizan los registros `HL` para después:

## Incremento y Decremento en Memoria

Tras haber finalizado la implementación de la adición y decremento de los registros de 8 y 16 bits, llega el momento de trabajar con las únicas dos que lo hacen sobre los valores en memoria: `INC (HL)` y `DEC (HL)`. Existen distintos grupos de instrucciones con un opcode para cada uno de los registros de 8 bits, y constantemente hacen uso de los valores almacenados en `HL`. Para gestionar esta dupla, se comienza por añadir una nueva dupla en nuestro `enum Regs`, expandiendo sus getters y setters:

```
// In cpu/mod.rs
// Unchanged code omitted

#[derive(Copy, Clone)]
pub enum Regs {
    A,
    B,
    C,
    D,
    E,
    F,
    H,
    L,
    HL,
}

impl Cpu {
    pub fn get_r8(&self, r: Regs) -> u8 {
        match r {
            Regs::A => { self.a },
            Regs::B => { self.b },
            Regs::C => { self.c },
            Regs::D => { self.d },
            Regs::E => { self.e },
            Regs::F => { self.f },
            Regs::H => { self.h },
            Regs::L => { self.l },
            Regs::HL => {
                let addr = self.get_r16(Regs16::HL);
                self.read_ram(addr)
            }
        }
    }

    pub fn set_r8(&mut self, r: Regs, val: u8) {
        match r {
            Regs::A => { self.a = val },
            Regs::B => { self.b = val },
            Regs::C => { self.c = val },
            Regs::D => { self.d = val },
            Regs::E => { self.e = val },
            Regs::F => { self.f = val & 0xF0 },
            Regs::H => { self.h = val },
            Regs::L => { self.l = val },
            Regs::HL => {
                let addr = self.get_r16(Regs16::HL);
                self.write_ram(addr, val);
            }
        }
    }
}
```

Esto permite utilizar la función helper para las demás operaciones:

```

    3
}

// DEC (HL)
// Z1H-

    cpu.dec_r8(Regs::HL);
    3
}
```
